1.5 The Process of Running Python Scripts – Under the Hood

Previous Topic Next Topic

Welcome back to Codify's Masterclass Notes! Up until now, you have written code and watched the magic happen on your screen. You write print("Hello"), press a button, and the words magically appear.

But have you ever wondered what exactly happens inside your computer's brain during that split second after you command it to run? Computers are actually quite simple-minded—they do not understand English words like print, if, or while. They only understand binary code (0s and 1s).

For a computer to run your Python script, a highly organized, multi-stage translation process must occur. In this ultimate guide, we will break down the exact journey your code takes from plain English text to raw computer electricity.

1. The Bird's-Eye View: The Two-Step System

⚠️
Myth Buster: A very common myth in computer science is that "Python is strictly an interpreted language and never compiles code." This is completely wrong! Python uses a hybrid approach. When you execute a script, Python actually performs a fast, hidden compilation phase before it interprets the instructions.

The entire process boils down to two main phases:

  • The Compilation Phase: Python converts your human-readable text code into an intermediate format called Bytecode.
  • The Interpretation Phase: A special software engine called the Python Virtual Machine (PVM) translates that bytecode line-by-line into raw binary machine code that your CPU chip understands.

2. Step-by-Step Breakdown: The Code Journey

Let’s trace the exact lifecycle of a Python script from start to finish.

Step 1: Writing the Source Code (.py)

You write a script in a text editor (like IDLE, VS Code, or PyCharm) and save it. This file is your Source Code. It is saved with a .py extension.

greet.py
# Example file: greet.py name = "Codify" print("Welcome to", name)

Step 2: The Compiler Takes Over (Syntax & Lexing)

The moment you run the file, the built-in Python compiler steps in. Before it translates anything, it performs a sanity check on your code:

  • Lexical Analysis: It breaks your lines of code down into individual components called "tokens" (keywords, variables, symbols).
  • Parsing: It arranges these tokens into a logical tree structural layout called an Abstract Syntax Tree (AST) to verify your grammar.
  • The Gatekeeper (SyntaxError): If you forgot a closing quote or misspelled a keyword (e.g., writing prnt() instead of print()), the compiler will stop immediately. It will refuse to run the code and throw a SyntaxError. If the grammar is perfect, it moves to the next step.

Step 3: Generation of Bytecode (.pyc)

Once the code passes the grammar test, the compiler converts your source code into Bytecode. It is a low-level, highly optimized set of instructions. It looks like complete gibberish if a human tries to read it, but it is the perfect language for Python's internal systems.

greet.py (Source)

The __pycache__ Folder

Have you ever noticed a strange folder named __pycache__ appear out of nowhere in your project directory? That is Python saving your bytecode! It saves these files with a .pyc extension. Why does it save it? Efficiency. The next time you run your script, Python checks if you made any changes. If you haven't, it completely skips the compilation steps and loads the saved .pyc file instantly, making your programs launch much faster!

Step 4: The Python Virtual Machine (PVM) Engine

Now, the bytecode is handed over to the Python Virtual Machine (PVM). The PVM is the actual heart and soul of the Python interpreter system.

The PVM acts like a real-time translator at an international conference. It reads the platform-independent bytecode instructions one single line at a time and turns them into native machine instructions tailored exactly for the machine you are using.

Dynamic Handling: As the PVM executes the bytecode line-by-line, it dynamically checks variable data types, allocates hardware RAM memory, and monitors system resources.

Step 5: CPU Execution (The Final Output)

The CPU processor receives the clean binary stream (01001001) from the PVM and sends electrical impulses to your hardware. Suddenly, text displays on your monitor, an image renders, or a file writes to your hard drive. The process is complete!

3. The Difference Between Compilation Errors and Runtime Errors

Understanding exactly when an error occurs helps you fix bugs ten times faster. Because of Python's execution process, bugs fall into two distinct categories:

⚠️ Syntax / Compile Error
When It Is Caught During the Compiler phase (Before the code even starts running).
Why It Happens Broken code rules (missing colons, mismatched brackets).
Real-World Analogy A recipe written in an entirely fake language that you cannot read.
🚨 Runtime Error / Exception
When It Is Caught During the PVM execution phase (While the code is actively running).
Why It Happens The grammar is perfect, but the instruction makes no logical sense.
Real-World Analogy A recipe that tells you to add "3 gallons of molten lava" to your cake mix.

Code Examples:

1. Compile Error Example
if True print("Missing a colon!") # Output: SyntaxError: expected ':' # Result: The program crashes instantly before doing anything.
2. Runtime Error Example
print("Hello user!") # This line runs perfectly! result = 10 / 0 # Crashing point! # Output: ZeroDivisionError: division by zero # Result: Line 1 runs, then the PVM crashes on line 2.

4. Different Ways to Trigger a Python Script

Depending on your workflows, you can trigger this entire execution pipeline using multiple methods:

Method A: Using the Command Line / Terminal

This is the way professional developers and automated server scripts run code. Open your Terminal (Mac/Linux) or Command Prompt (Windows). Type the command python (or python3) followed by the path to your script file:

Bash / Terminal
python my_script.py

Press Enter. The OS calls the Python system tool, loads the script, and feeds it into the execution loop.

Method B: Using an IDE / Code Editor

Environments like IDLE, VS Code, or PyCharm simplify your tasks by packaging everything cleanly. When you press the F5 key in IDLE or click the green "Play" icon in VS Code, the editor opens a terminal connection behind the scenes, builds the script system call automatically, and pipes the output straight into your built-in console display window.

5. Technical Comparison: Python vs. Pure Compiled Languages (C++)

To completely lock in this concept, let's see how Python's system compares to a purely compiled language like C++:

Architectural Step Python (Interpreted / Hybrid) C++ (Purely Compiled)
Direct Output Product Produces portable Bytecode (.pyc). Produces a native binary executable (.exe or .out).
Target Audience The bytecode targets a virtual engine software (PVM). The binary directly targets a specific hardware CPU processor.
Portability High. The same bytecode runs on Windows, Mac, or Linux without alterations. Low. You must re-compile the source code separately for each platform.
Speed Profile Slower, because the PVM must translate bytecode line-by-line while running. Extremely fast, because the processor reads raw binary instantly.
