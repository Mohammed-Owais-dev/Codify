1.14 Operator Precedence – The VIP Nightclub of Python

Previous Topic Next Topic

Welcome back to Codify’s Masterclass Notes! You’ve conquered data types and you know how Booleans work. But what happens when you throw numbers, math, comparisons, and Booleans into one giant line of code?

Imagine an exclusive nightclub with only one door. If 10 people try to walk through at the exact same time, it’s chaos. The bouncer needs a VIP list to decide who gets in first, who waits, and who checks their coat at the end of the night.

In Python, this VIP list is called Operator Precedence. It’s essentially PEMDAS (Order of Operations) on steroids. Without it, your computer would have a panic attack every time it looked at a complex logic puzzle. After diving into Python's official documentation and some weird internet edge-cases, we've put together the ultimate guide to mastering how Python reads your code.

1. Why Do We Even Need This? (The Math Connection)

You might wonder why Python doesn't just read code from left to right like a normal book. The answer lies in mathematical purity.

Python’s creator, Guido van Rossum, wanted the language to behave the way you learned math in middle school. If you write 5 + 3 * 2, reading left-to-right gives you 16. But mathematically, multiplication must happen first, giving 11. Python respects the universal laws of math, which is why it uses a strict hierarchy instead of reading left-to-right.

2. The Operator VIP List (Highest to Lowest)

Here is your master hierarchy. The higher up on the list, the faster Python executes it. The operators at the bottom have to wait patiently for everyone else to finish.

Precedence Operator Type Python Symbols The Vibe / Funny Note
1 (Highest) Parentheses () The Ultimate VIPs. They do whatever they want. Wrap anything in these, and they skip the entire line.
2 Exponentiation ** The Rocket Ships. Powering up numbers happens before any basic math.
3 Unary (Pos/Neg) +x, -x, ~x The Makeover Crew. They flip a number negative or positive before anyone else gets to touch it.
4 Multiplication / Division *, /, //, % The Math Nerds (Tier 1). They always calculate before the basic addition/subtraction crew.
5 Addition / Subtraction +, - The Basic Math Nerds. They sit around drinking water, waiting for the multiplication crew to finish.
6 Bitwise Operators &, |, ^, <<, >> The Hardware Hackers. Deep binary shifts happen here.
7 Relational (Comparisons) <, >, <=, >=, in, is The Judges. They wait for all the math to finish, then ruthlessly judge who is bigger, smaller, or identical.
8 Logical NOT not The Contrarian. Flips your logic (True to False). It waits for the judges to finish before giving its opinion.
9 Logical AND and The "Package Deal" Couple. Both sides must be true. They evaluate before the OR operators!
10 Logical OR or The "Whatever Works" Friend. As long as one side is true, they're happy. They wait for and to finish its drama.
11 (Lowest) Assignment =, +=, -= The Coat Check. Literally the last thing to happen. Takes all the hard work everyone else just did and stuffs it into a variable.

3. The Tie-Breaker: Associativity (Internet Research Edge Cases)

What happens when two operators have the exact same VIP status? For example, what happens if you have multiple division symbols in a row?

When there is a tie, Python uses Associativity, which is a fancy word for "which direction do I read this?"

Rule 1: Left-to-Right (The Standard)

Almost every operator in Python is evaluated from left to right.

math_problem = 100 / 10 * 2

Python reads 100 / 10 first (10.0), and then multiplies by 2. The answer is 20.0.

Rule 2: Right-to-Left (The Weird Exceptions)

This is a famous interview trick! Exponentiation (**) is evaluated right-to-left. Let's look at a wild edge case:

weird_math = 2 ** 3 ** 2
  • What you might think: 2 ** 3 is 8. And 8 ** 2 is 64. ❌ (Wrong!)
  • What Python actually does: It starts on the right! It calculates 3 ** 2 first (which is 9). Then it does 2 ** 9 (which is 512). ✅

Assignment (=) is also right-to-left. That's why you can do cool things like this:

a = b = c = 5 # Python assigns 5 to 'c', then 'c' to 'b', then 'b' to 'a'.

4. Better, Understandable Examples

Let's look at how the Python brain breaks down complex lines of code step-by-step.

Example 1: The Logic Showdown (AND vs. OR)

Interactive Feature: The VIP Logic Bouncer

Click "Next" to see who gets VIP priority in this logic statement.

True or
False and False
Human Brain thinks: (True or False) = True -> True and False = False. Let's see what Python does!
is_happy = True or False and False
  • Human Brain: Reading left-to-right... "True OR False is True. True AND False is False. The result is False."
  • Python Brain: Logical and has a higher VIP status than Logical or.
  • Step 1: Python evaluates the and first. False and False becomes False.
  • Step 2: Now Python looks at the or. True or False becomes True.
  • Result: is_happy is True.

Example 2: The "Everything Everywhere All At Once" Code

Let's combine math, comparisons, and logic.

score = 10 win = score * 2 > 15 and not False

Here is exactly how Python sorts this out:

  • Math (*): Sees score * 2 (10 * 2) and turns it into 20.
    Current state: win = 20 > 15 and not False
  • Relational (>): Checks if 20 is greater than 15. It is, so that becomes True.
    Current state: win = True and not False
  • Logical NOT (not): Sees not False and flips it to True.
    Current state: win = True and True
  • Logical AND (and): Checks if both sides are True. They are!
    Current state: win = True
  • Assignment (=): Finally, the Coat Check assigns the final True to the win variable.

5. A Python Superpower: Chained Comparisons

In many older programming languages (like C++ or Java), if you want to check if a number is between two other numbers, you have to write ugly code like this:

if (age > 12) and (age < 20):

But Python's operator precedence allows for Chained Comparisons, which reads exactly like human math:

age = 15 print(12 < age < 20) # Output: True
Terminal Output: True

Behind the scenes, Python secretly breaks this down into (12 < age) and (age < 20). It evaluates left to right and perfectly handles the logic.

💡
Pro-Tip from Senior Developers: Even if you perfectly memorize the VIP list and associativity rules, use parentheses anyway. Writing win = ((score * 2) > 15) and (not False) does the exact same thing as our earlier example, but it saves the next human reading your code from needing an aspirin! Practicality beats purity.
