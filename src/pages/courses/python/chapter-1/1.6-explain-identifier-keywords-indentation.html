1.6 Identifiers, Keywords, and Indentation in Python

Previous Topic Next Topic

Welcome back to Codify's Masterclass Notes! Up to now, you have learned how Python runs under the hood and how to use IDLE. Now, we are starting to learn the grammatical foundations of the Python language.

Just like English has nouns, strict vocabulary words, and structural paragraph rules, Python relies on three fundamental building blocks to structure code:

  1. Identifiers: How you name things in your program.
  2. Keywords: The reserved vocabulary words that Python keeps for itself.
  3. Indentation: The spatial layout rules that organize your code blocks.

Let's break down each concept with clear rules, visual diagrams, real-world analogies, and interactive quizzes!

1. Identifiers: The Naming System of Python

An Identifier is simply a user-defined name given to a programming element—such as a variable, function, class, module, or object.

👶
The Analogy: When a baby is born, parents give it a unique name so they can refer to it later ("Alex", "Sophia"). In Python, whenever you create a box to store data (a variable) or write a block of reusable code (a function), you must give it a name so you can call it later.
# Here, 'user_age' and 'greet_user' are IDENTIFIERS user_age = 18 def greet_user(): print("Welcome to Codify!")

The Strict Rules for Naming Identifiers

Python is very relaxed about many things, but it is extremely strict about naming rules. If you break even one rule, Python will throw a SyntaxError and refuse to run your code!

  • Rule 1: Allowed Characters Only: An identifier can ONLY contain Uppercase letters (A-Z), Lowercase letters (a-z), Digits (0-9), and Underscores (_). Prohibited: No special symbols like @, $, %, !, -, or spaces are allowed anywhere in the name!
  • Rule 2: Cannot Start with a Digit: An identifier can start with a letter or an underscore (_), but NEVER with a number. (student1 👉 VALID | 1student 👉 INVALID).
  • Rule 3: Case-Sensitivity Matters: Python treats uppercase and lowercase letters as entirely separate entities. age, Age, and AGE are 3 completely different variables!
  • Rule 4: Cannot Use Reserved Keywords: You cannot name a variable after a built-in Python keyword (e.g., you cannot name your variable if, for, or class).
  • Rule 5: Unlimited Length: An identifier can be as long as you want, but keeping names concise and descriptive makes your code easier to maintain.

Python Naming Conventions (PEP 8 Best Practices)

While the rules above dictate what is legal, Python's official style guide (PEP 8) specifies what is considered clean code:

  • Variables & Functions: Use snake_case (all lowercase with words separated by underscores, e.g., total_price, calculate_score()).
  • Classes: Use PascalCase (capitalize the first letter of every word, e.g., UserProfile, BankSystem).
  • Constants (Values that never change): Use ALL_CAPS (e.g., PI = 3.14159, MAX_USERS = 100).

2. Keywords: The Reserved Words of Python

Keywords are special, pre-defined words that have specific, fixed meanings to the Python compiler and Virtual Machine (PVM). They serve as the structural command grammar of the language.

🛑
The Analogy: Think of keywords as emergency road signs ("STOP", "YIELD", "ONE WAY"). You cannot paint over a STOP sign to use it as a billboard; its meaning is permanently locked into the traffic system.
# Run this code in Python IDLE to view the exact keyword list on your computer: import keyword print(keyword.kwlist)
['False', 'None', 'True', 'and', 'as', 'assert', 'async', 'await', 'break', 'class', 'continue', 'def', 'del', 'elif', 'else', 'except', 'finally', 'for', 'from', 'global', 'if', 'import', 'in', 'is', 'lambda', 'nonlocal', 'not', 'or', 'pass', 'raise', 'return', 'try', 'while', 'with', 'yield']

⚠️
Crucial Observation: Except for True, False, and None, ALL Python keywords are written entirely in lowercase letters! Writing If, FOR, or Def will trigger an immediate error.

Soft Keywords (Modern Python Feature)

In Python 3.9 and later, core developers introduced Soft Keywords: match, case, _, and type.

What makes them "soft"? They act as keywords only within structural pattern-matching statements, but they can still be used as variable names elsewhere without crashing old codebases.

3. Indentation: Python’s Visual Block Architecture

In computer programming, a block of code is a group of statements that execute together (like the steps inside a loop or an if statement).

  • In languages like C++, Java, or JavaScript, blocks are grouped using curly braces {}.
  • Python rejects curly braces entirely. Instead, Python uses Indentation (whitespace spaces at the beginning of a line) to define code blocks!

C++ vs. Python Block Architecture

C++ (Uses curly braces, ignores spacing):

// Ugly, unreadable, but perfectly valid in C++ if (score > 50) { cout << "You passed!"; cout << "Congratulations!"; }

Python (Uses indentation spaces):

# Clean, forced layout in Python if score > 50: print("You passed!") # Indented block print("Congratulations!") # Indented block
💡
The Rule of Thumb: In Python, a colon (:) at the end of a line indicates that an indented block of code follows!

How Many Spaces Should You Use?

According to the official PEP 8 Style Guide:

  • The standard Python indentation is exactly 4 spaces per block level.
  • Never mix Tabs and Spaces! Mixing them in the same script leads to a nightmare bug called an IndentationError or TabError. Modern editors like IDLE automatically convert the Tab key into 4 spaces for you.

Understanding Block Hierarchy (The "Accordion" Effect)

Indentation creates visual levels. Code aligned at the same horizontal position belongs to the same logical block:

# Level 0 (Main Outer Level)
user_status = "active"
age = 20
if user_status == "active":
# Level 1 (Inside the 'if' block)
print("Welcome, User!")
if age >= 18:
# Level 2 (Nested inside the age check)
print("Access Granted: Adult Account")
else:
# Level 2
print("Access Restricted: Minor Account")
# Level 0 (Outside the block, back to main timeline)
print("System execution finished.")

The Dreaded IndentationError

If you forget to indent code after a colon, Python throws an error and stops running immediately:

❌ WRONG CODE
if 5 > 2: print("Five is greater!") # Output: IndentationError: expected an indented block after 'if' statement on line 1
✅ CORRECT CODE
if 5 > 2: print("Five is greater!") # Properly indented with 4 spaces
