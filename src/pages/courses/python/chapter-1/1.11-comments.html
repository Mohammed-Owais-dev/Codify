1.11 Comments (The Secret Whispers of Code)

Previous Topic Next Topic

Welcome back to Codify’s Masterclass Notes! Imagine you are building a massive LEGO castle without a manual. Two weeks later, your friend comes over, points to a weird red block in the middle of the wall, and asks, "Why is that there?" You stare at it and realize... you have absolutely no idea.

Writing Python code without Comments is exactly like that.

Comments are notes, warnings, and explanations that you leave inside your code. The best part? The computer completely ignores them. In this fun and easy guide, we will learn how to write comments, why they save your life, and how to avoid writing terrible ones!

1. What Exactly is a Comment?

A Comment is a piece of text placed inside your Python script that the Python Virtual Machine (PVM) purposefully skips over.

🎬
The Analogy: Think of comments like the director's commentary on a movie, or the secret notes you pass in class. The teacher (the Python Compiler) doesn't grade them, and the audience (the computer) doesn't see them. They are purely for human eyes only.

2. Why Do We Need Comments? (The Funny Truth)

Beginners often think, "I wrote the code, so obviously I know what it does!" Trust us, you won't. Here is why every professional uses comments:

  • Amnesia Prevention: You will forget how your own code works after a long weekend. Comments are a time machine to remind your future self what you were thinking.
  • Teamwork & Apologies: When you work in a company, other people have to read your code. Comments help explain your logic (or apologize for it).
  • Debugging (The "Turn it Off" Trick): If a piece of code is causing an error, you can temporarily turn it into a comment so the computer ignores it while you test the rest of the program!

3. How to Write a Comment: The # Symbol

In Python, the official way to write a comment is to use the Hash symbol (#) (also known as the pound sign or number sign).

The moment Python sees a #, it completely ignores everything that comes after it on that specific line.

A. Block Comments (Full Line)

These are placed on their own line, usually directly above the code they are explaining.

# Calculate the user's age based on the current year birth_year = 2005 age = 2026 - birth_year

B. Inline Comments (Side-by-Side)

These are placed on the exact same line as the code, pushed out to the right side.

gravity = 9.8 # Earth's gravity in m/s^2

😂 Codify Real-World Funny Examples:

Here are some actual comments developers have left in professional software:

  • # I have no idea why this works, but if you delete it, the whole app crashes.
  • # Dear future me: Please forgive me for the messy code below.
  • # Sometimes I believe compiler ignores all my comments.
  • # TODO: Fix this bug before the boss finds out.

4. The Multi-Line Comment "Hack"

What if you need to write a massive paragraph of text? Typing a # at the start of 10 different lines gets annoying.

In languages like C++ or Java, they have a special symbol for multi-line comments (/* ... */). Python does NOT have a true multi-line comment! But Python developers are clever. They use two workarounds:

Workaround 1: The # Wall

Just use a bunch of hash marks. Modern code editors (like VS Code or IDLE) let you highlight multiple lines and press Alt + 3 or Ctrl + / to do this automatically!

# ---------------------------------------------------- # PROGRAM LOGIC: # 1. Ask the user for their name. # 2. Check if the name is in the VIP database. # 3. If they are not VIP, launch them into the sun. # ----------------------------------------------------

Workaround 2: The Triple-Quote Hack (""")

If you put text inside three double-quotes """ or three single-quotes ''', Python treats it as a multi-line string. If you don't assign that string to a variable, Python just looks at it, shrugs, and deletes it from memory! It functions exactly like a multi-line comment.

""" This is a multi-line comment hack! I can write as many lines as I want here. Python will technically read it, but since it's not saved to a variable, it just throws it in the trash bin immediately. """ print("The program starts here!")
Interactive Feature: The Compiler X-Ray

Click the button to see exactly what the computer's processor sees. Notice how the computer completely ignores the human text!

# We need to initialize the player's health before the game loop starts player_health = 100 """ Check if the player has touched the lava pit. If they have, reduce health by 50 points immediately. """ if touching_lava: player_health = player_health - 50 # Lava damage

5. Docstrings (The Professional's Comment)

While the triple-quote """ trick is often used as a comment, its actual, official purpose in Python is to create a Docstring (Documentation String).

If you put a triple-quote string immediately below a function or a class, it becomes the official manual for that code. Other programmers can use the help() command to read it!

def make_coffee(): """ This function brews a hot cup of coffee. Warning: Do not give to children under 5. """ print("Brewing coffee...") # If someone doesn't know what the function does, they can type: help(make_coffee)
Terminal OutputThis function brews a hot cup of coffee. Warning: Do not give to children under 5.

6. Good Comments vs. Bad Comments

Just because you can comment on everything doesn't mean you should. A golden rule in programming is: Code tells you HOW, comments tell you WHY.

Let's look at the difference between a rookie and a pro:

❌ The Rookie
x = 5 # Sets x to 5
✅ The Pro
timeout_limit = 5 # Wait 5 seconds before disconnecting
Why is the rookie bad? The code x = 5 is already obvious. We don't need a comment explaining basic English.
❌ The Rookie
# loop through list for i in users:
✅ The Pro
# Checking for users with expired passwords for user in users:
Why is the rookie bad? "Loop through list" is obvious. The good comment explains the purpose of the loop.
❌ The Rookie
# this is a cat variable dog = 10
✅ The Pro
# Default player speed speed = 10
Why is the rookie bad? The comment contradicts the code! (Yes, this happens a lot when people copy/paste).

7. Codify Master Summary Table

Comment Type Symbol Used Purpose
Single-Line (Block) # Placed above the code to explain the general logic of the next few lines.
Inline Comment # (at the end of a line) Explains a specific variable or a tricky piece of math on the same line.
Multi-Line Hack """ ... """ Used to write long paragraphs without typing # twenty times.
Docstrings """ ... """ (under functions) Creates an official help manual for a function or class.
