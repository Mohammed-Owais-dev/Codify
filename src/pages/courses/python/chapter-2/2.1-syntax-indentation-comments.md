# Chapter 2: Python Basics

## Section 2: Python Syntax, Indentation & Comments

Python syntax is the set of rules that describes how Python code must be written. Just as a sentence needs a clear structure to communicate an idea, a Python program needs valid syntax so the interpreter can understand it.

Python is designed to be readable. It often uses words and punctuation in a way that looks close to ordinary instructions. However, small details still matter: quotation marks must match, brackets must close, and code blocks must be indented correctly.

In this lesson, you will learn how Python statements are written, why indentation is important, how colons introduce blocks, and how comments help explain code.

---

## 1. Statements and Line Structure

A **statement** is an instruction that Python can execute. Most beginner programs place one statement on each line.

\`\`\`python
student = "Asha"
marks = 87
print(student)
print(marks)
\`\`\`

\`\`\`output
Asha
87
\`\`\`

Python normally executes these statements from top to bottom. First, it assigns the text \`"Asha"\` to \`student\`. Next, it assigns \`87\` to \`marks\`. The final two statements display the values.

Writing one statement per line makes code easier to read, debug, and update. Python allows some statements to be combined on one line with a semicolon, but this is usually unnecessary for beginner code.

## 2. Case Sensitivity

Python is **case-sensitive**. Uppercase and lowercase letters are treated as different characters in names.

\`\`\`python
name = "Asha"
Name = "Ravi"

print(name)
print(Name)
\`\`\`

\`\`\`output
Asha
Ravi
\`\`\`

Here, \`name\` and \`Name\` are two different variable names. This means that changing the capitalization accidentally can cause a \`NameError\` if the name you use has not been defined.

Use consistent capitalization. Variable names commonly use lowercase letters with underscores, such as \`student_name\`.

## 3. Indentation: Spaces at the Beginning of a Line

**Indentation** means the spaces placed before a statement. In Python, indentation is not just for appearance: it identifies which statements belong to a block of code.

Consider this example:

\`\`\`python
marks = 82

if marks >= 40:
    print("Pass")
    print("Result recorded")

print("Program finished")
\`\`\`

\`\`\`output
Pass
Result recorded
Program finished
\`\`\`

The two indented statements belong to the \`if\` block. The final statement is not indented, so it runs after the block finishes, regardless of whether the condition is true.

Python's common style is to use **four spaces** for each indentation level. Avoid mixing tabs and spaces in the same block.

### What happens when indentation is incorrect?

\`\`\`python
if marks >= 40:
print("Pass")
\`\`\`

This produces an \`IndentationError\` because Python expects the block after the colon to be indented.

A different indentation can also change the program's meaning:

\`\`\`python
if marks >= 40:
    print("Pass")
print("Checked")
\`\`\`

In this version, \`print("Checked")\` is outside the \`if\` block. It runs whether the marks are 82 or 20.

## 4. Colons and Code Blocks

A colon (\`:\`) commonly appears at the end of a line that begins a block, such as an \`if\`, \`elif\`, \`else\`, \`for\`, \`while\`, or function definition.

\`\`\`python
temperature = 31

if temperature > 30:
    print("It is a hot day")
else:
    print("The temperature is moderate")
\`\`\`

\`\`\`output
It is a hot day
\`\`\`

The colon indicates that a block follows. Indentation then identifies the statements inside each block. You will study conditions and loops in more detail in Chapter 3.

## 5. Comments: Notes for People Reading Code

A **comment** is text in the source code that Python ignores during normal execution. Comments explain why code exists, clarify a decision, or leave a useful note for another developer.

A single-line comment begins with \`#\`.

\`\`\`python
# Calculate the final amount after adding delivery
price = 250
delivery = 40
total = price + delivery

print(total)
\`\`\`

\`\`\`output
290
\`\`\`

Everything after \`#\` on that line is treated as a comment, except when the character appears inside a string.

\`\`\`python
print("Use # to begin a comment")
\`\`\`

\`\`\`output
Use # to begin a comment
\`\`\`

The \`#\` inside the quotation marks is part of the displayed text, not a comment marker.

### Inline comments

A short comment can appear after a statement:

\`\`\`python
attempts = 3  # Maximum number of allowed attempts
\`\`\`

Inline comments are useful when they explain something that is not obvious. Avoid adding comments that simply repeat the code without giving extra information.

## 6. Docstrings Are Different from Comments

A **docstring** is a string written at the beginning of a module, function, or class to describe its purpose. It is commonly written using triple quotation marks.

\`\`\`python
def calculate_total(price, quantity):
    """Return the total price for the requested quantity."""
    return price * quantity

print(calculate_total(50, 3))
\`\`\`

\`\`\`output
150
\`\`\`

The text inside the function is a docstring because it is placed first in the function body. Unlike an ordinary comment, a docstring can be accessed through documentation features such as \`calculate_total.__doc__\`.

Do not use triple-quoted strings as a general replacement for comments. Use \`#\` for ordinary code notes and docstrings to document modules, classes, and functions.

## 7. Real-World Example: A Simple Eligibility Check

Imagine a college program that checks whether a student has reached the minimum attendance percentage. Indentation clearly separates the message shown for each result.

\`\`\`python
attendance = 78
minimum_required = 75

if attendance >= minimum_required:
    print("Eligible for the examination")
    print("Attendance requirement satisfied")
else:
    print("Not eligible yet")
    print("Contact the college office")
\`\`\`

\`\`\`output
Eligible for the examination
Attendance requirement satisfied
\`\`\`

The comparison decides which block runs. Both statements in the selected block must have the same indentation level. Changing the attendance to \`60\` makes the \`else\` block run instead.

## 8. Common Syntax Errors

| Error | What it usually means | How to check it |
| --- | --- | --- |
| \`SyntaxError\` | Python cannot parse the statement | Check quotes, brackets, colons, and spelling |
| \`IndentationError\` | A block is not indented consistently or correctly | Check spaces before statements |
| \`NameError\` | A name has not been defined under that spelling | Check spelling and capitalization |
| Unexpected output | The code is valid but its structure or logic differs from your intention | Review indentation and execution order |

Python's error message usually identifies a line near the problem. The actual cause may be on that line or immediately before it. Read the message carefully instead of changing code randomly.

---

## ⚠️ Common Mistakes

* **Forgetting the colon:** block statements such as \`if\` need a colon at the end of the condition line.
* **Using inconsistent indentation:** statements in the same block should line up.
* **Confusing \`name\` with \`Name\`:** Python treats these as different names.
* **Expecting comments to run:** comments are notes for readers, not executable instructions.
* **Writing comments for every line:** comments should explain intent or important details, not make code unnecessarily noisy.
* **Using indentation only for visual alignment:** indentation changes which block owns a statement.

---

## 🔑 Key Points

* Python syntax defines the rules for writing valid Python statements.
* Python is case-sensitive.
* Indentation determines which statements belong to a block.
* Four spaces per indentation level is the common style.
* A colon introduces a block in statements such as \`if\`, loops, and function definitions.
* A single-line comment begins with \`#\`.
* Docstrings document modules, functions, and classes.
* Read error messages and check the line near the reported location.
