# Chapter 7: Object-Oriented Programming

## Section 3: Encapsulation & Access Control

**Encapsulation** means bundling data and methods together in a class and **controlling access** to that data. It protects important values from being changed by mistake.

---

## 1. What is Encapsulation?

Think of an ATM. You can deposit or withdraw money using buttons, but you cannot reach inside and change the balance directly. The machine controls access.

In programming, encapsulation:

* Hides the internal details of an object.
* Allows changes only through safe methods.
* Prevents invalid data, such as a negative balance.

---

## 2. The Problem Without Encapsulation

If every attribute is open, anyone can set a wrong value.

```python
class Account:
    def __init__(self, balance):
        self.balance = balance

acc = Account(1000)
acc.balance = -99999

print(acc.balance)
```

```output
-99999
```

Nothing stops this invalid change. We need access control.

---

## 3. Access Modifiers in Python

Python uses **naming conventions** instead of strict keywords.

| Level | Syntax | Meaning |
|-------|--------|---------|
| **Public** | `name` | Accessible from anywhere |
| **Protected** | `_name` | Should be used only inside the class and its subclasses (a convention) |
| **Private** | `__name` | Hidden from outside the class (name mangling) |

---

## 4. Public Members

By default, every attribute and method is public.

```python
class Person:
    def __init__(self, name):
        self.name = name

p = Person("Asha")
print(p.name)
```

```output
Asha
```

---

## 5. Protected Members

A single underscore tells other programmers: "internal use only." Python does not block access, but you should respect it.

```python
class Person:
    def __init__(self, name):
        self._age = 20

p = Person("Asha")
print(p._age)
```

```output
20
```

---

## 6. Private Members

Two leading underscores make a member private. Python renames it internally (**name mangling**), so it cannot be reached by the usual name from outside.

```python
class Account:
    def __init__(self, balance):
        self.__balance = balance

    def show(self):
        print("Balance:", self.__balance)

acc = Account(1000)
acc.show()

try:
    print(acc.__balance)
except AttributeError:
    print("Cannot access private attribute")
```

```output
Balance: 1000
Cannot access private attribute
```

Inside the class, `self.__balance` works normally.

---

## 7. How Name Mangling Works

Python changes `__balance` into `_ClassName__balance`.

```python
class Account:
    def __init__(self):
        self.__balance = 500

acc = Account()
print(acc._Account__balance)
```

```output
500
```

So private in Python means **hard to reach by accident**, not impossible. It is a protection against mistakes, not a security lock.

---

## 8. Getter and Setter Methods

Provide public methods to read (**getter**) and safely change (**setter**) private data.

```python
class Account:
    def __init__(self, balance):
        self.__balance = balance

    def get_balance(self):
        return self.__balance

    def set_balance(self, amount):
        if amount >= 0:
            self.__balance = amount
        else:
            print("Balance cannot be negative")

acc = Account(1000)

acc.set_balance(-500)
acc.set_balance(2500)

print(acc.get_balance())
```

```output
Balance cannot be negative
2500
```

The setter **validates** the value before saving it.

---

## 9. Private Methods

Methods can be private too. They are helpers meant only for use inside the class.

```python
class Bank:
    def __check_pin(self, pin):
        return pin == 1234

    def withdraw(self, pin, amount):
        if self.__check_pin(pin):
            return "Withdrawn " + str(amount)
        return "Wrong PIN"

b = Bank()
print(b.withdraw(1234, 500))
print(b.withdraw(1111, 500))
```

```output
Withdrawn 500
Wrong PIN
```

## 10. The `@property` Decorator

`@property` is the Pythonic way to write getters and setters. You can then use the attribute like a normal variable.

```python
class Student:
    def __init__(self, marks):
        self.__marks = marks

    @property
    def marks(self):
        return self.__marks

    @marks.setter
    def marks(self, value):
        if 0 <= value <= 100:
            self.__marks = value
        else:
            print("Marks must be between 0 and 100")

s = Student(70)
print(s.marks)

s.marks = 90
print(s.marks)

s.marks = 150
print(s.marks)
```

```output
70
90
Marks must be between 0 and 100
90
```

Notice that `s.marks` has no brackets, but the getter and setter still run.

---

## 11. Read-Only Properties

If you define only the getter, the attribute becomes **read-only**.

```python
class Circle:
    def __init__(self, radius):
        self.__radius = radius

    @property
    def area(self):
        return 3.14 * self.__radius * self.__radius

c = Circle(5)
print(c.area)

try:
    c.area = 100
except AttributeError:
    print("Area is read-only")
```

```output
78.5
Area is read-only
```

## 12. Benefits of Encapsulation

| Benefit | Explanation |
|---------|-------------|
| **Data protection** | Prevents accidental or invalid changes |
| **Validation** | Setters check values before saving |
| **Flexibility** | Internal code can change without breaking users of the class |
| **Cleaner interface** | Users see only what they need |

## Real-World Example

A **SecureAccount** with a private balance, a PIN check and safe operations:

```python
class SecureAccount:
    def __init__(self, owner, balance, pin):
        self.owner = owner
        self.__balance = balance
        self.__pin = pin

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount

    def withdraw(self, amount, pin):
        if pin != self.__pin:
            return "Wrong PIN"
        if amount > self.__balance:
            return "Insufficient funds"
        self.__balance -= amount
        return "Withdrawn " + str(amount)

    @property
    def balance(self):
        return self.__balance

acc = SecureAccount("Asha", 1000, 4321)

acc.deposit(500)
print(acc.withdraw(200, 1111))
print(acc.withdraw(200, 4321))
print(acc.withdraw(9000, 4321))
print("Balance:", acc.balance)
```

```output
Wrong PIN
Withdrawn 200
Insufficient funds
Balance: 1300
```

## Common Mistakes

### Thinking Private is Fully Secure

`_Account__balance` can still be reached. Private is a guard against mistakes, not a security feature.

### Adding Trailing Underscores to a Private Name

Names that end with two underscores, like `__name__`, are **special** Python names and are not made private. For a private member, use only the leading `__name`.

### Forgetting `self.` Inside the Class

```python
def show(self):
    print(__balance)     # NameError
```

Write `self.__balance`.

### Setter Without the Matching Property

`@marks.setter` works only after a `@property` named `marks` is defined first.

### Same Name for Attribute and Property

```python
self.marks = marks       # conflicts with the property named marks
```

Store the data in `self.__marks` and expose it through the `marks` property.

---

## Key Points

* Encapsulation bundles data and methods and controls access to data.
* Python uses naming conventions: `name` (public), `_name` (protected), `__name` (private).
* Private members use name mangling: `__x` becomes `_Class__x`.
* Getters and setters give controlled access and allow validation.
* `@property` lets you use methods like attributes.
* A property with no setter is read-only.
* Private methods are internal helpers.
* Encapsulation improves safety, validation and maintainability.
