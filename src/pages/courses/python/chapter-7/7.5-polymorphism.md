# Chapter 7: Object-Oriented Programming

## Section 5: Polymorphism & Abstraction

**Polymorphism** means "many forms": the same operation can behave differently for different objects. **Abstraction** means hiding complex details and showing only what is necessary. Together with encapsulation and inheritance, they are the four pillars of OOP.

---

## 1. The Four Pillars of OOP

| Pillar | Meaning |
|--------|---------|
| **Encapsulation** | Bundle data and methods; control access |
| **Inheritance** | Reuse code from a parent class |
| **Polymorphism** | Same name, different behavior |
| **Abstraction** | Hide details, show essentials |

---

## 2. What is Polymorphism?

A single interface can be used with different types. Python already does this in many places. The `+` operator adds numbers, joins strings and merges lists:

```python
print(5 + 3)
print("Py" + "thon")
print([1, 2] + [3])
```

```output
8
Python
[1, 2, 3]
```

The built-in `len()` also works on many types:

```python
print(len("Hello"))
print(len([10, 20, 30]))
print(len({"a": 1, "b": 2}))
```

```output
5
3
2
```

---

## 3. Polymorphism with Method Overriding

Child classes provide their own version of a parent's method. The same call gives a different result for each object.

```python
class Shape:
    def area(self):
        return 0

class Rectangle(Shape):
    def __init__(self, length, width):
        self.length = length
        self.width = width

    def area(self):
        return self.length * self.width

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14 * self.radius * self.radius

shapes = [Rectangle(4, 6), Circle(5)]

for shape in shapes:
    print(shape.area())
```

```output
24
78.5
```

The loop does not care about the exact type. It just calls `area()`.

## 4. Duck Typing

Python follows the idea: *"If it walks like a duck and quacks like a duck, it is a duck."* An object is accepted if it has the required method, whatever its class is. No common parent is needed.

```python
class Dog:
    def speak(self):
        return "Woof"

class Cat:
    def speak(self):
        return "Meow"

class Robot:
    def speak(self):
        return "Beep"

for thing in [Dog(), Cat(), Robot()]:
    print(thing.speak())
```

```output
Woof
Meow
Beep
```

---

## 5. Polymorphic Functions

A function can work with any object that supports the method it uses.

```python
class Email:
    def send(self):
        print("Sending an email")

class SMS:
    def send(self):
        print("Sending an SMS")

def notify(channel):
    channel.send()

notify(Email())
notify(SMS())
```

```output
Sending an email
Sending an SMS
```

## 6. Operator Overloading

Special **magic methods** (also called dunder methods) let your objects work with operators.

| Operator | Method |
|----------|--------|
| `+` | `__add__` |
| `-` | `__sub__` |
| `*` | `__mul__` |
| `==` | `__eq__` |
| `<` | `__lt__` |
| `len()` | `__len__` |
| `print()` | `__str__` |

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        return Point(self.x + other.x, self.y + other.y)

    def __str__(self):
        return "(" + str(self.x) + ", " + str(self.y) + ")"

p1 = Point(2, 3)
p2 = Point(4, 5)

print(p1 + p2)
```

```output
(6, 8)
```

Python converts `p1 + p2` into `p1.__add__(p2)`.

## 7. Comparing and Measuring Objects

```python
class Book:
    def __init__(self, title, pages):
        self.title = title
        self.pages = pages

    def __eq__(self, other):
        return self.pages == other.pages

    def __len__(self):
        return self.pages

b1 = Book("Python", 300)
b2 = Book("Java", 300)

print(b1 == b2)
print(len(b1))
```

```output
True
300
```

## 8. What is Abstraction?

Abstraction shows **what** an object does and hides **how** it does it. When you press the accelerator in a car, you do not need to know how the engine works.

In Python, abstraction is achieved using **abstract classes** from the `abc` module.

---

## 9. Abstract Classes and Methods

* An **abstract method** has a name but no real body. Child classes **must** implement it.
* An **abstract class** contains at least one abstract method and cannot be used to create objects.

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

class Square(Shape):
    def __init__(self, side):
        self.side = side

    def area(self):
        return self.side * self.side

s = Square(5)
print(s.area())
```

```output
25
```

Here `Shape` forces every shape to provide an `area()` method.

---

## 10. Abstract Classes Cannot Be Instantiated

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

try:
    s = Shape()
except TypeError:
    print("Cannot create an object of an abstract class")
```

```output
Cannot create an object of an abstract class
```

A child class that does **not** implement all abstract methods is also abstract:

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

class Broken(Shape):
    pass

try:
    Broken()
except TypeError:
    print("Broken must implement area()")
```

```output
Broken must implement area()
```

---

## 11. Abstract Classes with Normal Methods

An abstract class may also contain regular methods and a constructor that children can reuse.

```python
from abc import ABC, abstractmethod

class Employee(ABC):
    def __init__(self, name):
        self.name = name

    @abstractmethod
    def salary(self):
        pass

    def show(self):
        print(self.name, "earns", self.salary())

class FullTime(Employee):
    def salary(self):
        return 50000

class Intern(Employee):
    def salary(self):
        return 10000

FullTime("Asha").show()
Intern("Ravi").show()
```

```output
Asha earns 50000
Ravi earns 10000
```

---

## 12. Abstraction vs Encapsulation

| Feature | Abstraction | Encapsulation |
|---------|-------------|---------------|
| Goal | Hide complexity, show essentials | Protect data, control access |
| Level | Design level (what to expose) | Implementation level (how to protect) |
| Tool in Python | `ABC` and `@abstractmethod` | `_name`, `__name`, `@property` |

## Real-World Example

A **payment system** where each method pays differently, but checkout code stays the same:

```python
from abc import ABC, abstractmethod

class Payment(ABC):
    @abstractmethod
    def pay(self, amount):
        pass

class CreditCard(Payment):
    def pay(self, amount):
        print("Paid", amount, "using Credit Card")

class UPI(Payment):
    def pay(self, amount):
        print("Paid", amount, "using UPI")

class Cash(Payment):
    def pay(self, amount):
        print("Paid", amount, "in Cash")

def checkout(method, amount):
    method.pay(amount)

checkout(CreditCard(), 2500)
checkout(UPI(), 800)
checkout(Cash(), 150)
```

```output
Paid 2500 using Credit Card
Paid 800 using UPI
Paid 150 in Cash
```

Adding a new payment type needs no change to `checkout()`.

## Common Mistakes

### Forgetting to Implement an Abstract Method

A child class without every abstract method cannot be instantiated and raises `TypeError`.

### Creating an Object of an Abstract Class

```python
s = Shape()      # TypeError
```

Create objects only from concrete child classes.

### Forgetting `ABC` in the Parent

```python
class Shape:
    @abstractmethod
    def area(self): pass
```

Without inheriting from `ABC`, the abstract rule is **not** enforced. Write `class Shape(ABC):`.

### Misspelling the Magic Method

`__add` or `_add_` will not work. Use exactly `__add__`.

### Returning the Wrong Type from an Operator Method

`__add__` should return a new object or value. If it prints instead, `p1 + p2` gives `None`.

---

## Key Points

* Polymorphism means one interface, many behaviors.
* Method overriding is a common way to achieve polymorphism.
* Duck typing accepts any object that has the needed method.
* Magic methods such as `__add__`, `__eq__`, `__len__` and `__str__` let objects use operators and built-in functions.
* Abstraction hides complexity and shows only essential features.
* Use `ABC` and `@abstractmethod` from the `abc` module to create abstract classes.
* Abstract classes cannot be instantiated; child classes must implement all abstract methods.
* The four pillars of OOP are encapsulation, inheritance, polymorphism and abstraction.
