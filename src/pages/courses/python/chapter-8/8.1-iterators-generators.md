# Chapter 8: Advanced Python

## Section 1: Iterators & Generators

Every time you write a `for` loop, Python uses an **iterator** behind the scenes. In this section we look at how that works, and how **generators** let you produce values one at a time, saving memory and time.

---

## 1. Iterable vs Iterator

| Term | Meaning | Examples |
|------|---------|----------|
| **Iterable** | An object you can loop over | list, tuple, string, dict, set, range |
| **Iterator** | An object that gives the **next** item each time you ask | result of `iter(list)` |

An iterable can produce an iterator using the built-in `iter()` function.

```python
numbers = [10, 20, 30]

print(type(numbers))
print(type(iter(numbers)))
```

```output
<class 'list'>
<class 'list_iterator'>
```

---

## 2. Using `iter()` and `next()`

* `iter(obj)` creates an iterator from an iterable.
* `next(it)` returns the next item.

```python
numbers = [10, 20, 30]
it = iter(numbers)

print(next(it))
print(next(it))
print(next(it))
```

```output
10
20
30
```

An iterator remembers its position, so each `next()` call moves forward.

---

## 3. The `StopIteration` Exception

When no items are left, `next()` raises `StopIteration`.

```python
it = iter([1, 2])

print(next(it))
print(next(it))

try:
    print(next(it))
except StopIteration:
    print("No more items")
```

```output
1
2
No more items
```

You can give `next()` a default value to avoid the error:

```python
it = iter([1])
print(next(it, "Done"))
print(next(it, "Done"))
```

```output
1
Done
```

---

## 4. How a `for` Loop Really Works

A `for` loop does these steps automatically:

1. Calls `iter()` on the iterable.
2. Calls `next()` again and again.
3. Stops quietly when `StopIteration` is raised.

```python
for x in [1, 2, 3]:
    print(x)

# The same thing written manually
it = iter([1, 2, 3])
while True:
    try:
        x = next(it)
        print(x)
    except StopIteration:
        break
```

```output
1
2
3
1
2
3
```

---

## 5. Iterators Are Used Up

An iterator can be used **only once**. After it is finished, it stays empty.

```python
it = iter([1, 2, 3])

print(list(it))
print(list(it))
```

```output
[1, 2, 3]
[]
```

---

## 6. Creating a Custom Iterator

A class becomes an iterator when it defines two methods:

* `__iter__()` returns the iterator object itself.
* `__next__()` returns the next value or raises `StopIteration`.

```python
class Countdown:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        value = self.current
        self.current -= 1
        return value

for n in Countdown(3):
    print(n)
```

```output
3
2
1
```

---

## 7. What is a Generator?

Writing a class with `__iter__` and `__next__` is long. A **generator** is a much easier way to create an iterator. It is a function that uses the `yield` keyword instead of `return`.

```python
def count_up(n):
    for i in range(1, n + 1):
        yield i

gen = count_up(3)

print(type(gen))
print(next(gen))
print(next(gen))
print(next(gen))
```

```output
<class 'generator'>
1
2
3
```

---

## 8. `yield` vs `return`

| Feature | `return` | `yield` |
|---------|----------|---------|
| Function ends? | Yes, immediately | No, it **pauses** and remembers its state |
| Values given | One | Many, one at a time |
| Use | Normal functions | Generators |

A generator **pauses** at each `yield` and **resumes** from the same place on the next `next()` call.

```python
def demo():
    print("Step 1")
    yield "A"
    print("Step 2")
    yield "B"
    print("Step 3")

g = demo()

print(next(g))
print(next(g))
```

```output
Step 1
A
Step 2
B
```

---

## 9. Looping Over a Generator

```python
def squares(n):
    for i in range(1, n + 1):
        yield i * i

for value in squares(5):
    print(value)
```

```output
1
4
9
16
25
```

Converting to a list pulls out every value at once:

```python
def squares(n):
    for i in range(1, n + 1):
        yield i * i

print(list(squares(5)))
print(sum(squares(5)))
```

```output
[1, 4, 9, 16, 25]
55
```

---

## 10. Why Use Generators? (Lazy Evaluation)

A normal list stores **all** values in memory. A generator creates each value **only when needed**.

* Uses very little memory, even for millions of values.
* Starts giving results immediately.
* Can represent **infinite** sequences.

---

## 11. An Infinite Generator

```python
def natural_numbers():
    n = 1
    while True:
        yield n
        n += 1

gen = natural_numbers()

for _ in range(5):
    print(next(gen))
```

```output
1
2
3
4
5
```

This never runs out, yet it uses almost no memory because only one number exists at a time.

---

## 12. Fibonacci with a Generator

```python
def fibonacci(limit):
    a, b = 0, 1
    for _ in range(limit):
        yield a
        a, b = b, a + b

print(list(fibonacci(8)))
```

```output
[0, 1, 1, 2, 3, 5, 8, 13]
```

---

## 13. Generator Expressions

A generator expression looks like a list comprehension but uses **round brackets**.

```python
squares_list = [x * x for x in range(5)]
squares_gen = (x * x for x in range(5))

print(squares_list)
print(type(squares_gen))
print(sum(squares_gen))
```

```output
[0, 1, 4, 9, 16]
<class 'generator'>
30
```

Use a generator expression when you only need to loop through the results once, such as inside `sum()`, `max()` or `any()`.

---

## 14. `yield from`

`yield from` hands over values from another iterable.

```python
def combine():
    yield from [1, 2, 3]
    yield from "AB"

print(list(combine()))
```

```output
[1, 2, 3, 'A', 'B']
```

---

## 15. Generators Are Used Up Too

```python
gen = (x for x in range(3))

print(list(gen))
print(list(gen))
```

```output
[0, 1, 2]
[]
```

Create a new generator if you need the values again.

## Real-World Example 🌍

A generator that reads a large file **line by line** and keeps only matching lines, without loading the whole file into memory:

```python
def read_errors(lines):
    for line in lines:
        if "ERROR" in line:
            yield line.strip()

log = [
    "INFO: Server started",
    "ERROR: Disk full",
    "INFO: User logged in",
    "ERROR: Connection lost"
]

for error in read_errors(log):
    print(error)
```

```output
ERROR: Disk full
ERROR: Connection lost
```

With a real file you would pass `open("server.log")` instead of the list. The function stays the same.

## Common Mistakes

### Using `return` Instead of `yield`

```python
def numbers():
    for i in range(3):
        return i        # stops after the first value
```

Use `yield i` to produce all the values.

### Reusing an Exhausted Generator

A generator gives its values only once. Create it again to restart.

### Forgetting to Raise `StopIteration` in a Custom Iterator

Without it, the loop never ends.

### Trying to Index a Generator

```python
gen = (x for x in range(5))
print(gen[0])        # TypeError
```

Convert it with `list(gen)` first if you need indexing.

### Expecting a Generator Call to Run the Code

```python
g = demo()           # Nothing runs yet
```

The body runs only when you call `next(g)` or loop over it.

---

## Key Points

* An iterable can be looped over; an iterator gives items one at a time.
* `iter()` creates an iterator and `next()` fetches the next item.
* `StopIteration` signals that there are no more items.
* A `for` loop uses `iter()` and `next()` internally.
* A custom iterator needs `__iter__()` and `__next__()`.
* A generator is a function that uses `yield`.
* `yield` pauses the function and remembers its state.
* Generators are lazy, memory-efficient and can be infinite.
* A generator expression uses `( )` instead of `[ ]`.
* Iterators and generators can be used only once.
