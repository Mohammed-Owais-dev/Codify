# Chapter 9: Transitions, Transforms and Animations

## Section 5: Hover, Focus and Motion Preferences

Motion should help people, not bother them. In this lesson you will learn how to style **interactive states** like hover, focus and active, make them work for **keyboard and touch users** too, and respect people who prefer **less motion**. This is where good design meets accessibility.

---

## 1. Interactive States

Interactive elements such as links, buttons and form fields have different **states**. Each one has a pseudo-class.

| State | Pseudo-class | When it applies |
| ----- | ------------ | --------------- |
| Hover | `:hover` | The mouse pointer is over it |
| Focus | `:focus` | It has keyboard focus (or was clicked) |
| Keyboard focus | `:focus-visible` | It has focus, and the browser decides a focus ring is useful |
| Active | `:active` | It is being pressed |
| Visited | `:visited` | A link that was already visited |
| Disabled | `:disabled` | A form element that is turned off |

---

## 2. Hover Effects

A hover effect gives feedback that something can be clicked.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .btn {
    padding: 12px 26px;
    border: none;
    border-radius: 8px;
    color: white;
    font-size: 16px;
    cursor: pointer;
    background-color: #0ea5e9;
    transition: background-color 0.2s ease, transform 0.2s ease, box-shadow 0.2s ease;
  }
  .btn:hover {
    background-color: #0284c7;
    transform: translateY(-2px);
    box-shadow: 0 6px 14px rgba(2, 132, 199, 0.4);
  }
</style>

<button class="btn">Hover me</button>
```

---

## 3. The :active State

`:active` shows while the button is being pressed. It gives a "pushed" feeling.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .btn {
    padding: 12px 26px;
    border: none;
    border-radius: 8px;
    color: white;
    font-size: 16px;
    cursor: pointer;
    background-color: #16a34a;
    box-shadow: 0 4px 0 #166534;
    transition: transform 0.1s ease, box-shadow 0.1s ease;
  }
  .btn:active {
    transform: translateY(3px);
    box-shadow: 0 1px 0 #166534;
  }
</style>

<button class="btn">Press me</button>
```

## 4. Focus States

Not everyone uses a mouse. Many people move through a page with the **Tab key**. A visible focus style shows them where they are. **Never remove the focus outline without adding a clear replacement.**

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .field {
    display: block;
    width: 240px;
    margin-bottom: 12px;
    padding: 10px 12px;
    border: 2px solid #94a3b8;
    border-radius: 8px;
    font-size: 16px;
    transition: border-color 0.2s ease, box-shadow 0.2s ease;
  }
  .field:focus {
    outline: none;
    border-color: #0ea5e9;
    box-shadow: 0 0 0 4px rgba(14, 165, 233, 0.3);
  }
</style>

<input class="field" type="text" placeholder="Click or press Tab">
<input class="field" type="text" placeholder="Another field">
```

Here we removed the default outline, but added a blue border and a soft ring instead. This is acceptable because the replacement is clear.

---

## 5. :focus-visible

`:focus` also triggers when you click with the mouse. `:focus-visible` triggers only when the browser thinks the user needs a focus ring, such as keyboard navigation. This keeps mouse clicks clean, and still helps keyboard users.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .btn {
    padding: 12px 26px;
    margin-right: 8px;
    border: none;
    border-radius: 8px;
    color: white;
    font-size: 16px;
    cursor: pointer;
    background-color: #7c3aed;
  }
  .btn:focus-visible {
    outline: 3px solid #f59e0b;
    outline-offset: 3px;
  }
</style>

<button class="btn">First</button>
<button class="btn">Second</button>
<p>Click a button with the mouse, then press Tab to move between them.</p>
```

---

## 6. :focus-within

`:focus-within` matches a **parent** when any child inside it has focus. It is good for highlighting a whole form group.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .group {
    width: 260px;
    padding: 12px;
    border: 2px solid #cbd5e1;
    border-radius: 10px;
    transition: border-color 0.2s ease, background-color 0.2s ease;
  }
  .group:focus-within {
    border-color: #0ea5e9;
    background-color: #f0f9ff;
  }
  .group label {
    display: block;
    margin-bottom: 6px;
    font-size: 14px;
  }
  .group input {
    width: 100%;
    padding: 8px;
    box-sizing: border-box;
  }
</style>

<div class="group">
  <label for="name">Your name</label>
  <input id="name" type="text">
</div>
```

## 7. Hover on Touch Devices

Phones and tablets have no real hover. Some devices also keep a "stuck" hover state after a tap. Keep these rules in mind:

* **Do not hide important content behind hover only.**
* Put hover-only styles inside `@media (hover: hover)`, so they apply only to devices that can hover.
* Give touch users `:active` feedback.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .card {
    width: 240px;
    padding: 18px;
    color: #0f172a;
    background-color: white;
    border-radius: 10px;
    box-shadow: 0 2px 6px rgba(0, 0, 0, 0.15);
    transition: transform 0.25s ease, box-shadow 0.25s ease;
  }

  @media (hover: hover) {
    .card:hover {
      transform: translateY(-6px);
      box-shadow: 0 14px 26px rgba(0, 0, 0, 0.22);
    }
  }
  .card:active {
    transform: scale(0.98);
  }
</style>

<div class="card">A card that lifts only on devices with real hover</div>
```

## 8. Link Styling Order: LVHFA

When you style links with several states, the order of your rules matters, because they have the same specificity. A good order to remember is:

**L**ink, **V**isited, **H**over, **F**ocus, **A**ctive (a friendly way to remember: "LoVe HAte" becomes LVHFA).

```css
a:link { color: #0369a1; }
a:visited { color: #6d28d9; }
a:hover { color: #0ea5e9; }
a:focus-visible { outline: 3px solid #f59e0b; }
a:active { color: #0c4a6e; }
```

If `:hover` came before `:visited`, the visited color would always win on visited links.

## 9. Why Reduced Motion Matters

Some people have **vestibular disorders**, migraines or other conditions where large movement, spinning or parallax can cause dizziness, nausea or pain. Their devices have a setting such as **Reduce motion**. Your CSS can see this setting with the `prefers-reduced-motion` media feature.

| Value | Meaning |
| ----- | ------- |
| `no-preference` | The user did not ask for less motion |
| `reduce` | The user wants less motion |

---

## 10. Respecting prefers-reduced-motion

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  @keyframes bounce {
    0%, 100% {
      transform: translateY(0);
    }
    50% {
      transform: translateY(-30px);
    }
  }
  .ball {
    width: 50px;
    height: 50px;
    margin: 50px 20px 10px;
    background-color: #f97316;
    border-radius: 50%;
    animation: bounce 1s ease-in-out infinite;
  }

  @media (prefers-reduced-motion: reduce) {
    .ball {
      animation: none;
    }
  }
</style>

<div class="ball"></div>
<p>If your device is set to "reduce motion", the ball stays still.</p>
```

A good approach is to apply a small, safe rule for the whole site:

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

This nearly removes all animation and transitions on the page.

## 11. Reduce, Do Not Always Remove

"Reduce motion" does not always mean "no animation at all". Good choices are:

* Replace big moving effects (sliding, zooming, spinning) with a simple **fade**.
* Keep small, helpful changes such as a color change.
* Remove **auto-playing** and **infinite** animations that distract.
* Avoid parallax and large background movement.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  @keyframes slide-in {
    from {
      opacity: 0;
      transform: translateX(-60px);
    }
    to {
      opacity: 1;
      transform: translateX(0);
    }
  }
  @keyframes fade-in {
    from {
      opacity: 0;
    }
    to {
      opacity: 1;
    }
  }
  .panel {
    padding: 16px;
    color: white;
    background-color: #0ea5e9;
    border-radius: 10px;
    animation: slide-in 0.6s ease both;
  }

  @media (prefers-reduced-motion: reduce) {
    .panel {
      animation-name: fade-in;
    }
  }
</style>

<div class="panel">Slides in normally, and only fades in for users who want less motion</div>
```

---

## 12. Motion Safety Checklist

* Nothing should flash more than **three times per second**. Fast flashing can trigger seizures.
* Give users a way to **pause, stop or hide** moving content that plays for more than five seconds.
* Keep transitions short (0.15s to 0.4s) for UI feedback.
* Do not use motion as the **only** way to give information. Add text or color too.
* Test with your system's "reduce motion" setting turned on.

## Real-World Example 🌍

An accessible button group with hover, focus, active and reduced-motion support:

```html
<style>
  * {
    box-sizing: border-box;
  }
  body {
    margin: 0;
    padding: 20px;
    font-family: Arial, sans-serif;
    background-color: #f1f5f9;
  }
  .actions {
    display: flex;
    flex-wrap: wrap;
    gap: 10px;
    max-width: 360px;
    margin: 0 auto;
  }
  .action {
    flex: 1 1 140px;
    padding: 14px 18px;
    border: 2px solid #0ea5e9;
    border-radius: 10px;
    color: #0369a1;
    font-size: 16px;
    background-color: white;
    cursor: pointer;
    transition: background-color 0.2s ease, color 0.2s ease, transform 0.2s ease;
  }
  @media (hover: hover) {
    .action:hover {
      color: white;
      background-color: #0ea5e9;
      transform: translateY(-3px);
    }
  }
  .action:focus-visible {
    outline: 3px solid #f59e0b;
    outline-offset: 3px;
  }
  .action:active {
    transform: scale(0.97);
  }
  .action:disabled {
    color: #94a3b8;
    border-color: #cbd5e1;
    cursor: not-allowed;
  }

  @media (prefers-reduced-motion: reduce) {
    .action {
      transition: background-color 0.01ms, color 0.01ms;
    }
    .action:hover,
    .action:active {
      transform: none;
    }
  }
</style>

<div class="actions">
  <button class="action">Save</button>
  <button class="action">Share</button>
  <button class="action" disabled>Delete</button>
</div>
```

## Common Mistakes

### Removing the Focus Outline Without a Replacement

```css
button:focus { outline: none; }                                /* keyboard users get lost */
button:focus-visible { outline: 3px solid #f59e0b; }
```

### Hover-Only Content

```css
.menu:hover .sub { display: block; }     /* touch users cannot open it */
/* Also open it on :focus-within or with a button click. */
```

### Wrong Order for Link States

```css
a:hover { color: red; }
a:visited { color: purple; }     /* visited now overrides hover */
```

### Ignoring Reduced Motion

```css
.hero { animation: zoom 10s infinite; }    /* no option for users who need less motion */
```

### Hover Effects That Are Too Strong or Too Slow

```css
.card:hover { transform: scale(2); transition: 2s; }   /* feels jarring */
.card:hover { transform: translateY(-4px); transition: 0.2s; }
```

---

## Key Points

* Style the states of interactive elements: `:hover`, `:focus`, `:focus-visible`, `:active` and `:disabled`.
* Never remove the focus outline without a clear replacement.
* `:focus-visible` shows focus rings for keyboard users, and keeps mouse clicks clean.
* `:focus-within` styles a parent when a child has focus.
* Put hover-only effects inside `@media (hover: hover)`, and add `:active` feedback for touch.
* Remember link state order: **L**ink, **V**isited, **H**over, **F**ocus, **A**ctive.
* Use `@media (prefers-reduced-motion: reduce)` to turn off or soften animations.
* Replace big motion with a simple fade, and remove infinite or auto-playing effects.
* Do not flash content more than three times per second.
* Make sure every action works for mouse, keyboard and touch users.
