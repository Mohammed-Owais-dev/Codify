# Chapter 2: Selectors and the Cascade

## Section 3: Attribute and Combinator Selectors

Classes and ids are not the only way to find elements. CSS can also select elements by their **attributes** (such as `type` or `href`) and by their **position** in the HTML family tree (such as "a link inside a nav"). In this lesson you will learn attribute selectors and the four combinators.

---

## 1. Attribute Selectors

An **attribute selector** is written in square brackets `[ ]`. It selects elements that have a certain attribute, or an attribute with a certain value.

```text
[attribute]              has the attribute
[attribute="value"]      attribute equals the value exactly
[attribute^="value"]     attribute starts with the value
[attribute$="value"]     attribute ends with the value
[attribute*="value"]     attribute contains the value anywhere
```

Attribute selectors are powerful because you can style elements without adding any extra classes.

---

## 2. Has the Attribute: [attribute]

This selects every element that has the attribute, no matter what its value is.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  [title] {
    border-bottom: 2px dotted #7c3aed;
    cursor: help;
  }
</style>

<p>This text has no title attribute.</p>
<p title="More information here">Hover over this text, it has a title.</p>
<abbr title="HyperText Markup Language">HTML</abbr>
```

---

## 3. Exact Value: [attribute="value"]

This matches only when the attribute value is exactly the same. It is very useful for form inputs.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  input[type="text"] {
    border: 2px solid #0ea5e9;
    padding: 8px;
    border-radius: 6px;
  }
  input[type="password"] {
    border: 2px solid #f97316;
    padding: 8px;
    border-radius: 6px;
  }
</style>

<p><input type="text" placeholder="Username"></p>
<p><input type="password" placeholder="Password"></p>
```

Both fields are `<input>` elements, but each gets a different style because of its `type` attribute.

---

## 4. Starts With, Ends With and Contains

Three special operators match part of the value.

| Selector | Meaning | Example match |
| -------- | ------- | ------------- |
| `[href^="https"]` | Value **starts** with `https` | `https://example.com` |
| `[href$=".pdf"]` | Value **ends** with `.pdf` | `notes.pdf` |
| `[href*="codify"]` | Value **contains** `codify` | `https://codify.com/css` |

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  a[href^="https"] {
    color: #16a34a;
  }
  a[href$=".pdf"] {
    color: #dc2626;
    font-weight: bold;
  }
  a[href*="codify"] {
    text-decoration: underline wavy;
  }
</style>

<p><a href="https://example.com">Secure link (starts with https)</a></p>
<p><a href="syllabus.pdf">Download syllabus.pdf (ends with .pdf)</a></p>
<p><a href="https://example.com/css">Codify CSS (contains codify)</a></p>
<p><a href="about.html">Normal link</a></p>
```

Developers often use `[href$=".pdf"]` to add a small file icon automatically to every PDF link.

---

## 5. Combinators: Using the Family Tree

HTML elements form a family tree: parents, children, siblings. A **combinator** is a symbol that joins two selectors using their relationship.

```html
<div class="menu">           <- parent
  <p>First</p>               <- child of .menu
  <p>Second</p>              <- child, and sibling of the first p
  <span>
     <a href="#">Link</a>    <- descendant of .menu (grandchild)
  </span>
</div>
```

There are four combinators:

| Combinator | Symbol | Meaning |
| ---------- | ------ | ------- |
| Descendant | space | Any element **inside** another, at any depth |
| Child | `>` | Only **direct** children |
| Adjacent sibling | `+` | The **very next** sibling |
| General sibling | `~` | **All following** siblings |

---

## 6. Descendant Combinator (space)

A space between two selectors selects the second one when it is **anywhere inside** the first.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .article p {
    color: #1d4ed8;
  }
</style>

<div class="article">
  <p>A paragraph inside the article.</p>
  <section>
    <p>A deeper paragraph, still inside the article.</p>
  </section>
</div>
<p>A paragraph outside the article.</p>
```

Both paragraphs inside `.article` are blue, even the one in the nested `section`. The paragraph outside stays normal.

---

## 7. Child Combinator (>)

The `>` selects only **direct children**, not deeper descendants.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .box > p {
    color: #dc2626;
    font-weight: bold;
  }
</style>

<div class="box">
  <p>Direct child: styled.</p>
  <section>
    <p>Grandchild: NOT styled.</p>
  </section>
</div>
```

Only the first paragraph is red. The second is inside a `section`, so it is not a direct child of `.box`.

---

## 8. Adjacent Sibling Combinator (+)

The `+` selects the element that comes **immediately after** another, at the same level.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  h3 + p {
    background-color: #fef9c3;
    padding: 6px;
  }
</style>

<h3>Heading</h3>
<p>This paragraph comes right after the h3, so it is highlighted.</p>
<p>This second paragraph is not the immediate neighbour.</p>
```

---

## 9. General Sibling Combinator (~)

The `~` selects **all** matching siblings that come **after** the first element.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  h3 ~ p {
    color: #0f766e;
  }
</style>

<p>Before the heading: not styled.</p>
<h3>Heading</h3>
<p>After the heading: styled.</p>
<p>Also after the heading: styled.</p>
```

The difference from `+`: `h3 + p` picks only the first paragraph after the heading, while `h3 ~ p` picks every paragraph after it.

---

## 10. Combining Everything

Selectors can be chained to be very precise. Read them from **right to left** to understand them: the last part is the element that actually gets styled.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  nav > ul > li > a[href^="https"] {
    color: #7c3aed;
    font-weight: bold;
    text-decoration: none;
  }
</style>

<nav>
  <ul>
    <li><a href="https://example.com">External site</a></li>
    <li><a href="home.html">Home page</a></li>
  </ul>
</nav>
```

This reads: "Style a link whose `href` starts with `https`, that is inside an `li`, inside a `ul`, inside a `nav`." Do not make selectors longer than needed, because long selectors are hard to read and to override.

## Real-World Example

A navigation menu and a download list styled using combinators and attribute selectors:

```html
<style>
  body {
    font-family: Arial, sans-serif;
    padding: 16px;
  }
  .menu {
    list-style: none;
    padding: 0;
    display: flex;
    gap: 10px;
    background-color: #0f172a;
    border-radius: 8px;
    padding: 10px;
  }
  .menu > li > a {
    color: white;
    text-decoration: none;
    padding: 6px 12px;
    border-radius: 6px;
  }
  .menu > li + li > a {
    background-color: #1e293b;
  }
  .files a[href$=".pdf"] {
    color: #dc2626;
    font-weight: bold;
  }
  .files a[href$=".zip"] {
    color: #7c3aed;
    font-weight: bold;
  }
  .files a[href^="https"] {
    color: #16a34a;
  }
</style>

<ul class="menu">
  <li><a href="#">Home</a></li>
  <li><a href="#">Courses</a></li>
  <li><a href="#">Contact</a></li>
</ul>

<h3>Downloads</h3>
<ul class="files">
  <li><a href="notes.pdf">CSS notes (PDF)</a></li>
  <li><a href="starter.zip">Starter files (ZIP)</a></li>
  <li><a href="https://codify.com">Codify website</a></li>
</ul>
```

Not a single extra class is needed on the links. The selectors find them by position and by their `href` value.

## Common Mistakes

### Forgetting the Quotes in Attribute Values

```css
input[type=text] { }       /* often works, but quotes are safer */
input[type="text"] { }     /* recommended */
```

Quotes are required when the value has spaces or special characters, so make it a habit to always use them.

### Confusing Descendant and Child

```css
.box p { }       /* every p inside .box, at any depth */
.box > p { }     /* only p elements directly inside .box */
```

### Confusing + and ~

```css
h3 + p { }     /* only the first p right after h3 */
h3 ~ p { }     /* all p siblings after h3 */
```

### Adding Spaces Inside the Selector by Mistake

```css
a [href] { }     /* any [href] element INSIDE an a */
a[href] { }      /* an a element that has an href */
```

### Looking Backwards

```css
li + h3 { }
```

Sibling combinators only look **forward**. CSS cannot select a previous sibling with `+` or `~`.

---

## Key Points

* **Attribute selectors** use square brackets: `[type="text"]`.
* `[attr]` checks if the attribute exists, and `[attr="value"]` checks for an exact value.
* `^=` means starts with, `$=` means ends with, and `*=` means contains.
* A **combinator** joins selectors based on how the elements are related.
* **Space** is the descendant combinator, and it matches elements at any depth inside.
* `>` is the **child** combinator and matches only direct children.
* `+` matches the **next** sibling, and `~` matches **all following** siblings.
* Read long selectors from right to left, and keep them as short as you can.

- [ ] `~`

- [ ] A space
