# Chapter 2: Selectors and the Cascade

## Section 5: Cascade, Specificity and Inheritance

What happens when two CSS rules try to style the same element in different ways? Which color does the text get? The browser follows a clear system called the **cascade**. This lesson explains the three big ideas that decide the final style: **order**, **specificity** and **inheritance**.

---

## 1. What Is the Cascade?

The "C" in CSS means **Cascading**. When many rules apply to one element, the browser picks the winner by checking these things in order:

1. **Importance:** a declaration marked `!important` beats a normal one.
2. **Specificity:** a more specific selector beats a less specific one.
3. **Source order:** if everything else is equal, the rule written **last** wins.

```text
Rule A: p { color: blue; }
Rule B: p { color: red; }

Same importance + same specificity -> the later rule (B) wins -> red
```

Styles that are not written by you also take part: the browser's default styles are the weakest, and your styles override them.

---

## 2. Rule 1: Source Order

When two rules have the same specificity, the **last one** in the stylesheet wins.

```html
<style>
  p {
    color: blue;
  }
  p {
    color: green;
  }
</style>

<p>This text is green because the green rule comes last.</p>
```

If you swap the order of the two rules, the text becomes blue.

---

## 3. Rule 2: Specificity

**Specificity** is a score that tells how targeted a selector is. A more specific selector wins even if it comes **earlier** in the file.

| Selector type | Strength | Example |
| ------------- | -------- | ------- |
| Universal selector | Lowest (zero) | `*` |
| Element or pseudo-element | Low | `p`, `::before` |
| Class, attribute or pseudo-class | Medium | `.note`, `[type="text"]`, `:hover` |
| ID | High | `#title` |
| Inline style | Very high | `style="..."` |

```html
<style>
  #unique {
    color: red;
  }
  .note {
    color: green;
  }
  p {
    color: blue;
  }
</style>

<p id="unique" class="note">I am red, because the id is the strongest.</p>
<p class="note">I am green, because a class beats an element.</p>
<p>I am blue, the element selector only.</p>
```

The first paragraph matches all three rules, but the id rule wins. Order does not matter here, because specificity is checked first.

---

## 4. Counting Specificity

Specificity is counted as three numbers: **(IDs, classes, elements)**. Compare them from left to right.

| Selector | IDs | Classes | Elements | Score |
| -------- | --- | ------- | -------- | ----- |
| `p` | 0 | 0 | 1 | (0, 0, 1) |
| `.note` | 0 | 1 | 0 | (0, 1, 0) |
| `p.note` | 0 | 1 | 1 | (0, 1, 1) |
| `ul li a` | 0 | 0 | 3 | (0, 0, 3) |
| `.menu li.active` | 0 | 2 | 1 | (0, 2, 1) |
| `#nav a:hover` | 1 | 1 | 1 | (1, 1, 1) |

Important: the columns are **not** added into one number. One id (1, 0, 0) always beats any number of classes, such as (0, 20, 0). Compare the first column first, then the next, and so on.

```html
<style>
  p.note {
    color: red;
  }
  .box p {
    color: blue;
  }
  body .box p.note {
    color: purple;
  }
</style>

<div class="box">
  <p class="note">Purple wins: (0, 2, 3) beats (0, 1, 1) and (0, 1, 1).</p>
</div>
```

---

## 5. Inline Styles and IDs

An inline `style` attribute is stronger than any selector in a stylesheet, including an id selector.

```html
<style>
  #banner {
    color: red;
  }
</style>

<p id="banner" style="color: green;">I am green because inline styles are stronger than ids.</p>
```

This is why inline styles are hard to override and should be avoided in real projects.

---

## 6. The !important Declaration

Adding `!important` after a value makes that declaration beat normal declarations, even inline styles.

```html
<style>
  p {
    color: orange !important;
  }
  #banner {
    color: red;
  }
</style>

<p id="banner" style="color: green;">I am orange because of !important.</p>
```

`!important` is like an emergency button. It makes your CSS harder to change later, because the only way to beat it is another `!important` with equal or higher strength. Use it very rarely, for example to override styles from a library you cannot edit.

---

## 7. What Is Inheritance?

Some properties are **passed down** from a parent element to its children automatically. This is called **inheritance**. You set the style once on the parent, and the children follow.

```html
<style>
  .parent {
    color: #7c3aed;
    font-family: Georgia, serif;
    border: 3px solid #7c3aed;
    padding: 12px;
  }
</style>

<div class="parent">
  Parent text
  <p>Child paragraph: inherits the color and font, but not the border.</p>
</div>
```

The paragraph is purple and uses Georgia, but it has no border of its own. Text properties are inherited, but box properties like `border` are not.

---

## 8. Which Properties Are Inherited?

| Usually inherited | Usually NOT inherited |
| ----------------- | --------------------- |
| `color` | `margin`, `padding` |
| `font-family`, `font-size`, `font-weight` | `border` |
| `line-height`, `letter-spacing` | `background` |
| `text-align`, `text-indent` | `width`, `height` |
| `visibility`, `cursor` | `display`, `position` |
| `list-style` | `overflow` |

The idea makes sense: you want text style to flow through the page, but you do not want every child to get its own border and background.

---

## 9. Controlling Inheritance with Keywords

Four special keywords can be used as the value of any property.

| Keyword | Meaning |
| ------- | ------- |
| `inherit` | Take the value from the parent |
| `initial` | Use the default value defined by CSS |
| `unset` | Act like `inherit` if the property is normally inherited, otherwise like `initial` |
| `revert` | Go back to the browser's default style |

A common use is making buttons and inputs match the page font. Form controls do not inherit fonts by default.

```html
<style>
  body {
    font-family: Georgia, serif;
    font-size: 18px;
  }
  .plain-button {
    padding: 8px 16px;
  }
  .matching-button {
    padding: 8px 16px;
    font-family: inherit;
    font-size: inherit;
  }
</style>

<p>Default button font:</p>
<button class="plain-button">Submit</button>
<p>Button that inherits the page font:</p>
<button class="matching-button">Submit</button>
```

## 10. Why Is My Style Not Working?

When a style does not apply, follow these steps:

1. **Check spelling** of the selector, class name and property.
2. **Open DevTools** (F12) and inspect the element. In the Styles panel, a rule that lost is shown with a **line through it**.
3. **Compare specificity.** Is there a stronger selector, an id or an inline style?
4. **Check the order.** Is another rule with the same strength written after yours?
5. **Check inheritance.** Is the property one that is inherited, or are you expecting it on a child?
6. **Check the link.** Is your CSS file actually loaded?

---

## 11. Writing CSS That Is Easy to Manage

* Prefer **classes** for styling. They are strong enough, and easy to override.
* Avoid styling with **ids** and avoid **inline styles**.
* Avoid long selectors like `body div.main ul li a`. They are hard to override.
* Avoid `!important` unless there is no other way.
* Put general styles first and special styles later in the file.
* Set text styles once on `body` and let inheritance do the rest.

## Real-World Example 🌍

A page that uses inheritance for the base design and specificity for special cases:

```html
<style>
  body {
    font-family: Arial, sans-serif;
    color: #334155;
    line-height: 1.6;
    background-color: #f8fafc;
    padding: 20px;
  }
  h2 {
    color: #0f172a;
  }
  .alert {
    background-color: #fef2f2;
    border: 1px solid #fecaca;
    padding: 12px;
    border-radius: 8px;
    color: #b91c1c;
  }
  .alert.success {
    background-color: #f0fdf4;
    border-color: #bbf7d0;
    color: #15803d;
  }
  .alert strong {
    text-transform: uppercase;
  }
  button {
    font-family: inherit;
    padding: 8px 18px;
    border-radius: 6px;
    border: none;
    background-color: #2563eb;
    color: white;
  }
</style>

<h2>Messages</h2>
<p class="alert"><strong>Error:</strong> Your password is too short.</p>
<p class="alert success"><strong>Success:</strong> Your profile was saved.</p>
<button>Try again</button>
```

The page font and color come from `body` through inheritance. `.alert.success` has a higher specificity than `.alert`, so its green colors win without `!important`.

## Common Mistakes

### Thinking the Last Rule Always Wins

```text
.note { color: green; }
p { color: red; }
```

A paragraph with the class `note` is green. A class is more specific than an element, so order does not matter.

### Adding Specificity by Adding More IDs

```text
#a #b #c { color: red; }
```

Making selectors stronger and stronger starts a "specificity war". Instead, write simpler selectors and organize your CSS.

### Overusing !important

```text
p { color: red !important; }
.note { color: blue !important; }
```

When everything is `!important`, nothing is. This makes the CSS very difficult to fix.

### Expecting Every Property to Inherit

```text
.parent { border: 2px solid red; }
```

The children will **not** get a border. Only properties like `color` and `font-family` are inherited by default.

### Forgetting That Inline Styles Are Strong

```text
<p style="color: red;" class="blue-text">
```

Even if `.blue-text` sets blue, the inline red wins.

---

## Key Points

* The **cascade** chooses the winning rule using importance, specificity and source order.
* A more **specific** selector beats a less specific one, no matter where it is written.
* Specificity is counted as (IDs, classes, elements) and compared from left to right.
* Order is (weakest to strongest): `*`, elements, classes and pseudo-classes, ids, inline styles.
* If specificity is equal, the **last** rule wins.
* `!important` beats normal rules, but should be used very rarely.
* **Inheritance** passes properties like `color` and `font-family` from parent to child.
* Box properties such as `margin`, `padding`, `border` and `background` are not inherited.
* The keywords `inherit`, `initial`, `unset` and `revert` control inheritance.
* Use DevTools to see which rules won and which were crossed out.
