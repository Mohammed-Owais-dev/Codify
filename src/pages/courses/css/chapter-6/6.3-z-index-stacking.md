# Chapter 6: Layout with Display and Position

## Section 3: z-index and Stacking Context

When elements overlap, the browser must decide which one is **on top**. This is called stacking. The `z-index` property gives you control over it. In this lesson you will learn how stacking works and why `z-index` sometimes seems not to work.

---

## 1. The Third Dimension

The screen has an **x-axis** (left to right) and a **y-axis** (top to bottom). The **z-axis** goes from the screen toward you. A bigger z-index means closer to the viewer.

---

## 2. Default Stacking Order

If you do not set any `z-index`, elements are stacked in this order, from back to front:

1. The background and borders of the parent
2. Normal-flow block elements
3. Floated elements
4. Normal-flow inline elements
5. **Positioned** elements (`relative`, `absolute`, `fixed`, `sticky`), in HTML order

So a positioned element is above normal elements. When two positioned elements overlap, the one that comes **later in the HTML** is on top.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .stack {
    position: relative;
    height: 150px;
  }
  .box {
    position: absolute;
    width: 120px;
    height: 80px;
    color: white;
    padding: 8px;
  }
  .one {
    top: 10px;
    left: 10px;
    background-color: #0ea5e9;
  }
  .two {
    top: 40px;
    left: 70px;
    background-color: #f97316;
  }
</style>

<div class="stack">
  <div class="box one">Box 1</div>
  <div class="box two">Box 2 (later in HTML)</div>
</div>
```

---

## 3. Using z-index

`z-index` takes a number. A higher number is placed on top. Negative numbers are allowed. It works only on **positioned** elements (and on flex and grid items).

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .stack {
    position: relative;
    height: 150px;
  }
  .box {
    position: absolute;
    width: 120px;
    height: 80px;
    color: white;
    padding: 8px;
  }
  .one {
    top: 10px;
    left: 10px;
    background-color: #0ea5e9;
    z-index: 2;
  }
  .two {
    top: 40px;
    left: 70px;
    background-color: #f97316;
    z-index: 1;
  }
</style>

<div class="stack">
  <div class="box one">Box 1 (z-index 2)</div>
  <div class="box two">Box 2 (z-index 1)</div>
</div>
```

Now Box 1 is on top, even though it comes first in the HTML.

---

## 4. z-index Needs a Position

A very common problem is a z-index that does nothing. The reason is usually that the element is `position: static`.

```css
.modal { z-index: 999; }                        /* ignored */
.modal { position: relative; z-index: 999; }    /* works */
```

The exception is flex and grid items, where `z-index` works without `position`.

---

## 5. Negative z-index

A negative z-index puts an element **behind** its parent's content. This is used for decorations behind text.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .wrap {
    position: relative;
    z-index: 0;
    width: 260px;
    padding: 30px 20px;
    background-color: white;
  }
  .wrap::before {
    content: "";
    position: absolute;
    top: 8px;
    left: 8px;
    right: -8px;
    bottom: -8px;
    background-color: #fde68a;
    z-index: -1;
  }
</style>

<div class="wrap">Text with a colored shape behind it</div>
```

Notice that `.wrap` has `z-index: 0`. This keeps the `-1` layer inside `.wrap`, so it does not slip behind the page background. This leads us to stacking contexts.

---

## 6. What Is a Stacking Context?

A **stacking context** is like a separate layer group. Inside it, children are sorted by their own z-index. The whole group is then treated as **one single layer** in its parent.

A new stacking context is created when an element has:

* the root `<html>` element
* `position: absolute` or `relative` with a `z-index` other than `auto`
* `position: fixed` or `sticky`
* `opacity` less than `1`
* `transform`, `filter` or `perspective`
* a flex or grid child with a `z-index` other than `auto`

---

## 7. The Trap: A High z-index That Loses

A child can never go above something outside of its parent's stacking context. Its z-index only matters **inside** the parent.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .scene {
    position: relative;
    height: 170px;
  }
  .parent-a {
    position: absolute;
    top: 10px;
    left: 10px;
    width: 160px;
    height: 100px;
    background-color: #bae6fd;
    z-index: 1;
  }
  .child-a {
    position: absolute;
    top: 50px;
    left: 80px;
    width: 140px;
    height: 70px;
    background-color: #0284c7;
    color: white;
    padding: 6px;
    z-index: 9999;
  }
  .parent-b {
    position: absolute;
    top: 30px;
    left: 100px;
    width: 160px;
    height: 100px;
    background-color: #fed7aa;
    z-index: 2;
  }
</style>

<div class="scene">
  <div class="parent-a">
    Parent A (z 1)
    <div class="child-a">Child (z 9999)</div>
  </div>
  <div class="parent-b">Parent B (z 2)</div>
</div>
```

The child has `z-index: 9999`, but it is still **below** Parent B. Parent A has z-index 1, Parent B has z-index 2, and the child's big number only counts inside Parent A.

When a z-index does not work, look at the **parents**. Find which one makes a stacking context.

---

## 8. Good z-index Habits

* Use **small numbers** (1, 2, 10, 100). Do not race to `99999`.
* Keep a simple scale for the whole project, for example: dropdown `100`, sticky header `200`, modal `300`, toast `400`.
* Use CSS variables to name them. You will learn this in chapter 10.
* Create a stacking context on purpose with `isolation: isolate`, so a component's inner layers stay inside it.

```css
.card { isolation: isolate; }
```

## Real-World Example 🌍

A dropdown menu that appears above the content below it:

```html
<style>
  * {
    box-sizing: border-box;
  }
  body {
    margin: 0;
    padding: 16px;
    font-family: Arial, sans-serif;
    background-color: #f1f5f9;
  }
  .menu {
    position: relative;
    display: inline-block;
    z-index: 10;
  }
  .menu button {
    padding: 10px 18px;
    border: none;
    border-radius: 8px;
    background-color: #0f172a;
    color: white;
    cursor: pointer;
  }
  .dropdown {
    position: absolute;
    top: 100%;
    left: 0;
    min-width: 160px;
    margin-top: 6px;
    background-color: white;
    border: 1px solid #cbd5e1;
    border-radius: 8px;

    margin-top: 10px;

<div class="menu">

  <div class="dropdown">
    <a href="#">HTML</a>

  </div>

```

## Common Mistakes

### z-index on a Static Element

```css
.box { z-index: 10; }                       /* no effect */
.box { position: relative; z-index: 10; }   /* works */
```

### Trying to Beat a Parent's Stacking Context

```css
.child { z-index: 99999; }    /* still below elements outside its stacking parent */
```

### Using Huge Numbers

```css
.modal { z-index: 2147483647; }   /* hard to manage later */
.modal { z-index: 300; }          /* use a clear scale */
```

### Forgetting That opacity and transform Create Contexts

```css
.card { transform: translateY(0); }   /* now .card is a stacking context */
```

---

## Key Points

* `z-index` controls which overlapping element is on top. A bigger number is closer to you.
* It works on positioned elements, and on flex and grid items.
* Without z-index, positioned elements stack in HTML order, and later ones are on top.
* A **stacking context** groups layers. Children are sorted only inside their own context.
* `opacity` below 1, `transform`, `filter`, `fixed` and `sticky` create new stacking contexts.
* A child with a huge z-index cannot go above elements outside its parent's context.
* Use a small, clear z-index scale and `isolation: isolate` to keep things simple.
