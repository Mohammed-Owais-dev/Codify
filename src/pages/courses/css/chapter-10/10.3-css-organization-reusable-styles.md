# Chapter 10: Practical CSS and Best Practices

## Section 3: CSS Organization and Reusable Styles

Small projects are easy to manage. But as a website grows, the CSS file can turn into a mess of long rules, repeated code and surprising overrides. In this lesson you will learn how to **organize** your CSS, name things clearly, and write **reusable** styles so your code stays easy to read and change.

---

## 1. Why Organization Matters

Messy CSS causes real problems:

* You cannot find the rule you need to change.
* Changing one thing breaks something somewhere else.
* The same code is copied in many places.
* New team members are afraid to touch the file.

Good organization makes your CSS **predictable**, **short** and **easy to maintain**.

---

## 2. A Good File Structure

Start with a clear order in your stylesheet. A common order goes from general to specific.

```text
/* 1. Variables */
:root { ... }

/* 2. Reset / base styles */
*, *::before, *::after { box-sizing: border-box; }
body { ... }
img { max-width: 100%; height: auto; }

/* 3. Layout (page structure) */
.container { ... }
.grid { ... }

/* 4. Components (cards, buttons, forms, nav) */
.card { ... }
.btn { ... }

/* 5. Utilities (small helper classes) */
.text-center { ... }
.mt-2 { ... }

/* 6. Page-specific or responsive tweaks */
@media (min-width: 768px) { ... }
```

For bigger projects, split these into separate files (`base.css`, `layout.css`, `components.css`, `utilities.css`) and link them in order.

---

## 3. Naming Classes Clearly

A class name should say **what the thing is** or **what it does**, not how it looks.

| Weak name | Better name | Why |
| --------- | ----------- | --- |
| `.red-box` | `.alert-error` | The color may change later |
| `.big-text` | `.page-title` | Describes the role |
| `.left` | `.sidebar` | The position may change |
| `.div1` | `.product-card` | Explains the content |

Use lowercase letters and dashes (called **kebab-case**): `.product-card`, `.nav-link`.

---

## 4. The BEM Naming Method

**BEM** stands for **Block, Element, Modifier**. It is a popular way to name classes in larger projects.

| Part | Meaning | Format | Example |
| ---- | ------- | ------ | ------- |
| **Block** | A standalone component | `.block` | `.card` |
| **Element** | A part inside the block | `.block__element` | `.card__title` |
| **Modifier** | A variation of the block or element | `.block--modifier` | `.card--featured` |

```html
<style>
  body {
    font-family: Arial, sans-serif;
    background-color: #f1f5f9;
    padding: 14px;
  }
  .card {
    max-width: 280px;
    margin-bottom: 12px;
    padding: 16px;
    background-color: white;
    border: 2px solid #e2e8f0;
    border-radius: 10px;
  }
  .card__title {
    margin: 0 0 6px 0;
    font-size: 18px;
  }
  .card__text {
    margin: 0;
    color: #475569;
  }
  .card--featured {
    border-color: #0ea5e9;
    background-color: #f0f9ff;
  }
</style>

<div class="card">
  <h3 class="card__title">Normal card</h3>
  <p class="card__text">A regular card.</p>
</div>
<div class="card card--featured">
  <h3 class="card__title">Featured card</h3>
  <p class="card__text">Same card, with a modifier.</p>
</div>
```

BEM keeps specificity low and flat, because everything is a single class. It also tells you where a class belongs just by reading it.

## 5. Keep Specificity Low

High specificity makes CSS hard to override. Follow these habits:

* Style with **classes**, not IDs or long selector chains.
* Avoid deep nesting such as `.page .sidebar ul li a span`.
* Do not use `!important`, except in rare utility classes.
* Do not qualify classes with tags (`div.card`) without a good reason.

```text
/* Hard to override */
#main .sidebar ul li a { color: red; }

/* Easy to manage */
.sidebar-link { color: red; }
```

---

## 6. DRY: Do Not Repeat Yourself

If you copy the same declarations into many rules, move them into one shared place.

```text
/* Repeated */
.btn-save   { padding: 10px 20px; border-radius: 8px; color: white; background: green; }
.btn-cancel { padding: 10px 20px; border-radius: 8px; color: white; background: gray; }
```

Better: one base class and small modifiers.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .btn {
    padding: 10px 20px;
    margin-right: 6px;
    font: inherit;
    color: white;
    background-color: var(--btn-bg, #475569);
    border: none;
    border-radius: 8px;
    cursor: pointer;
  }
  .btn--save {
    --btn-bg: #16a34a;
  }
  .btn--cancel {
    --btn-bg: #64748b;
  }
</style>

<button class="btn btn--save">Save</button>
<button class="btn btn--cancel">Cancel</button>
```

## 7. Utility Classes

**Utility classes** are small classes that do one job. They are handy for quick spacing and alignment.

```html
<style>
  :root {
    --space: 8px;
  }
  body {
    font-family: Arial, sans-serif;
  }
  .text-center { text-align: center; }
  .mt-1 { margin-top: var(--space); }
  .mt-2 { margin-top: calc(var(--space) * 2); }
  .p-2  { padding: calc(var(--space) * 2); }
  .flex { display: flex; }
  .gap-1 { gap: var(--space); }
  .bg-soft { background-color: #e0f2fe; }

  .chip {
    padding: 4px 12px;
    background-color: #0ea5e9;
    color: white;
    border-radius: 999px;
  }
</style>

<div class="bg-soft p-2 text-center">Centered with utilities</div>
<div class="flex gap-1 mt-2">
  <span class="chip">HTML</span>
  <span class="chip">CSS</span>
  <span class="chip">JS</span>
</div>
```

Do not go too far. If an element needs ten utility classes, a proper component class is cleaner.

## 8. Reusable Components

A **component** is a self-contained piece of design, such as a card, a badge or an alert. Build it so it does not depend on where it is placed.

* The component controls its own padding, color and layout.
* The **parent** controls the space around it (margin, grid position).

```html
<style>
  * {
    box-sizing: border-box;
  }
  body {
    margin: 0;
    padding: 14px;
    font-family: Arial, sans-serif;
    background-color: #f1f5f9;
  }
  .alert {
    --alert-color: #0ea5e9;
    padding: 12px 14px;
    color: #0f172a;
    background-color: #f8fafc;
    border-left: 5px solid var(--alert-color);
    border-radius: 8px;
  }
  .alert--success { --alert-color: #16a34a; }
  .alert--warning { --alert-color: #f59e0b; }
  .alert--error   { --alert-color: #dc2626; }

  /* The parent controls spacing between alerts */
  .stack {
    display: grid;
    gap: 10px;
    max-width: 380px;
  }
</style>

<div class="stack">
  <div class="alert">Info: a normal message</div>
  <div class="alert alert--success">Success: saved</div>
  <div class="alert alert--warning">Warning: check your input</div>
  <div class="alert alert--error">Error: something failed</div>
</div>
```

The alerts have no margin of their own. The `.stack` wrapper spaces them with `gap`. This makes the alert reusable in any layout.

---

## 9. Comments and Sections

Use comments to explain **why**, and to mark sections.

```text
/* ==========================================================================
   Components: Card
   ========================================================================== */

.card { ... }

/* The extra padding keeps the shadow from being clipped by overflow: hidden */
.card-wrap { padding: 8px; }
```

Do not write comments that only repeat the code, such as `/* makes text red */` above `color: red;`.

---

## 10. Cascade Layers (A Modern Tool)

`@layer` lets you decide the order of your style groups, so that a later group always wins, no matter how specific the selectors are.

```text
@layer reset, base, components, utilities;

@layer reset {
  * { margin: 0; box-sizing: border-box; }
}
@layer components {
  .btn { padding: 10px 20px; }
}
@layer utilities {
  .p-0 { padding: 0; }     /* always wins over .btn */
}
```

It is a great tool for bigger projects, and it is supported in all modern browsers.

## 11. Habits for Maintainable CSS

* Use CSS variables for colors, spacing and fonts.
* Use `rem` and relative units for scalable layouts.
* Prefer Flexbox and Grid over floats and hacks.
* Write mobile-first, with a few clear breakpoints.
* Delete CSS you no longer use.
* Keep one meaning per class.
* Use a linter or formatter (like Stylelint or Prettier) to keep the code tidy.
* Review your CSS after a project and clean it up.

## Real-World Example 🌍

A tidy mini stylesheet with variables, base, layout, components and utilities:

```html
<style>
  /* 1. Variables */
  :root {
    --color-primary: #0ea5e9;
    --color-text: #0f172a;
    --color-muted: #64748b;
    --color-surface: #ffffff;
    --color-bg: #f1f5f9;

    margin: 0;

    color: var(--color-text);
    background-color: var(--color-bg);
  }

  /* 3. Layout */
  .container {
    width: 100%;
    max-width: 640px;
    margin: 0 auto;
    padding: calc(var(--space) * 2);

  .grid {
    display: grid;

    .grid--2 {
      grid-template-columns: repeat(2, 1fr);

  /* 4. Components */
  .course-card {

```

## Common Mistakes

### Naming by Appearance

```text
.blue-button { }      /* what if the brand color changes? */
.btn-primary { }
```

### Overly Specific Selectors

```text
body #wrapper .main ul li a.link { }     /* nearly impossible to override */
.nav-link { }
```

### Using !important Everywhere

```text
.box { color: red !important; }     /* leads to an !important war */
/* Fix the specificity or order instead. */
```

### Copy-Pasting the Same Block

```text
/* Repeating 8 declarations in 6 classes: move them into one base class. */
```

### One Giant Unorganized File

```text
/* A 4,000-line file with no sections is hard to maintain. Split and label it. */
```

### Components That Control Their Own Outer Margin

```text
.card { margin: 40px; }      /* breaks in a grid or a different layout */
/* Let the parent control spacing with gap. */
```

---

## Key Points

* Organize your stylesheet from general to specific: variables, base, layout, components, utilities.
* Name classes by **purpose**, in lowercase kebab-case.
* **BEM** (`.block__element--modifier`) gives clear, flat, low-specificity names.
* Keep specificity low: use single classes, avoid IDs, deep nesting and `!important`.
* Follow **DRY**: share common styles in a base class, and use modifiers or variables for differences.
* **Utility classes** are small helpers for spacing and alignment. Use them with care.
* Build reusable components that let the parent control the outside space.
* Use comments for sections and for explaining why.
* `@layer` controls the order of style groups in large projects.
* Remove unused CSS and keep the code consistent.
