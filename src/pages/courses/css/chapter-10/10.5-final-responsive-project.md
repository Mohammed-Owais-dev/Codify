# Chapter 10: Practical CSS and Best Practices

## Section 5: Final Project: Responsive Webpage

Congratulations on reaching the last lesson! Now it is time to put everything you learned together. In this project you will build a complete, **responsive landing page** for a fictional online coding school called **"BrightCode"**. You will use variables, Flexbox, Grid, media queries, transitions, forms and accessibility habits from all ten chapters.

---

## 1. What We Will Build

The page has these sections:

| Section | Main skills used |
| ------- | ---------------- |
| **Header** with logo and navigation | Flexbox, sticky position, responsive menu |
| **Hero** with a title and buttons | Gradients, `clamp()`, spacing |
| **Features** grid | CSS Grid, `auto-fit`, cards, shadows |
| **Courses** cards | Flexbox, transitions, hover effects |
| **Newsletter form** | Forms, focus styles, labels |
| **Footer** | Grid, media queries |

The design is **mobile-first**, so we start with the phone layout and add changes for larger screens.

---

## 2. Planning the Project

Before writing code, plan these four things.

* **Content**: what the visitor needs to see and do.
* **Structure**: which HTML elements to use (`header`, `nav`, `main`, `section`, `footer`).
* **Design tokens**: colors, spacing, fonts and radius, stored as variables.
* **Breakpoints**: a small number, for example `600px` and `900px`.

## 8. Step 6: Course Cards

Cards that lift on hover, with the button pinned to the bottom using Flexbox.

```css
.courses {
  display: grid;
  gap: var(--space-2);
}

.course {
  display: flex;
  flex-direction: column;
  overflow: hidden;
  background-color: var(--color-surface);
  border-radius: var(--radius);
  box-shadow: var(--shadow);
  transition: transform 0.25s ease, box-shadow 0.25s ease;
}

.course__cover {
  aspect-ratio: 16 / 9;
  background-color: var(--color-primary);
}

.course__body {
  display: flex;
  flex: 1;
  flex-direction: column;
  gap: var(--space-1);
  padding: var(--space-2);
}

.course__body .btn {
  margin-top: auto;
  text-align: center;
}

@media (hover: hover) {
  .course:hover {
    transform: translateY(-6px);
    box-shadow: 0 14px 28px rgba(15, 23, 42, 0.2);
  }
}
```

The `margin-top: auto` on the button pushes it to the bottom of every card, so all buttons line up even when the text lengths differ.

## 10. Step 8: The Footer and Breakpoints

The footer stacks on phones, and becomes a three-column grid on larger screens. Then we add the media queries, written mobile-first with `min-width`.

```css

    grid-template-columns: repeat(2, 1fr);
  }
  .newsletter__form {
    grid-template-columns: 1fr auto;
    align-items: end;
  }

  .courses {
    grid-template-columns: repeat(3, 1fr);
  }
  .footer__grid {
    grid-template-columns: 2fr 1fr 1fr;
  }
}

@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

## 12. Testing Your Project

Go through this checklist before you call the project done:

* **Resize** the browser from very narrow (320px) to very wide. Nothing should overflow or look broken.
* **Keyboard test**: press Tab and check that every link and button shows a visible focus ring.
* **Zoom** to 200%. The text should stay readable, with no overlapping.
* **Contrast**: check that your text colors meet 4.5 : 1.
* **Touch**: make sure buttons are at least 44px tall.
* **Reduced motion**: turn on "reduce motion" in your system, and check that the page is calm.
* **Validate** your HTML and CSS with online validators.

## Common Mistakes

### Starting to Code Without a Plan

```css
/* Write down sections, colors, spacing and breakpoints first. */
```

### Designing for Desktop First

```css
.courses { grid-template-columns: repeat(3, 1fr); }     /* breaks on phones */
/* Start with one column, then add columns with min-width. */
```

### Hard-Coding the Same Value Everywhere

```text
color: #2563eb;  /* repeated 30 times */
color: var(--color-primary);
```

### Forgetting to Test on Small Screens and the Keyboard

```css
/* Always test narrow widths, Tab navigation and zoom. */
```

### Too Many Overrides

```css
.btn { color: red !important; }
/* Use modifier classes and low specificity instead. */
```

## Key Points

* A real project combines **variables, Flexbox, Grid, media queries, transitions and accessible forms**.
* Plan the content, structure, design tokens and breakpoints before writing CSS.
* Write mobile-first: base CSS for phones, `min-width` queries for larger screens.
* Use `auto-fit` with `minmax()` for grids that adapt by themselves.
* Build reusable components such as `.btn`, `.feature` and `.course`, with modifiers for variations.
* Use `margin-top: auto` in a flex column to pin elements, such as buttons, to the bottom of cards.
* Support keyboard users, touch users and users who prefer reduced motion.
* Test by resizing, zooming, tabbing and checking contrast.
* Keep growing: build more pages, read other people's CSS, and keep practicing.
