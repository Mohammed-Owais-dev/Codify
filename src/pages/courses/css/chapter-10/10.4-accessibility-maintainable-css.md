# Chapter 10: Practical CSS and Best Practices

## Section 4: Accessibility and Maintainable CSS

A good website works for **everyone**: people who use a keyboard instead of a mouse, people with low vision or color blindness, people who use screen readers, and people on slow devices. This is called **accessibility** (often written **a11y**). In this lesson you will learn the CSS habits that make your pages easy to use and easy to maintain.

---

## 1. Why Accessibility Matters

* Many people have a permanent, temporary or situational disability. Think of a broken arm, a bright sunny screen or a noisy room.
* Accessible pages are also easier for everyone else.
* Search engines like clean, well-built pages.
* In many places, accessibility is required by law.

Accessibility starts with good HTML, and CSS can either help it or break it.

---

## 2. Color Contrast

Text must stand out from its background. The **WCAG** guidelines use a contrast ratio:

| Text type | Minimum ratio (level AA) |
| --------- | ------------------------ |
| Normal text | **4.5 : 1** |
| Large text (24px, or 19px bold) | **3 : 1** |
| Icons and input borders | **3 : 1** |

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .box {
    max-width: 320px;
    margin-bottom: 8px;
    padding: 12px;
    border-radius: 8px;
  }
  .bad {
    color: #94a3b8;
    background-color: #f1f5f9;
  }
  .good {
    color: #334155;
    background-color: #f1f5f9;
  }
</style>

<div class="box bad">Poor contrast: hard to read</div>
<div class="box good">Good contrast: easy to read</div>
```

Use a free contrast checker in your browser's developer tools, or an online tool, to test your colors.

## 3. Do Not Use Color Alone

About 1 in 12 men are color blind. Never use color as the **only** way to give information.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .msg {
    max-width: 320px;
    margin-bottom: 8px;
    padding: 10px 12px;
    border-radius: 8px;
    border-left: 6px solid;
  }
  .msg::before {
    margin-right: 8px;
    font-weight: bold;
  }
  .ok {
    color: #14532d;
    background-color: #f0fdf4;
    border-color: #16a34a;
  }
  .ok::before { content: "\2713 Success:"; }
  .err {
    color: #7f1d1d;
    background-color: #fef2f2;
    border-color: #dc2626;
  }
  .err::before { content: "\2717 Error:"; }
</style>

<div class="msg ok">Your file was saved.</div>
<div class="msg err">Your file could not be saved.</div>
```

Each message uses color, an icon and a word. Any one of them is enough to understand it.

## 4. Focus Styles for Keyboard Users

Many people use only the **Tab** key to move around. They need a clear, visible focus style.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  a,
  button {
    margin-right: 10px;
    padding: 10px 16px;
    color: white;
    font: inherit;
    text-decoration: none;
    background-color: #1d4ed8;
    border: none;
    border-radius: 8px;
    cursor: pointer;
  }
  a:focus-visible,
  button:focus-visible {
    outline: 3px solid #f59e0b;
    outline-offset: 3px;
  }
</style>

<a href="#">Link</a>
<button>Button</button>
<p>Press Tab to move focus and see the orange ring.</p>
```

Rules for focus:

* **Never** use `outline: none` without a clear replacement.
* Make the focus ring at least 2px thick, with good contrast.
* The focus order should follow the visual order. Be careful with `order`, `position` and `grid` changes.

## 5. Readable Text

* Use a base font size of **16px** or more (`1rem`).
* Use **relative units** (`rem`, `em`) for text, so users can scale it.
* Use a comfortable `line-height` of about **1.5** for body text.
* Keep lines to about **45 to 75 characters** (`max-width: 65ch`).
* Avoid long blocks of centered or fully justified text.

```html
<style>
  body {
    margin: 0;
    padding: 16px;
    font-family: Arial, sans-serif;
    font-size: 1rem;
    line-height: 1.6;
    color: #1e293b;
  }
  .article {
    max-width: 65ch;
  }
  .article h2 {
    margin: 0 0 8px 0;
    line-height: 1.25;
  }
</style>

<div class="article">
  <h2>Easy to Read</h2>
  <p>This paragraph has a good line height and a limited width, so your eyes can follow each line to the next one without getting lost. Long lines of text are tiring to read.</p>
</div>
```

---

## 6. Do Not Block Zoom or Text Resizing

* Never disable zoom with `user-scalable=no` in the viewport tag.
* Do not set fixed heights on text containers. Use `min-height`, so larger text can still fit.
* Test your page at **200% zoom**. Nothing should be cut off or overlap.

```text
/* Fragile: large text spills out */
.card { height: 80px; }

/* Flexible: grows with the content */
.card { min-height: 80px; }
```

## 7. Hiding Content the Right Way

| Goal | Use |
| ---- | --- |
| Hide from everyone (sight and screen readers) | `display: none` or `visibility: hidden` |
| Hide visually, but keep for screen readers | A "visually hidden" class |
| Show but make it unclickable | `pointer-events: none` (with care) |

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .visually-hidden {
    position: absolute;
    width: 1px;
    height: 1px;
    margin: -1px;
    padding: 0;
    overflow: hidden;
    white-space: nowrap;
    border: 0;
    clip-path: inset(50%);
  }
  .icon-btn {
    width: 44px;
    height: 44px;
    font-size: 20px;
    color: white;
    background-color: #0f172a;
    border: none;
    border-radius: 50%;
    cursor: pointer;
  }
</style>

<button class="icon-btn">
  &#9776;
  <span class="visually-hidden">Open menu</span>
</button>
```

A sighted user sees the menu icon. A screen reader says "Open menu".

## 8. Reduce Motion and Respect User Settings

Remember lesson 9.5. Support these user preferences:

```text
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}

@media (prefers-color-scheme: dark) {
  :root {
    --bg: #0f172a;
    --text: #e2e8f0;
  }
}

@media (prefers-contrast: more) {
  :root {
    --border: #000000;
  }
}
```

## 9. Touch Targets and Spacing

* Buttons and links should be at least **44px by 44px** on touch screens.
* Leave space between targets, so users do not tap the wrong one.
* Make the whole row or card clickable when it makes sense, not just a small word.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .list {
    display: grid;
    gap: 6px;
    max-width: 300px;
    padding: 0;
    list-style: none;
  }
  .list a {
    display: block;
    min-height: 44px;
    padding: 12px 14px;
    color: #0f172a;
    text-decoration: none;
    background-color: #e0f2fe;
    border-radius: 8px;
  }
</style>

<ul class="list">
  <li><a href="#">Lesson one</a></li>
  <li><a href="#">Lesson two</a></li>
  <li><a href="#">Lesson three</a></li>
</ul>
```

## 10. CSS That Is Easy to Maintain

Accessibility and maintainability work together. Clean CSS is easier to test and fix.

* Store colors with good contrast in **variables**, so they are consistent.
* Use **semantic HTML** (`<nav>`, `<main>`, `<button>`, `<h1>` to `<h6>`) first, and style it second. Do not use a `<div>` as a button.
* Do not change the **meaning** of content with CSS, such as using `content:` for important text.
* Keep styles **simple and flat**. Avoid long selector chains.
* Document unusual code with short comments.
* Use browser **developer tools** to inspect, test and debug your CSS.
* Use tools like **Lighthouse** or a browser accessibility checker to find problems.
* Test with the keyboard only, and with zoom at 200%.

---

## 11. A Simple Accessibility Checklist

* Is there enough color contrast for text and controls?
* Is information given in more than one way, not only by color?
* Can I use every control with the keyboard, and see the focus?
* Can text be resized or zoomed without breaking the layout?
* Are tap targets big enough, with enough space?
* Are animations gentle, and do they respect `prefers-reduced-motion`?
* Do images have `alt` text, and form fields have labels?
* Does the page use real HTML elements for headings, lists, buttons and links?

## Real-World Example 🌍

An accessible notification card with good contrast, focus styles, a visually hidden label and reduced motion support:

```html
<style>
  :root {
    --text: #0f172a;
    --muted: #475569;
    --surface: #ffffff;
    --bg: #f1f5f9;
    --primary: #1d4ed8;
    --focus: #f59e0b;
  }
  * {
    box-sizing: border-box;
  }
  body {
    margin: 0;
    padding: 20px;
    font-family: Arial, sans-serif;
    font-size: 1rem;
    line-height: 1.6;
    color: var(--text);
    background-color: var(--bg);
  }
  .visually-hidden {
    position: absolute;
    width: 1px;
    height: 1px;
    margin: -1px;
    overflow: hidden;
    white-space: nowrap;
    clip-path: inset(50%);
  }
  .notice {
    display: flex;
    gap: 12px;
    align-items: flex-start;
    max-width: 460px;
    margin: 0 auto;
    padding: 16px;
    background-color: var(--surface);
    border: 2px solid var(--primary);
    border-radius: 12px;
    animation: slide-in 0.4s ease both;
  }
  .notice__icon {
    flex: 0 0 auto;
    width: 32px;
    height: 32px;
    display: flex;
    align-items: center;
    justify-content: center;
    color: white;
    font-weight: bold;
    background-color: var(--primary);
    border-radius: 50%;
  }
  .notice__body h2 {
    margin: 0 0 4px 0;
    font-size: 1.1rem;
  }
  .notice__body p {
    margin: 0 0 10px 0;
    color: var(--muted);
  }
  .notice__btn {
    min-height: 44px;
    padding: 10px 18px;
    color: white;
    font: inherit;
    font-weight: bold;
    background-color: var(--primary);
    border: none;
    border-radius: 8px;
    cursor: pointer;
  }
  .notice__btn:focus-visible {
    outline: 3px solid var(--focus);
    outline-offset: 3px;
  }
  @keyframes slide-in {
    from {
      opacity: 0;
      transform: translateY(-12px);
    }
    to {
      opacity: 1;
      transform: translateY(0);
    }
  }
  @media (prefers-reduced-motion: reduce) {
    .notice {
      animation: none;
    }
  }
</style>

<section class="notice" aria-labelledby="notice-title">
  <div class="notice__icon" aria-hidden="true">i</div>
  <div class="notice__body">
    <h2 id="notice-title">New lesson available</h2>
    <p>Chapter 10 is ready. Continue where you stopped.</p>
    <button class="notice__btn">
      Continue <span class="visually-hidden">to chapter 10</span>
    </button>
  </div>
</section>
```

## Common Mistakes

### Low-Contrast Text

```text
color: #aaa; background: #fff;     /* about 2.3 : 1, too low */
color: #475569; background: #fff;  /* much better */
```

### Removing Focus Styles

```text
*:focus { outline: none; }    /* keyboard users cannot navigate */
```

### Using Color Only

```text
.error { color: red; }        /* color-blind users may miss it */
/* Add an icon and text such as "Error:". */
```

### Fixed Heights and Tiny Fixed Text

```text
.card { height: 60px; font-size: 11px; }    /* breaks with zoom, hard to read */
.card { min-height: 60px; font-size: 1rem; }
```

### Making a div Act Like a Button

```text
<div class="btn">Click</div>      /* no keyboard support */
<button class="btn">Click</button>
```

### Hiding Labels with display: none

```text
.label { display: none; }                /* screen readers lose it */
.label { /* use the visually-hidden pattern */ }
```

---

## Key Points

* Accessibility means a site that works for **everyone**, and CSS plays a big role.
* Text needs a contrast ratio of **4.5 : 1** (normal) or **3 : 1** (large text).
* Never give information by **color alone**. Add text or icons.
* Always keep a clear `:focus-visible` style for keyboard users.
* Use `rem`, a 16px base size, `line-height` around 1.5 and `max-width` in `ch` for readable text.
* Never block zoom. Use `min-height` instead of fixed heights.
* Use a **visually hidden** class to give screen readers extra text.
* Respect `prefers-reduced-motion`, `prefers-color-scheme` and `prefers-contrast`.
* Make touch targets at least **44px**.
* Use semantic HTML, variables, low specificity and developer tools to keep CSS accessible and maintainable.
