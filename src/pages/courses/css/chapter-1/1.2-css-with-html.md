# Chapter 1: Introduction to CSS

## Section 2: How CSS Works with HTML

HTML creates the elements of a page, and CSS decides how those elements look. But how does the browser know which style belongs to which element? In this lesson you will learn how HTML and CSS connect, and what the browser does step by step to show a styled page.

---

## 1. How HTML and CSS Work Together

HTML and CSS are two separate languages that cooperate.

* HTML describes **what** is on the page: headings, paragraphs, images, buttons.
* CSS describes **how** those things should look: color, size, spacing, position.

The link between them is the **selector**. A selector in CSS points to an HTML element, and the rule styles it.

---

## 2. Selecting an Element and Styling It

The simplest selector is the name of an HTML tag. This rule selects every `<h1>` and every `<p>`.

```html
<style>
  h1 {
    color: #7c3aed;
    font-family: Arial, sans-serif;
  }
  p {
    color: #475569;
    font-family: Arial, sans-serif;
  }
</style>

<h1>Learning CSS</h1>
<p>CSS finds the tags and applies the styles.</p>
```

The word `h1` in CSS matches the `<h1>` tag in HTML. This is how the two languages are connected.

---

## 3. Using Classes and IDs

Sometimes you want to style only **some** elements, not all of them. For this, HTML gives elements a `class` or an `id`, and CSS selects them.

* In CSS, a class is written with a dot: `.note`
* In CSS, an id is written with a hash: `#main-title`

```html
<style>
  .note {
    background-color: #fef9c3;
    padding: 10px;
    font-family: Arial, sans-serif;
  }
  #main-title {
    color: #0369a1;
    font-family: Arial, sans-serif;
  }
</style>

<h1 id="main-title">Today's Lesson</h1>
<p class="note">This paragraph has the note style.</p>
<p>This paragraph has no special style.</p>
<p class="note">This one also uses the note class.</p>
```

Two paragraphs share the `note` class, so both get the yellow background. The paragraph without the class stays plain.

---

## 4. What the Browser Does Step by Step

When you open a webpage, the browser follows these steps:

```text
1. Download the HTML file.
2. Read the HTML and build the DOM (a tree of all elements).
3. Find the CSS (inside <style> or in linked .css files) and read it.
4. Match each CSS rule to the elements it selects.
5. Calculate the final style of every element.
6. Draw (render) the page on the screen.
```

The **DOM** (Document Object Model) is the browser's tree-like map of your page. CSS rules are applied to the elements in this tree.

---

## 5. Default Browser Styles

Even if you write no CSS, the browser adds its own styles. This built-in stylesheet is called the **user agent stylesheet**.

| Element | Default look |
| ------- | ------------ |
| `<h1>` | Large, bold text with space above and below |
| `<p>` | Space above and below |
| `<a>` | Blue text with an underline |
| `<ul>` | Bullets and left indentation |
| `<body>` | A small margin around the page |

Your own CSS is applied **after** these defaults, so your rules can change them.

```html
<style>
  a {
    color: #16a34a;
    text-decoration: none;
    font-family: Arial, sans-serif;
  }
</style>

<a href="#">Link with our style</a>
```

The link is no longer blue and underlined because our CSS replaced the default.

---

## 6. Parent and Child Elements

HTML elements are placed inside each other, like boxes inside boxes. An element inside another is called a **child**, and the outer one is the **parent**.

Some CSS properties, such as `color` and `font-family`, are passed **down** from parent to child. This is called **inheritance**.

```html
<style>
  .box {
    color: #be123c;
    font-family: Georgia, serif;
    font-size: 18px;
  }
</style>

<div class="box">
  <p>I am a child paragraph.</p>
  <p>I am another child.</p>
</div>
```

We styled only the `div`, but both paragraphs inside it received the color and font. You will study inheritance fully in Chapter 2.

---

## 7. Page-Wide Styles with body

The `<body>` element holds everything visible on the page. A style on `body` becomes the base style for the whole page.

```html
<style>
  body {
    font-family: Arial, sans-serif;
    background-color: #f1f5f9;
    color: #1e293b;
  }
</style>

<h2>Page Title</h2>
<p>All text on this page uses the body font and color.</p>
<ul>
  <li>Item one</li>
  <li>Item two</li>
</ul>
```

Setting the font and color once on `body` saves you from repeating them on every element.

---

## 8. One Stylesheet, Many Pages

A big website may have many HTML pages (home, about, contact). Instead of copying CSS into every page, you keep it in **one** `.css` file and link every page to it.

```text
index.html   ---\
about.html   ----->  style.css
contact.html ---/
```

When you edit `style.css`, all three pages change at once. You will learn how to link a stylesheet in the next lesson.

---

## 9. What to Change: HTML or CSS?

Beginners often get confused about where to make a change. Use this table.

| You want to... | Change |
| -------------- | ------ |
| Change the words, add a button, add an image | HTML |
| Change color, size, spacing, fonts | CSS |
| Move content to a new place on the page layout | CSS |
| Add a new section or menu item | HTML (and CSS to style it) |

---

## 10. Inspecting Styles in the Browser

Every browser has **Developer Tools** that show which CSS rules are applied to an element.

* Right-click any element and choose **Inspect**.
* The **Elements** tab shows the HTML.
* The **Styles** panel shows the CSS rules that affect the selected element.

You can even edit the CSS there to test ideas. These changes are temporary and disappear when you refresh the page.

## Real-World Example 🌍

A small blog post styled using tag, class and id selectors together:

```html
<style>
  body {
    font-family: Arial, sans-serif;
    background-color: #f8fafc;
    color: #334155;
    padding: 20px;
  }
  #post-title {
    color: #0f172a;
    margin-bottom: 4px;
  }
  .author {
    color: #64748b;
    font-size: 14px;
    margin-top: 0;
  }
  .highlight {
    background-color: #dbeafe;
    border-left: 4px solid #2563eb;
    padding: 10px;
  }
</style>

<h1 id="post-title">Why CSS Matters</h1>
<p class="author">Written by Ravi Kumar</p>
<p>CSS gives every website its own personality and makes it easy to read.</p>
<p class="highlight">Tip: Keep your HTML clean and let CSS handle the design.</p>
```

The HTML only describes the content. Each style comes from a CSS rule that selects the right element.

## Common Mistakes

### Class Name Does Not Match

```html
<style>
  .card { color: red; }
</style>

<p class="cards">This will not be red.</p>
```

The CSS says `card` but the HTML says `cards`. Names must match exactly.

### Forgetting the Dot or Hash

```text
note { color: red; }     /* looks for a <note> tag, not a class */
.note { color: red; }    /* correct: selects class="note" */
```

### Broken HTML Breaks the Styles

```text
<div class="box">
  <p>Missing closing tags can confuse the browser
</div>
```

Unclosed or wrongly placed tags can change the structure, and then your CSS may style the wrong elements.

### Expecting a Refresh to Keep DevTools Edits

```text
Changes made in the browser's Developer Tools are temporary.
Copy the final CSS into your own .css file and save it.
```

---

## Key Points

* HTML provides the **elements** and CSS provides the **styles**.
* A **selector** connects a CSS rule to HTML elements.
* Use a **class** (`.name`) or **id** (`#name`) to style specific elements.
* The browser builds the **DOM**, matches CSS rules, and then draws the page.
* Browsers add **default styles**, and your CSS can override them.
* Properties like `color` and `font-family` are **inherited** by child elements.
* One stylesheet can be shared by many pages.
* Developer Tools let you inspect and test styles, but the changes are not saved.
