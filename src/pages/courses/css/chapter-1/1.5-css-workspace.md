# Chapter 1: Introduction to CSS

## Section 5: Setting Up Your CSS Workspace

Before you write your first real stylesheet, you need a proper place to work. A good workspace saves time and prevents many beginner problems. In this lesson you will set up a code editor, create a project folder, link your files and learn to use the browser's Developer Tools.

---

## 1. What You Need

CSS needs very little to get started. You need only three things:

| Tool | Purpose | Examples |
| ---- | ------- | -------- |
| Code editor | To write HTML and CSS | VS Code, Sublime Text, Notepad++ |
| Web browser | To see the result | Chrome, Edge, Firefox, Safari |
| Project folder | To keep your files organized | `my-first-site` |

All of these are free, and you do not need an internet connection to practice.

---

## 2. Choosing a Code Editor

You can write CSS in any text editor, even Notepad, but a **code editor** helps you a lot. It adds colors to your code, suggests property names, fixes spacing and warns you about mistakes.

**Visual Studio Code (VS Code)** is the most popular choice for beginners and professionals. It is free and works on Windows, macOS and Linux.

Useful editor features for CSS:

* **Syntax highlighting:** different colors for selectors, properties and values.
* **Auto-complete:** type a few letters and the editor suggests the rest.
* **Color preview:** a small colored box appears next to color values.
* **Auto-indent:** your code stays neat as you type.

---

## 3. Recommended VS Code Extensions

Extensions add extra tools to VS Code. These are popular and helpful for CSS work.

| Extension | What it does |
| --------- | ------------ |
| Live Server | Opens your page and refreshes it automatically when you save |
| Prettier | Formats your code neatly |
| CSS Peek | Jumps from an HTML class to its CSS rule |
| Auto Rename Tag | Renames the closing tag when you rename the opening tag |

You can start without any extension. Add them later when you feel comfortable.

---

## 4. Creating a Project Folder

Create one folder for every project and keep all its files inside. A simple structure looks like this:

```text
my-first-site/
  index.html
  css/
    style.css
  images/
```

* `index.html` is the main page. The name `index` is special because servers open it first.
* `css/` holds your stylesheets.
* `images/` holds your pictures.

For tiny practice projects, you can also keep `style.css` in the same folder as `index.html`.

---

## 5. Creating index.html

Create a file named `index.html` and write a basic page that links to the stylesheet.

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My First CSS Page</title>
  <link rel="stylesheet" href="css/style.css">
</head>
<body>
  <h1>Hello, CSS!</h1>
  <p>My workspace is ready.</p>
</body>
</html>
```

The `<link>` line connects the page to `css/style.css`. The `viewport` meta tag helps your page display correctly on phones.

---

## 6. Creating style.css

Create a new file inside the `css` folder named `style.css` and add your first rules.

```css
body {
  font-family: Arial, sans-serif;
  background-color: #f1f5f9;
  color: #1e293b;
  padding: 20px;
}

h1 {
  color: #2563eb;
}
```

Save both files. The CSS file must be saved with the `.css` extension.

---

## 7. A Complete Starter Page

Here is the same idea in one piece, so you can see the result right away. This version keeps the CSS in a `<style>` tag so it runs in the preview.

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My First CSS Page</title>
  <style>
    body {
      font-family: Arial, sans-serif;
      background-color: #f1f5f9;
      color: #1e293b;
      padding: 20px;
    }
    h1 {
      color: #2563eb;
    }
  </style>
</head>
<body>
  <h1>Hello, CSS!</h1>
  <p>My workspace is ready.</p>
</body>
</html>
```

You can use this as a **starter template** for every new practice page.

---

## 8. Opening Your Page in the Browser

There are two easy ways to see your page:

1. **Open the file directly:** double-click `index.html`, or right-click it and choose "Open with" your browser.
2. **Use Live Server (VS Code):** right-click `index.html` and choose **Open with Live Server**. The browser opens and refreshes every time you save.

After changing your CSS, save the file and refresh the browser to see the new result.

---

## 9. Using Browser Developer Tools

**Developer Tools (DevTools)** are built into every modern browser. They show how the browser understands your HTML and CSS, and they are the best way to find problems.

How to open them:

* Press **F12**, or **Ctrl + Shift + I** (Windows/Linux), or **Cmd + Option + I** (Mac).
* Or right-click any element and choose **Inspect**.

| Panel | What it shows |
| ----- | ------------- |
| Elements | The HTML structure (the DOM) |
| Styles | The CSS rules applied to the selected element |
| Computed | The final values the browser calculated |
| Device toolbar | Preview your page at phone and tablet sizes |

In the Styles panel you can click a value, change it and see the result instantly. This is a great way to experiment. Remember that these edits are **temporary**. Copy anything you like into your `.css` file and save it.

---

## 10. Refreshing When Changes Do Not Show

Sometimes you change your CSS but the browser still shows the old design. Check these things in order:

* Did you **save** the file? (Look for a dot or circle on the file tab in your editor.)
* Is the `<link>` path correct?
* Try a **hard refresh**: **Ctrl + F5** or **Ctrl + Shift + R** (Cmd + Shift + R on Mac). This ignores the stored copy of the old CSS file.
* Open DevTools and look for a red error saying the CSS file could not be found.

---

## 11. Good Workspace Habits

* Use **lowercase** file names with **hyphens**, such as `about-us.html`. Avoid spaces.
* Keep CSS, images and other files in separate folders.
* Use the same indentation (2 or 4 spaces) in every file.
* Add short comments to explain sections of your CSS.
* Save often and test small changes one at a time.
* Use DevTools whenever something does not look right.

## Real-World Example 🌍

Professional developers set up the same kind of workspace for every website. A realistic small project looks like this:

```text
portfolio/
  index.html
  about.html
  css/
    style.css
  images/
    profile.jpg
    logo.png
```

And the top of every page follows the same pattern:

```html
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Ravi Kumar | Portfolio</title>
  <link rel="stylesheet" href="css/style.css">
</head>
```

With a clean workspace, adding a new page takes a minute, and the design stays the same on every page because they all share `style.css`.

## Common Mistakes

### Hidden File Extensions

```text
style.css.txt     (wrong: Windows hid the real .txt extension)
style.css         (correct)
```

Turn on "File name extensions" in your file explorer so you can see the full file names.

### Spaces and Capital Letters in File Names

```text
My Style.CSS      (can cause problems on web servers)
my-style.css      (safe and clean)
```

### Forgetting to Save

```text
Your editor shows unsaved changes with a dot on the tab.
The browser can only show what has been saved.
```

### Editing in DevTools and Expecting It to Stay

```text
DevTools changes are lost when you refresh.
Always make the final change in your own .css file.
```

### Wrong Link Path

```text
Folder:  css/style.css
Link:    <link rel="stylesheet" href="style.css">    (wrong)
Correct: <link rel="stylesheet" href="css/style.css">
```

---

## Key Points

* You need a **code editor**, a **browser** and a **project folder** to start with CSS.
* **VS Code** is a popular free editor, and **Live Server** refreshes your page automatically.
* Keep files organized: `index.html`, a `css` folder and an `images` folder.
* Link your stylesheet with `<link rel="stylesheet" href="css/style.css">` inside `<head>`.
* Add the `viewport` meta tag so pages work well on mobile screens.
* **DevTools** (F12) show the HTML, CSS rules and the final computed styles.
* DevTools edits are temporary, so save real changes in your own files.
* If changes do not appear, save the file, check the path and try a hard refresh.
* Use lowercase file names with hyphens and avoid spaces.
