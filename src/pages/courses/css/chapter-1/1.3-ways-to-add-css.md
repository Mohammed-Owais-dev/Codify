# Chapter 1: Introduction to CSS

## Section 3: Ways to Add CSS

You know that CSS styles HTML elements, but where do you actually write the CSS? There are three ways to add CSS to a webpage: **inline**, **internal** and **external**. In this lesson you will learn all three, compare them and see which one to use in real projects.

---

## 1. The Three Ways at a Glance

| Method | Where the CSS is written | Affects |
| ------ | ------------------------ | ------- |
| Inline CSS | Inside the `style` attribute of one tag | One element |
| Internal CSS | Inside a `<style>` tag in the same HTML file | One page |
| External CSS | In a separate `.css` file linked to the page | Many pages |

---

## 2. Inline CSS

Inline CSS is written directly inside an HTML tag using the `style` attribute.

```html
<h1 style="color: #dc2626; font-family: Arial, sans-serif;">Inline Heading</h1>
<p style="color: #475569; font-size: 20px;">This paragraph is styled inline.</p>
<p>This paragraph has no style.</p>
```

Each declaration ends with a semicolon, and several declarations are separated inside the quotes. Only the element that has the `style` attribute is changed.

Inline CSS is good for a quick test, but it mixes design with content and is hard to maintain.

---

## 3. Internal CSS

Internal CSS is written inside a `<style>` tag. The tag is usually placed inside the `<head>` section of the page.

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Internal CSS</title>
  <style>
    body {
      font-family: Arial, sans-serif;
      background-color: #f0f9ff;
    }
    h1 {
      color: #0369a1;
    }
    p {
      color: #334155;
      font-size: 18px;
    }
  </style>
</head>
<body>
  <h1>Internal CSS</h1>
  <p>All styles live in the style tag of this page.</p>
  <p>They affect every matching element on this page.</p>
</body>
</html>
```

Internal CSS styles the whole page from one place. But the styles cannot be reused by other pages, so you would copy them again and again.

---

## 4. External CSS

External CSS is written in a separate file with the `.css` extension. The HTML page connects to it using a `<link>` tag inside `<head>`.

This is the HTML file, `index.html`:

```text
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>External CSS</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h1>External CSS</h1>
  <p>My styles come from style.css.</p>
</body>
</html>
```

This is the CSS file, `style.css`:

```text
body {
  font-family: Arial, sans-serif;
  background-color: #f0f9ff;
}

h1 {
  color: #0369a1;
}

p {
  color: #334155;
}
```

The CSS file contains **only CSS**. Do not write any HTML tags or a `<style>` tag inside it.

---

## 5. Understanding the link Tag

```text
<link rel="stylesheet" href="style.css">
```

| Part | Meaning |
| ---- | ------- |
| `link` | A tag that connects an outside file to the page |
| `rel="stylesheet"` | Tells the browser the file is a stylesheet |
| `href="style.css"` | The path (location) of the CSS file |

The `<link>` tag is a **void element**, so it has no closing tag.

---

## 6. Writing the Correct File Path

The `href` must lead to the real location of your CSS file.

| Folder layout | Correct href |
| ------------- | ------------ |
| `style.css` in the same folder as the page | `href="style.css"` |
| `style.css` inside a `css` folder | `href="css/style.css"` |
| `style.css` one folder above the page | `href="../style.css"` |
| A file on another website | `href="https://example.com/style.css"` |

```text
project/
  index.html
  css/
    style.css
```

For this project, the link in `index.html` must be `href="css/style.css"`.

---

## 7. Comparing the Three Methods

| | Inline | Internal | External |
| - | ------ | -------- | -------- |
| Reusable on many pages | No | No | **Yes** |
| Keeps HTML clean | No | Partly | **Yes** |
| Easy to maintain | No | Medium | **Yes** |
| Browser can store (cache) it | No | No | **Yes** |
| Best for | Quick tests | Small single pages | Real websites |

For real projects, **external CSS is the best choice**.

---

## 8. What If Styles Conflict?

You can use more than one method at the same time. If two rules style the same property of the same element, one must win. A style written **inline** is stronger than a style in `<style>` or in a linked file.

```html
<style>
  p {
    color: blue;
  }
</style>

<p>This paragraph is blue from the style tag.</p>
<p style="color: green;">This paragraph is green because inline CSS wins.</p>
```

Chapter 2 explains these priority rules in detail under the cascade and specificity.

---

## 9. Order Matters

When two rules have the same strength, the **last one** wins. This also applies to many stylesheets.

```html
<style>
  h2 {
    color: red;
  }
  h2 {
    color: purple;
  }
</style>

<h2>This heading is purple.</h2>
```

Both rules select `h2`, but the second one comes later, so purple wins. The same idea applies to two linked files: the file linked later can override the earlier one.

```text
<link rel="stylesheet" href="base.css">
<link rel="stylesheet" href="theme.css">   <!-- can override base.css -->
```

---

## 10. The @import Rule

CSS can also load another stylesheet using `@import`. It must be written at the very top of the CSS.

```text
@import url("fonts.css");

body {
  font-family: Arial, sans-serif;
}
```

This works, but it makes the page load slower because the browser must wait for one file before it finds the next. Using several `<link>` tags is usually better.

---

## Real-World Example 🌍

A normal small website uses external CSS. Here is the usual project structure:

```text
my-website/
  index.html
  about.html
  contact.html
  css/
    style.css
  images/
    logo.png
```

Every page contains the same line in its `<head>`:

```text
<link rel="stylesheet" href="css/style.css">
```

Now the whole website shares one design. If the client asks for a new brand color, you edit **one line** in `style.css` and all three pages are updated.

## Common Mistakes

### Wrong File Path

```text
<link rel="stylesheet" href="style.css">     <!-- file is really in css/style.css -->
```

If the path is wrong, the browser cannot find the file and the page shows no styles. Check the folder names and spelling.

### Forgetting rel="stylesheet"

```text
<link href="style.css">      <!-- wrong: the browser does not know the file type -->
```

### Writing HTML Inside the CSS File

```text
<style>
  body { color: red; }
</style>
```

A `.css` file must contain only CSS rules. The `<style>` tags belong in an HTML file.

### Saving the File with the Wrong Name

```text
style.css.txt     (wrong: it is a text file)
style.css         (correct)
```

On Windows, file extensions can be hidden, so a file may secretly be named `style.css.txt`.

### Forgetting the Semicolon in Inline CSS

```text
<p style="color: red font-size: 20px">Neither style works</p>
<p style="color: red; font-size: 20px">Both work</p>
```

---

## Key Points

* There are three ways to add CSS: **inline**, **internal** and **external**.
* **Inline** CSS uses the `style` attribute and affects one element.
* **Internal** CSS uses a `<style>` tag and affects one page.
* **External** CSS uses a `.css` file linked with `<link rel="stylesheet" href="...">`.
* Use **external CSS** for real websites so styles can be reused and maintained easily.
* The `href` path must match the real file location.
* Inline styles are stronger than internal and external styles.
* When rules have the same strength, the **last one** wins.
