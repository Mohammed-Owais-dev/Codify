# Chapter 1: Introduction to CSS

## Section 4: CSS Syntax, Rules and Comments

Every language has grammar, and CSS is no different. If you write a rule in the wrong way, the browser quietly ignores it. In this lesson you will learn how a CSS rule is built, how to write properties and values correctly, and how to add comments to explain your code.

---

## 1. The Structure of a CSS Rule

A CSS **rule** (also called a **rule set**) tells the browser which elements to style and how to style them.

```text
selector {
  property: value;
  property: value;
}
```

A real example:

```text
h1 {
  color: blue;
  font-size: 32px;
}
```

| Part | Example | Meaning |
| ---- | ------- | ------- |
| Selector | `h1` | Chooses which elements to style |
| Declaration block | `{ ... }` | The curly braces that hold all the styles |
| Declaration | `color: blue;` | One complete style instruction |
| Property | `color` | What you want to change |
| Value | `blue` | The setting you want to give it |

---

## 2. Property and Value

A declaration is a **property** and a **value** separated by a colon `:` and ended with a semicolon `;`.

```html
<style>
  p {
    color: #0f766e;
    font-size: 22px;
    font-family: Arial, sans-serif;
  }
</style>

<p>This text is teal, 22 pixels tall and uses Arial.</p>
```

Here `color`, `font-size` and `font-family` are **properties**. The things after the colon are their **values**.

---

## 3. Several Declarations in One Rule

You can put as many declarations as you need inside one block. Each one ends with a semicolon.

```html
<style>
  .banner {
    background-color: #1e293b;
    color: white;
    padding: 16px;
    text-align: center;
    font-family: Arial, sans-serif;
    border-radius: 8px;
  }
</style>

<div class="banner">Welcome to Codify</div>
```

One selector, six declarations, and the `div` becomes a styled banner.

---

## 4. Several Rules in One Stylesheet

A stylesheet is simply a list of rules. Each rule has its own selector and its own block.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  h1 {
    color: #9333ea;
  }
  p {
    color: #475569;
  }
  a {
    color: #ea580c;
  }
</style>

<h1>Rules List</h1>
<p>Each rule styles a different element.</p>
<a href="#">A styled link</a>
```

---

## 5. Writing Neat CSS

CSS ignores extra spaces and new lines, so both styles below work the same.

```text
/* Compact (hard to read) */
p{color:red;font-size:18px;}

/* Neat (easy to read) */
p {
  color: red;
  font-size: 18px;
}
```

Good habits for clean CSS:

* Write **one declaration per line**.
* Indent the declarations by **2 or 4 spaces**.
* Put one space after the colon and before the opening brace.
* Always end each declaration with a semicolon, even the last one.
* Write properties in **lowercase**, such as `font-size`.

---

## 6. Types of Values

Different properties accept different kinds of values.

| Value type | Examples | Used in |
| ---------- | -------- | ------- |
| Keyword | `red`, `center`, `bold`, `none` | `color`, `text-align`, `font-weight` |
| Number with unit | `16px`, `2em`, `50%` | `font-size`, `width`, `margin` |
| Color code | `#ff0000`, `rgb(255, 0, 0)` | `color`, `background-color` |
| Text in quotes | `"Open Sans"` | `font-family` with spaces in the name |
| URL | `url("photo.jpg")` | `background-image` |

```html
<style>
  .demo {
    color: white;
    background-color: #7c3aed;
    width: 60%;
    padding: 12px;
    font-family: "Trebuchet MS", sans-serif;
    text-align: center;
  }
</style>

<div class="demo">A rule with different kinds of values</div>
```

---

## 7. Units Need to Be Written Correctly

When a value is a number, it needs a **unit** with no space between them.

```html
<style>
  .good {
    width: 200px;
    background-color: #bbf7d0;
    padding: 10px;
    font-family: Arial, sans-serif;
  }
  .bad {
    width: 200 px;
    background-color: #fecaca;
    padding: 10px;
    font-family: Arial, sans-serif;
  }
</style>

<p class="good">Correct: 200px</p>
<p class="bad">Wrong: 200 px, so the width is ignored</p>
```

The only number that can be written without a unit is **0**, as in `margin: 0;`.

---

## 8. CSS Comments

A **comment** is a note for humans. The browser ignores it completely. CSS comments start with `/*` and end with `*/`.

```html
<style>
  /* This is a single-line comment */
  h1 {
    color: #2563eb; /* a comment after a declaration */
  }

  /*
    This is a multi-line comment.
    It can cover many lines.
  */
  p {
    color: #475569;
  }
</style>

<h1>Comments are invisible</h1>
<p>The comments in the style tag do not appear on the page.</p>
```

Use comments to explain **why** you wrote something, to divide a long file into sections, and to leave reminders.

---

## 9. Commenting Out Code

You can also use a comment to **turn off** a declaration without deleting it. This is a handy way to test your design.

```html
<style>
  .box {
    width: 220px;
    padding: 20px;
    background-color: #e0f2fe;
    /* border: 4px solid #0284c7; */
    font-family: Arial, sans-serif;
  }
</style>

<div class="box">The border line is commented out, so no border appears.</div>
```

Remove the comment marks `/* */` around the border line and the border will return.

---

## 10. Shorthand Properties

Some properties can set many values at once. These are called **shorthand** properties.

```text
/* Longhand: four separate lines */
margin-top: 10px;
margin-right: 20px;
margin-bottom: 10px;
margin-left: 20px;

/* Shorthand: one line */
margin: 10px 20px;
```

Common shorthand properties are `margin`, `padding`, `border`, `background` and `font`. You will learn each of them in the coming chapters.

---

## 11. What Happens When There Is a Mistake?

CSS is **forgiving**. If the browser finds a wrong declaration, it skips that one and continues with the rest. The page does not crash.

```html
<style>
  p {
    colour: red;
    font-size: 20px;
    font-family: Arial, sans-serif;
  }
</style>

<p>The color is ignored, but the size and font still work.</p>
```

`colour` is not a real CSS property (CSS uses American spelling, `color`), so the browser ignores it. The other two declarations are still applied.

This is useful, but it also means mistakes are **silent**. If a style does not work, check your spelling first.

---

## 12. Case and Naming Rules

* Property names and keywords are **not** case-sensitive (`COLOR` works), but always use lowercase.
* **Class and id names are case-sensitive.** `.Card` and `.card` are different.
* Names for classes and ids should use letters, numbers, hyphens and underscores, and should not start with a number.
* A popular naming style is **kebab-case**, such as `main-title` or `nav-link`.

## Real-World Example 🌍

A small, well-organized stylesheet with comments, written the way professionals do it:

```html
<style>
  /* ===== Base styles ===== */
  body {
    font-family: Arial, sans-serif;
    background-color: #f1f5f9;
    color: #1e293b;
    padding: 20px;
  }

  /* ===== Notice box ===== */
  .notice {
    background-color: #fff7ed;
    border-left: 5px solid #f97316; /* orange accent */
    padding: 14px 18px;
    border-radius: 6px;
  }

  .notice h3 {
    margin: 0 0 6px;
    color: #c2410c;
  }

  .notice p {
    margin: 0;
  }

  /* ===== Button ===== */
  .btn {
    display: inline-block;
    margin-top: 14px;
    padding: 10px 22px;
    background-color: #f97316;
    color: white;
    border: none;
    border-radius: 6px;
  }
</style>

<div class="notice">
  <h3>Exam Reminder</h3>
  <p>The CSS quiz opens on Monday at 10 AM.</p>
</div>
<button class="btn">Set Reminder</button>
```

Section comments make a long stylesheet easy to scan, and each rule uses clear, readable formatting.

## Common Mistakes

### Missing Semicolon

```text
p {
  color: red
  font-size: 20px;
}
```

The browser reads `red font-size: 20px` as one broken value, so **both** declarations are ignored. Always end with a semicolon.

### Using = Instead of a Colon

```text
p {
  color = red;     /* wrong */
  color: red;      /* correct */
}
```

### Wrong Comment Style

```text
// This is not a CSS comment
<!-- This is an HTML comment, not a CSS comment -->
/* This is the correct CSS comment */
```

A line starting with `//` is not ignored by CSS and can break the rule that follows it.

### Missing Closing Brace

```text
h1 {
  color: blue;

p {
  color: red;
}
```

Without the closing `}` for `h1`, the browser cannot read the next rule properly.

### Putting a Space Between the Number and the Unit

```text
font-size: 20 px;    /* wrong */
font-size: 20px;     /* correct */
```

---

## Key Points

* A CSS rule has a **selector** and a **declaration block** in curly braces `{ }`.
* A declaration is `property: value;`, with a colon in the middle and a semicolon at the end.
* One rule can contain many declarations, and a stylesheet is a list of rules.
* Numbers need a unit with no space, such as `16px`. Only `0` can be written without a unit.
* Comments are written as `/* comment */` and are ignored by the browser.
* Use comments to explain code, organize sections, or temporarily turn off a declaration.
* Shorthand properties like `margin: 10px 20px;` set several values at once.
* CSS ignores invalid declarations silently, so check spelling when something does not work.
* Class and id names are case-sensitive, so use lowercase and kebab-case.
