# Chapter 8: Responsive Web Design

## Section 4: Mobile-First Design

**Mobile-first** is a way of writing CSS. You start with the design for the **smallest screen**, and then add improvements for bigger screens. Most websites today are visited on phones, so this approach makes a lot of sense. In this lesson you will learn how mobile-first works and why it is a good habit.

---

## 1. Two Ways to Build Responsive CSS

| Approach | Start with | Use media queries to... |
| -------- | ---------- | ----------------------- |
| **Desktop-first** | The big design | Remove or simplify things for smaller screens (`max-width`) |
| **Mobile-first** | The small design | Add or enhance things for bigger screens (`min-width`) |

Mobile-first uses `min-width` queries. Desktop-first uses `max-width` queries.

---

## 2. Why Mobile-First?

* **Simpler base CSS.** A phone layout is usually one column. The default block layout already does this, so you write less code.
* **Better performance.** Phones load only the simple rules. The extra rules only apply on larger screens.
* **Better focus.** You must decide what is truly important when space is small.
* **Progressive enhancement.** Every device gets a working page, and bigger devices get more.
* **Matches real use.** Many visitors are on mobile devices.

---

## 3. The Mobile-First Pattern

The pattern has two steps.

```css
/* Step 1: base styles, for all screens (the phone design) */
.layout {
  display: grid;
  grid-template-columns: 1fr;
  gap: 12px;
}

/* Step 2: add changes as the screen gets wider */
@media (min-width: 600px) {
  .layout {
    grid-template-columns: repeat(2, 1fr);
  }
}

@media (min-width: 1000px) {
  .layout {
    grid-template-columns: repeat(3, 1fr);
  }
}
```

Each media query **builds on** the one before it. Larger screens match all the smaller `min-width` queries too.

## 4. Mobile-First vs Desktop-First: A Comparison

```html
<style>
  * {
    box-sizing: border-box;
  }
  body {
    font-family: Arial, sans-serif;
  }
  /* Mobile-first: base is simple, add for bigger screens */
  .mf {
    display: grid;
    gap: 8px;
    margin-bottom: 14px;
  }
  .mf div {
    padding: 14px;
    text-align: center;
    color: white;
    background-color: #0ea5e9;
    border-radius: 8px;
  }
  @media (min-width: 500px) {
    .mf {
      grid-template-columns: repeat(3, 1fr);
    }
  }
</style>

<div class="mf">
  <div>One</div>
  <div>Two</div>
  <div>Three</div>
</div>
<p>On a narrow screen the boxes stack. At 500px and wider they sit in three columns.</p>
```

Notice that the base CSS has no media query at all. The phone design is simply the normal CSS.

## 5. Building a Component Mobile-First

Let us build a card. First we design it for a phone, and then we improve it.

```html
<style>
  * {
    box-sizing: border-box;
  }
  body {
    margin: 0;
    padding: 12px;
    font-family: Arial, sans-serif;
    background-color: #f1f5f9;
  }
  /* Base (mobile) */
  .profile {
    padding: 16px;
    background-color: white;
    border-radius: 12px;
    box-shadow: 0 1px 5px rgba(0, 0, 0, 0.1);
    text-align: center;
  }
  .avatar {
    width: 72px;
    height: 72px;
    margin: 0 auto 10px;
    border-radius: 50%;
    background-color: #0ea5e9;
  }
  .profile h3 {
    margin: 0 0 4px 0;
  }
  .profile p {
    margin: 0;
    color: #475569;
  }

  /* Wider screens */
  @media (min-width: 520px) {
    .profile {
      display: flex;
      align-items: center;
      gap: 16px;
      text-align: left;
    }
    .avatar {
      margin: 0;
      flex-shrink: 0;
    }
  }
</style>

<div class="profile">
  <div class="avatar"></div>
  <div>
    <h3>Asha Kumar</h3>
    <p>CSS learner and future web developer</p>
  </div>
</div>
```

On phones, the avatar is above the text and centered. On wider screens, it moves to the left of the text.

## 6. Progressive Enhancement

Mobile-first fits the idea of **progressive enhancement**: begin with a basic version that works everywhere, then add extras for devices that can handle them.

```html
<style>
  body {
    font-family: Arial, sans-serif;
  }
  .btn {
    display: inline-block;
    padding: 12px 22px;
    color: white;
    background-color: #1d4ed8;
    border-radius: 8px;
    text-decoration: none;
    transition: background-color 0.2s;
  }

  /* Only add hover effects on devices that can really hover */
  @media (hover: hover) {
    .btn:hover {
      background-color: #1e3a8a;
    }
  }
</style>

<a class="btn" href="#">Enroll now</a>
```

## 7. Mobile-First Typography and Spacing

Start with smaller values, and then increase them on larger screens.

```html
<style>
  body {
    margin: 0;
    padding: 12px;
    font-family: Arial, sans-serif;
  }
  .article {
    max-width: 640px;
    margin: 0 auto;
  }
  .article h1 {
    margin: 0 0 8px 0;
    font-size: 1.6rem;
  }
  .article p {
    font-size: 1rem;
    line-height: 1.6;
  }

  @media (min-width: 700px) {
    body {
      padding: 32px;
    }
    .article h1 {
      font-size: 2.4rem;
    }
    .article p {
      font-size: 1.15rem;
    }
  }
</style>

<div class="article">
  <h1>Mobile-First Article</h1>
  <p>The heading and the page padding are small on phones, and larger when the screen is 700px or wider. Resize the preview to see it.</p>
</div>
```

## 8. A Mobile-First Workflow

Follow these steps for any new page:

* **Step 1**: Plan the content. What is the most important thing?
* **Step 2**: Write the HTML in a good order. On mobile, the HTML order is the visual order.
* **Step 3**: Style the phone layout with no media query.
* **Step 4**: Widen the browser until the layout looks stretched or empty.
* **Step 5**: Add a `min-width` breakpoint at that point and improve the layout.
* **Step 6**: Repeat for larger screens.

## Common Mistakes

### Using max-width Queries in a Mobile-First Project

```css
@media (max-width: 600px) { }    /* desktop-first style */
@media (min-width: 600px) { }    /* mobile-first style */
```

### Writing the Desktop Layout as the Base

```css
.layout { display: grid; grid-template-columns: repeat(3, 1fr); }   /* base is for desktop */
/* Start with one column, then add columns inside a min-width query. */
```

### Hiding Content on Mobile Instead of Planning It

```css
.sidebar { display: none; }    /* phone users lose the content */
```

### Too Many Breakpoints

```css
/* Two or three breakpoints are enough for most pages. */
```

### Hover-Only Features

```css
.menu:hover .sub { display: block; }   /* touch users cannot hover */
```

---

## Key Points

* **Mobile-first** means writing the small-screen CSS first, and adding bigger-screen changes with `min-width` media queries.
* The base CSS (without any media query) is the phone design.
* Each larger breakpoint builds on the smaller ones.
* Mobile-first gives simpler code, better performance and a clearer focus on what matters.
* It supports **progressive enhancement**: a working page for everyone, and extras for capable devices.
* Use `@media (hover: hover)` for hover effects, so touch devices are not affected.
* Add a breakpoint where the layout starts to look stretched, not for specific devices.
