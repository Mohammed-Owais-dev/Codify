# Chapter 2: JavaScript Fundamentals

## Section 1: JavaScript Syntax and Comments

Every language has rules for how code must be written. These rules are called **syntax**. In this section you will learn the basic syntax rules of JavaScript and how to write comments that make your code easier to understand.

---

## 1. Statements

A JavaScript program is a list of **statements**. Each statement is an instruction for the computer, and it usually ends with a semicolon `;`.

```javascript
let a = 5;
let b = 10;
console.log(a + b);
```

```output
15
```

JavaScript runs statements from top to bottom, one after another.

---

## 2. Semicolons

Semicolons end statements. Several statements can be written on one line if each one has its own semicolon.

```javascript
let x = 1; let y = 2;
console.log(x, y);
```

```output
1 2
```

> 💡 JavaScript can insert missing semicolons automatically (called **ASI**, Automatic Semicolon Insertion), so code often works without them. Beginners should still write semicolons, because ASI can cause surprising bugs.

### An ASI Surprise

```javascript
function getValue() {
  return
  42;
}

console.log(getValue());
```

```output
undefined
```

JavaScript inserts a semicolon right after `return`, so the function returns nothing. Always start the returned value on the same line as `return`.

---

## 3. Whitespace and Indentation

JavaScript ignores extra spaces and blank lines. These two programs are equivalent:

```javascript
let total=10+5;console.log(total);
```

```output
15
```

```javascript
let total = 10 + 5;
console.log(total);
```

```output
15
```

Use spaces and indentation (2 or 4 spaces) to keep code readable. Readable code is easier to fix.

---

## 4. Case Sensitivity

JavaScript treats uppercase and lowercase letters as different.

```javascript
let score = 90;
let Score = 50;

console.log(score);
console.log(Score);
```

```output
90
50
```

`score` and `Score` are two separate variables.

---

## 5. Code Blocks

Curly braces `{ }` group statements into a **block**. Blocks are used with conditions, loops and functions.

```javascript
if (true) {
  console.log("Inside the block");
  console.log("Still inside");
}
```

```output
Inside the block
Still inside
```

---

## 6. Identifiers and Naming Rules

An **identifier** is the name of a variable, function or other item. The rules are:

* Names can contain letters, digits, underscore `_` and dollar sign `$`.
* A name **cannot start with a digit**.
* A name **cannot contain spaces or hyphens**.
* A name **cannot be a reserved keyword** such as `let`, `if` or `class`.

| Name | Valid? | Reason |
| --- | --- | --- |
| `userName` | Yes | Letters only |
| `_count` | Yes | Can start with `_` |
| `$price` | Yes | Can start with `$` |
| `total2` | Yes | Digits allowed after the first character |
| `2total` | No | Starts with a digit |
| `user-name` | No | Hyphen is not allowed |
| `let` | No | Reserved keyword |

---

## 7. Naming Conventions

Following conventions makes your code look professional.

| Style | Used for | Example |
| --- | --- | --- |
| `camelCase` | Variables and functions | `firstName`, `getTotal` |
| `PascalCase` | Classes | `StudentRecord` |
| `UPPER_SNAKE_CASE` | Fixed constants | `MAX_SCORE` |

Choose meaningful names. `totalPrice` is better than `tp`.

---

## 8. Reserved Keywords

Some words have special meaning in JavaScript and cannot be used as names.

```text
break  case  class  const  continue  default  do  else  export
for  function  if  import  let  new  return  switch  this
try  catch  throw  typeof  var  while  true  false  null
```

## 9. Comments

Comments are notes for humans. JavaScript ignores them.

### Single-Line Comments

```javascript
// This line prints a greeting
console.log("Hello"); // comment after code
```

```output
Hello
```

### Multi-Line Comments

```javascript
/*
  This comment spans
  more than one line.
*/
console.log("Done");
```

```output
Done
```

### Commenting Out Code

You can disable a line of code temporarily by turning it into a comment.

```javascript
console.log("Step 1");
// console.log("Step 2");
console.log("Step 3");
```

```output
Step 1
Step 3
```

### Documentation Comments

Special comments that start with `/**` describe functions. Editors such as VS Code show them as hints.

```javascript
/**
 * Adds two numbers.
 * @param {number} a - first number
 * @param {number} b - second number
 * @returns {number} the sum
 */
function add(a, b) {
  return a + b;
}

console.log(add(2, 3));
```

```output
5
```

> 💡 Write comments that explain **why** the code does something, not just what it does.

---

## 10. Strict Mode

Adding `"use strict";` at the top of a script makes JavaScript stricter and helps catch mistakes, such as using a variable that was never declared.

```javascript
"use strict";

x = 5;
console.log(x);
```

```output
ReferenceError: x is not defined
```

Without strict mode, JavaScript would silently create a global variable `x`. Code inside modules and classes is strict automatically.

## Real-World Example

A well-commented program that calculates a bill with tax:

```javascript
// Calculate the final bill with GST
const price = 200;       // price of the item
const taxRate = 0.18;    // 18% tax

/* Final amount = price + tax */
const total = price + price * taxRate;

console.log("Total:", total);
```

```output
Total: 236
```

## Common Mistakes

### Using a Reserved Word as a Name

```javascript
let class = "A";    // SyntaxError
```

### Starting a Name with a Digit or Using a Hyphen

```javascript
let 1stPlace = "Asha";    // SyntaxError
let first-name = "Asha";  // SyntaxError
```

Use `firstPlace` and `firstName`.

### Wrong Capitalization

```javascript
let userName = "Asha";
console.log(username);    // ReferenceError: username is not defined
```

### Missing Closing Brace or Bracket

```javascript
if (true) {
  console.log("Hi");
// SyntaxError: missing }
```

### Nesting Multi-Line Comments

```javascript
/* outer /* inner */ still a comment? */    // SyntaxError
```

A `/* */` comment ends at the first `*/`, so comments cannot be nested.

---

## Key Points

* A program is a list of statements, usually ending with `;`.
* JavaScript ignores extra whitespace, but good indentation improves readability.
* JavaScript is case-sensitive.
* Curly braces `{ }` create code blocks.
* Names may use letters, digits, `_` and `$`, and cannot start with a digit.
* Use `camelCase` for variables and functions.
* Reserved keywords cannot be used as names.
* `//` is a single-line comment and `/* */` is a multi-line comment.
* `"use strict";` catches common mistakes.
