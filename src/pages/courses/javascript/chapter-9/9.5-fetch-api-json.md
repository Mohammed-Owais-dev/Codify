# Chapter 9: Asynchronous JavaScript

## Section 5: Fetch API and JSON

Almost every modern website talks to a server: it loads products, posts comments, checks logins and more. The **Fetch API** sends HTTP requests from JavaScript, and **JSON** is the data format used to carry information back and forth. Together they connect your web page to the rest of the internet.

---

## 1. What Is JSON?

**JSON** (JavaScript Object Notation) is a lightweight text format for storing and exchanging data. It looks like a JavaScript object, but it is always a **string** when sent over the network.

```javascript
const jsonText = `{
  "name": "Asha",
  "age": 20,
  "isStudent": true,
  "skills": ["HTML", "CSS", "JavaScript"],
  "address": null
}`;

console.log(typeof jsonText);
```

```output
string
```

JSON follows strict rules:

| Rule | Example |
| --- | --- |
| Keys must be in **double quotes** | `"name"` (not `name`) |
| Strings use **double quotes** | `"Asha"` (not `'Asha'`) |
| No trailing commas | `{"a": 1}` (not `{"a": 1,}`) |
| No functions, `undefined` or comments | Only data is allowed |

Valid JSON value types are string, number, boolean, `null`, array and object.

---

## 2. JSON.stringify: Object to JSON

`JSON.stringify()` converts a JavaScript value into a JSON string.

```javascript
const student = {
  name: "Asha",
  age: 20,
  skills: ["JS", "HTML"]
};

const json = JSON.stringify(student);

console.log(json);
console.log(typeof json);
```

```output
{"name":"Asha","age":20,"skills":["JS","HTML"]}
string
```

Add a third argument to make the output easier to read.

```javascript
const student = { name: "Asha", age: 20 };

console.log(JSON.stringify(student, null, 2));
```

```output
{
  "name": "Asha",
  "age": 20
}
```

---

## 3. JSON.parse: JSON to Object

`JSON.parse()` converts a JSON string back into a JavaScript value.

```javascript
const json = '{"name":"Ravi","age":22,"skills":["CSS","JS"]}';

const user = JSON.parse(json);

console.log(user.name);
console.log(user.skills[1]);
console.log(typeof user);
```

```output
Ravi
JS
object
```

Invalid JSON throws a `SyntaxError`, so wrap risky parsing in `try...catch`.

```javascript
try {
  JSON.parse("{ name: 'Asha' }");
} catch (error) {
  console.log(error.name);
}
```

```output
SyntaxError
```

## 4. JSON vs JavaScript Objects

| Feature | JavaScript object | JSON |
| --- | --- | --- |
| Type | Real object in memory | Text (string) |
| Keys | Quotes optional | Always double quotes |
| Functions | Allowed | Not allowed |
| `undefined` | Allowed | Not allowed (skipped) |
| Comments | Allowed in code | Not allowed |

```javascript
const data = {
  name: "Meena",
  greet() { return "Hi"; },
  nickname: undefined
};

console.log(JSON.stringify(data));
```

```output
{"name":"Meena"}
```

Functions and `undefined` values are dropped when converting to JSON.

## 5. What Is the Fetch API?

`fetch(url)` sends a request and returns a **Promise** that fulfills with a `Response` object. Reading the body is a **second** asynchronous step, so you usually need two `await`s.

* `fetch(url)` starts the request.
* `response.json()` reads the body and parses it as JSON (also returns a Promise).
* `response.text()` reads the body as plain text.

---

## 6. Your First Fetch with then

This example uses a free practice API called JSONPlaceholder.

```javascript
fetch("https://jsonplaceholder.typicode.com/todos/1")
  .then(response => response.json())
  .then(todo => {
    console.log(todo);
  })
  .catch(error => console.log("Error:", error.message));
```

```output
{ userId: 1, id: 1, title: 'delectus aut autem', completed: false }
```

* The first `.then()` turns the raw response into a JavaScript object.
* The second `.then()` receives the final data.
* `.catch()` handles network failures.

---

## 7. Fetch with async/await

The same request is easier to read with `async/await`.

```javascript
async function getTodo() {
  try {
    const response = await fetch("https://jsonplaceholder.typicode.com/todos/1");
    const todo = await response.json();

    console.log("Title:", todo.title);
    console.log("Done:", todo.completed);
  } catch (error) {
    console.log("Error:", error.message);
  }
}

getTodo();
```

```output
Title: delectus aut autem
Done: false
```

## 8. Checking the Response Status

**Important:** `fetch` only rejects on **network failures** (no internet, blocked request). A `404` or `500` response is still a successful fetch. You must check `response.ok` yourself.

```javascript
async function getMissingTodo() {
  const response = await fetch("https://jsonplaceholder.typicode.com/todos/99999");

  console.log("Status:", response.status);
  console.log("OK:", response.ok);
}

getMissingTodo();
```

```output
Status: 404
OK: false
```

A safe pattern is to throw an error when the response is not OK.

```javascript
async function getData(url) {
  const response = await fetch(url);

  if (!response.ok) {
    throw new Error("Request failed with status " + response.status);
  }

  return response.json();
}

getData("https://jsonplaceholder.typicode.com/todos/99999")
  .catch(error => console.log(error.message));
```

```output
Request failed with status 404
```

| Status range | Meaning |
| --- | --- |
| 200 to 299 | Success (`response.ok` is `true`) |
| 300 to 399 | Redirect |
| 400 to 499 | Client error (404 Not Found, 401 Unauthorized) |
| 500 to 599 | Server error |

## 9. Sending Data with POST

By default `fetch` makes a **GET** request. To send data, pass an options object with the `method`, `headers` and `body`.

```javascript
async function createPost() {
  const newPost = {
    title: "Learn Fetch",
    body: "Notes",
    userId: 1
  };

  const response = await fetch("https://jsonplaceholder.typicode.com/posts", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(newPost)
  });

  const created = await response.json();
  console.log(created);
}

createPost();
```

```output
{ title: 'Learn Fetch', body: 'Notes', userId: 1, id: 101 }
```

* `method` sets the HTTP method (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`).
* `headers` tells the server the body is JSON.
* `body` must be a **string**, so use `JSON.stringify`.
* The server replies with the saved data and a new `id`.

## 10. Query Parameters

Add `?key=value` to the URL to filter or limit results. Use `URLSearchParams` to build them safely.

```javascript
const params = new URLSearchParams({ userId: 1, _limit: 3 });
const url = "https://jsonplaceholder.typicode.com/todos?" + params;

console.log(url);

async function getTodos() {
  const response = await fetch(url);
  const todos = await response.json();

  todos.forEach(todo => console.log(todo.title));
}

getTodos();
```

```output
https://jsonplaceholder.typicode.com/todos?userId=1&_limit=3
delectus aut autem
quis ut nam facilis et officia qui
fugiat veniam minus
```

## 11. Showing Fetched Data on the Page

Press **Run**, then click the button to load a todo from the server and display it.

```html
<!DOCTYPE html>
<html>
<body style="font-family: Arial, sans-serif; padding: 20px;">
  <button id="loadBtn">Load Todo</button>
  <p id="status"></p>
  <ul id="result"></ul>

  <script>
    const button = document.getElementById("loadBtn");
    const status = document.getElementById("status");
    const result = document.getElementById("result");

    button.addEventListener("click", async () => {
      status.textContent = "Loading...";
      result.innerHTML = "";

      try {
        const response = await fetch("https://jsonplaceholder.typicode.com/todos/1");

        if (!response.ok) {
          throw new Error("Server returned " + response.status);
        }

        const todo = await response.json();

        result.innerHTML =
          "<li>Title: " + todo.title + "</li>" +
          "<li>Completed: " + todo.completed + "</li>";
        status.textContent = "Loaded!";
      } catch (error) {
        status.textContent = "Failed: " + error.message;
      }
    });
  </script>
</body>
</html>
```

## 12. The Loading, Success and Error Pattern

Real pages always handle three states while talking to a server:

* **Loading:** show a spinner or "Loading..." text.
* **Success:** display the data.
* **Error:** show a friendly message and let the user retry.

```javascript
async function loadData(url) {
  console.log("Loading...");

  try {
    const response = await fetch(url);
    if (!response.ok) throw new Error("Status " + response.status);

    const data = await response.json();
    console.log("Success: got " + data.length + " items");
  } catch (error) {
    console.log("Error: " + error.message);
  }
}

loadData("https://jsonplaceholder.typicode.com/todos?_limit=5");
```

```output
Loading...
Success: got 5 items
```

## Real-World Example 🌍

A task app that loads the first three tasks from a server and prints a short summary:

```javascript
async function showTasks() {
  try {
    const response = await fetch("https://jsonplaceholder.typicode.com/todos?_limit=3");

    if (!response.ok) {
      throw new Error("Could not load tasks");
    }

    const tasks = await response.json();

    tasks.forEach((task, index) => {
      const status = task.completed ? "done" : "pending";
      console.log(`${index + 1}. ${task.title} [${status}]`);
    });
  } catch (error) {
    console.log("Error: " + error.message);
  }
}

showTasks();
```

```output
1. delectus aut autem [pending]
2. quis ut nam facilis et officia qui [pending]
3. fugiat veniam minus [pending]
```

## Common Mistakes

### Forgetting to Parse the Response

```javascript
const response = await fetch(url);
console.log(response.title);    // undefined, response is not the data
```

Use `const data = await response.json();`.

### Assuming fetch Rejects on 404

```javascript
try {
  await fetch("/missing");    // does NOT throw on 404
} catch (error) {
  // never reached for HTTP errors
}
```

Always check `response.ok`.

### Sending an Object Without JSON.stringify

```javascript
fetch(url, { method: "POST", body: { name: "Asha" } });                   // wrong
fetch(url, { method: "POST", body: JSON.stringify({ name: "Asha" }) });   // correct
```

### Forgetting the Content-Type Header

Without `"Content-Type": "application/json"`, many servers cannot read your JSON body.

### Reading the Body Twice

```javascript
const data1 = await response.json();
const data2 = await response.json();    // TypeError: body already used
```

A response body can be read only **once**. Store the result in a variable.

### Inserting Server Data with innerHTML

Server text may contain harmful HTML. Prefer `textContent` unless you trust and sanitize the data.

### Using Single Quotes in JSON

```javascript
JSON.parse("{'name': 'Asha'}");    // SyntaxError
JSON.parse('{"name": "Asha"}');    // correct
```

---

## Key Points

* JSON is a text format for data with strict rules: double-quoted keys and strings, no functions or comments.
* `JSON.stringify()` converts a value to a JSON string; `JSON.parse()` converts it back.
* `fetch(url)` returns a Promise that fulfills with a `Response` object.
* Read the body with `await response.json()` (or `.text()`); this is a second async step.
* `fetch` rejects only on network errors; always check `response.ok` for HTTP errors.
* Send data with `method`, `headers` and a `JSON.stringify`'d `body`.
* Build query strings safely with `URLSearchParams`.
* Handle the loading, success and error states in every real page.
* A response body can be read only once.
