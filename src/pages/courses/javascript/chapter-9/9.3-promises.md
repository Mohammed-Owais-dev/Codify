# Chapter 9: Asynchronous JavaScript

## Section 3: Promises

A **Promise** is an object that represents a value that is not available yet but will be in the future. It is JavaScript's cleaner answer to callback hell. With Promises you can chain steps in a flat, readable way and handle errors in one place.

---

## 1. What Is a Promise?

Think of ordering food at a restaurant. You receive a token and the kitchen promises to give you food later. The token is a Promise, and it can end in one of three ways.

| State | Meaning |
| --- | --- |
| **Pending** | The work is still in progress |
| **Fulfilled** | The work succeeded and there is a result value |
| **Rejected** | The work failed and there is an error |

A Promise starts as **pending** and then settles **once**, either fulfilled or rejected. After that it never changes.

```javascript
const waiting = new Promise(() => {});
const done = Promise.resolve(42);

console.log(waiting);
console.log(done);
```

```output
Promise { <pending> }
Promise { 42 }
```

---

## 2. Creating a Promise

You create a Promise with `new Promise()`. It receives an **executor** function with two parameters: `resolve` and `reject`.

```javascript
function checkAge(age) {
  return new Promise((resolve, reject) => {
    if (age >= 18) {
      resolve("Access granted");
    } else {
      reject(new Error("Access denied"));
    }
  });
}

checkAge(20)
  .then(message => console.log(message))
  .catch(error => console.log(error.message));

checkAge(15)
  .then(message => console.log(message))
  .catch(error => console.log(error.message));
```

```output
Access granted
Access denied
```

* Call `resolve(value)` when the work succeeds.
* Call `reject(error)` when the work fails.
* Reject with an `Error` object so you get a useful message and stack trace.

---

## 3. Consuming a Promise: then, catch and finally

| Method | Runs when |
| --- | --- |
| `.then(onFulfilled)` | The Promise is fulfilled |
| `.catch(onRejected)` | The Promise is rejected |
| `.finally(callback)` | Always, after success or failure |

```javascript
const wait = (ms, value) =>
  new Promise(resolve => setTimeout(() => resolve(value), ms));

wait(500, "Profile data")
  .then(data => console.log("Received:", data))
  .catch(error => console.log("Error:", error.message))
  .finally(() => console.log("Loading finished"));
```

```output
Received: Profile data
Loading finished
```

`finally` is the right place for cleanup, such as hiding a loading spinner.

---

## 4. Promise Chaining

Every `.then()` returns a **new Promise**, so you can chain steps. The value you `return` becomes the input of the next step.

```javascript
Promise.resolve(2)
  .then(n => n * 2)
  .then(n => n + 1)
  .then(n => {
    console.log("Result:", n);
  });
```

```output
Result: 5
```

If you return another Promise from `.then()`, the chain waits for it to finish.

```javascript
const wait = (ms, value) =>
  new Promise(resolve => setTimeout(() => resolve(value), ms));

wait(300, "Step 1")
  .then(result => {
    console.log(result);
    return wait(300, "Step 2");
  })
  .then(result => {
    console.log(result);
    return wait(300, "Step 3");
  })
  .then(result => console.log(result));
```

```output
Step 1
Step 2
Step 3
```

Compare this flat chain with the nested callback pyramid from Chapter 4. Same behavior, much easier to read.

---

## 5. Error Handling in Chains

An error thrown anywhere in a chain skips the remaining `.then()` calls and jumps to the nearest `.catch()`.

```javascript
Promise.resolve(1)
  .then(n => {
    throw new Error("Something broke");
  })
  .then(() => console.log("This is skipped"))
  .catch(error => console.log("Caught: " + error.message))
  .finally(() => console.log("Done"));
```

```output
Caught: Something broke
Done
```

After a `.catch()`, the chain **recovers** and continues normally.

```javascript
Promise.reject(new Error("Failed"))
  .catch(error => {
    console.log("Handled: " + error.message);
    return "fallback value";
  })
  .then(value => console.log("Continuing with " + value));
```

```output
Handled: Failed
Continuing with fallback value
```

---

## 6. Promise.resolve and Promise.reject

These shortcuts create Promises that are already settled.

```javascript
Promise.resolve("Ready").then(value => console.log(value));

Promise.reject(new Error("Not ready")).catch(error => console.log(error.message));
```

```output
Ready
Not ready
```

They are useful when a function must always return a Promise, even if the answer is already known.

---

## 7. Promise.all: Wait for Everything

`Promise.all` takes an array of Promises and fulfills when **all** of them fulfill. The results keep the **same order** as the input. If any Promise rejects, `Promise.all` rejects immediately.

```javascript
const wait = (ms, value) =>
  new Promise(resolve => setTimeout(() => resolve(value), ms));

Promise.all([
  wait(300, "A"),
  wait(100, "B"),
  wait(200, "C")
]).then(results => console.log(results));
```

```output
[ 'A', 'B', 'C' ]
```

All three timers run **at the same time**, so the total time is about 300 ms, not 600 ms.

---

## 8. Promise.allSettled: Wait Without Failing

`Promise.allSettled` waits for every Promise to finish, whether it succeeded or failed, and reports each outcome.

```javascript
Promise.allSettled([
  Promise.resolve("ok"),
  Promise.reject(new Error("fail")),
  Promise.resolve("fine")
]).then(results => {
  results.forEach(result => console.log(result.status));
});
```

```output
fulfilled
rejected
fulfilled
```

---

## 9. Promise.race and Promise.any

* `Promise.race` settles as soon as the **first** Promise settles (success or failure).
* `Promise.any` fulfills with the **first successful** Promise and ignores failures.

```javascript
const wait = (ms, value) =>
  new Promise(resolve => setTimeout(() => resolve(value), ms));

Promise.race([wait(300, "slow"), wait(100, "fast")])
  .then(winner => console.log("Race winner:", winner));

Promise.any([
  Promise.reject(new Error("failed")),
  wait(200, "first success"),
  wait(400, "second success")
]).then(value => console.log("Any result:", value));
```

```output
Race winner: fast
Any result: first success
```

| Method | Fulfills when | Rejects when |
| --- | --- | --- |
| `Promise.all` | All fulfill | Any one rejects |
| `Promise.allSettled` | All have settled | Never |
| `Promise.race` | First one fulfills | First one rejects |
| `Promise.any` | First one fulfills | All reject |

## 10. Turning Callbacks into Promises

You can wrap a callback-based function in a Promise. This is called **promisifying**.

```javascript
function loadUser(id, callback) {
  setTimeout(() => callback(null, { id: id, name: "Asha" }), 300);
}

function loadUserPromise(id) {
  return new Promise((resolve, reject) => {
    loadUser(id, (error, user) => {
      if (error) reject(error);
      else resolve(user);
    });
  });
}

loadUserPromise(1).then(user => console.log(user.name));
```

```output
Asha
```

## Real-World Example 🌍

An online checkout that verifies payment, creates the order and sends an email, one step after another:

```javascript
const step = (ms, message) =>
  new Promise(resolve => setTimeout(() => resolve(message), ms));

function verifyPayment() { return step(300, "Payment verified"); }
function createOrder()   { return step(300, "Order created"); }
function sendEmail()     { return step(300, "Email sent"); }

verifyPayment()
  .then(message => {
    console.log(message);
    return createOrder();
  })
  .then(message => {
    console.log(message);
    return sendEmail();
  })
  .then(message => console.log(message))
  .catch(error => console.log("Checkout failed: " + error.message))
  .finally(() => console.log("Checkout finished"));
```

```output
Payment verified
Order created
Email sent
Checkout finished
```

## Common Mistakes

### Forgetting to Return Inside then

```javascript
fetchUser()
  .then(user => {
    getOrders(user.id);    // missing return, the next then gets undefined
  })
  .then(orders => console.log(orders));
```

Write `return getOrders(user.id);`.

### Nesting Promises Like Callbacks

```javascript
getUser().then(user => {
  getOrders(user.id).then(orders => {
    console.log(orders);
  });
});
```

Return the inner Promise and chain flat `.then()` calls instead.

### Forgetting catch

```javascript
Promise.reject(new Error("Oops"));    // unhandled rejection warning
```

Always end a chain with `.catch()` so errors are never silent.

### Rejecting with a String

```javascript
reject("Something went wrong");                 // no stack trace
reject(new Error("Something went wrong"));      // better
```

### Expecting resolve to Stop the Function

```javascript
new Promise((resolve, reject) => {
  resolve("done");
  console.log("Still runs");    // resolve does not stop the code
});
```

Only the **first** call to `resolve` or `reject` counts. Later calls are ignored.

### Using Promise.all When Failure Is Acceptable

If one failure should not cancel everything, use `Promise.allSettled`.

---

## Key Points

* A Promise represents a value that will be available later.
* A Promise is **pending**, then becomes **fulfilled** or **rejected** exactly once.
* Create one with `new Promise((resolve, reject) => { ... })`.
* Use `.then()` for success, `.catch()` for errors and `.finally()` for cleanup.
* Each `.then()` returns a new Promise, which makes chaining possible.
* Return a value or another Promise inside `.then()` to pass it to the next step.
* An error skips ahead to the next `.catch()`.
* `Promise.all` waits for all, `allSettled` reports all, `race` takes the first to settle and `any` takes the first success.
* Promises remove deep nesting and make async code easier to read.
