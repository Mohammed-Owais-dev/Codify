# Chapter 9: Asynchronous JavaScript

## Section 2: setTimeout and setInterval

JavaScript has two built-in timer functions. `setTimeout` runs code **once** after a delay, and `setInterval` runs code **repeatedly** at a fixed interval. They are the simplest way to see asynchronous code in action, and they power countdowns, auto-save, sliders and clocks.

---

## 1. setTimeout Basics

`setTimeout(callback, delay)` runs a function once after a delay in **milliseconds** (1000 ms = 1 second).

```javascript
console.log("Order placed");

setTimeout(() => {
  console.log("Order delivered after 2 seconds");
}, 2000);

console.log("Waiting...");
```

```output
Order placed
Waiting...
Order delivered after 2 seconds
```

* The first argument is the **callback** function.
* The second argument is the **delay** in milliseconds.
* JavaScript does not wait; it continues with the next line.

You can also pass a named function. Pass the **name** without parentheses.

```javascript
function sayHello() {
  console.log("Hello after 1 second");
}

setTimeout(sayHello, 1000);
```

```output
Hello after 1 second
```

---

## 2. Passing Arguments to the Callback

Any values after the delay are passed to the callback as arguments.

```javascript
function greet(name, greeting) {
  console.log(`${greeting}, ${name}!`);
}

setTimeout(greet, 500, "Asha", "Hello");
```

```output
Hello, Asha!
```

An arrow function does the same job and is often easier to read.

```javascript
const user = "Ravi";

setTimeout(() => greet(user, "Welcome"), 500);

function greet(name, greeting) {
  console.log(`${greeting}, ${name}!`);
}
```

```output
Welcome, Ravi!
```

---

## 3. Cancelling a Timer with clearTimeout

`setTimeout` returns an **ID**. Pass that ID to `clearTimeout` to cancel the timer before it runs.

```javascript
const timerId = setTimeout(() => {
  console.log("This will never run");
}, 1000);

clearTimeout(timerId);
console.log("Timer cancelled");
```

```output
Timer cancelled
```

Cancelling is useful when the user leaves a page, closes a popup or starts a new action before the timer fires.

---

## 4. setInterval Basics

`setInterval(callback, interval)` runs a function again and again, every `interval` milliseconds, **until you stop it**.

```javascript
let count = 0;

const intervalId = setInterval(() => {
  count++;
  console.log("Tick " + count);

  if (count === 3) {
    clearInterval(intervalId);
    console.log("Stopped");
  }
}, 500);
```

```output
Tick 1
Tick 2
Tick 3
Stopped
```

* `setInterval` returns an ID, just like `setTimeout`.
* `clearInterval(id)` stops the repetition.
* If you never call `clearInterval`, the timer keeps running forever.

---

## 5. Order of Timers

Timers run in order of their **delay**, not the order in which you wrote them.

```javascript
setTimeout(() => console.log("Slow (300ms)"), 300);
setTimeout(() => console.log("Fast (100ms)"), 100);
setTimeout(() => console.log("Medium (200ms)"), 200);
```

```output
Fast (100ms)
Medium (200ms)
Slow (300ms)
```

When two timers have the **same** delay, they run in the order they were created.

```javascript
console.log("A");

setTimeout(() => console.log("B"), 0);
setTimeout(() => console.log("C"), 0);

console.log("D");
```

```output
A
D
B
C
```

> The delay is a **minimum**, not a guarantee. If the call stack is busy, the callback runs later than requested.

---

## 6. Recursive setTimeout

Instead of `setInterval`, you can call `setTimeout` again inside the callback. This is called a **recursive timer** and it gives you more control.

```javascript
function countdown(n) {
  if (n === 0) {
    console.log("Go!");
    return;
  }

  console.log(n);
  setTimeout(() => countdown(n - 1), 500);
}

countdown(3);
```

```output
3
2
1
Go!
```

Why choose recursive `setTimeout`?

* The next run is scheduled **after** the current one finishes, so runs never overlap.
* You can change the delay each time (for example, slow down after each failure).
* You can stop simply by not scheduling the next call.

---

## 7. A Sleep Helper with Promises

You can wrap `setTimeout` in a Promise to create a reusable `sleep` function. You will use it with `async/await` later in this chapter.

```javascript
const sleep = ms => new Promise(resolve => setTimeout(resolve, ms));

async function demo() {
  console.log("Before");
  await sleep(1000);
  console.log("After 1 second");
}

demo();
```

```output
Before
After 1 second
```

## 8. Timers in the Browser

Press **Run** to try a stopwatch built with `setInterval`. The **Start** button checks `timerId` so that pressing it twice does not create two timers.

```html
<!DOCTYPE html>
<html>
<body style="font-family: Arial, sans-serif; padding: 20px;">
  <h2 id="display">0</h2>
  <button id="startBtn">Start</button>
  <button id="stopBtn">Stop</button>
  <button id="resetBtn">Reset</button>

  <script>
    let seconds = 0;
    let timerId = null;
    const display = document.getElementById("display");

    document.getElementById("startBtn").addEventListener("click", () => {
      if (timerId !== null) return;

      timerId = setInterval(() => {
        seconds++;
        display.textContent = seconds;
      }, 1000);
    });

    document.getElementById("stopBtn").addEventListener("click", () => {
      clearInterval(timerId);
      timerId = null;
    });

    document.getElementById("resetBtn").addEventListener("click", () => {
      clearInterval(timerId);
      timerId = null;
      seconds = 0;
      display.textContent = seconds;
    });
  </script>
</body>
</html>
```

## 9. setTimeout vs setInterval

| Feature | `setTimeout` | `setInterval` |
| --- | --- | --- |
| Runs | Once | Repeatedly |
| Stop with | `clearTimeout(id)` | `clearInterval(id)` |
| Good for | Delays, one-time actions | Clocks, polling, slideshows |
| Overlap risk | None | Possible if the callback is slow |

## Real-World Example

An OTP screen that lets the user resend the code only after a countdown:

```javascript
let secondsLeft = 3;

const timer = setInterval(() => {
  if (secondsLeft > 0) {
    console.log(`Resend OTP in ${secondsLeft}s`);
    secondsLeft--;
  } else {
    clearInterval(timer);
    console.log("You can resend the OTP now");
  }
}, 1000);
```

```output
Resend OTP in 3s
Resend OTP in 2s
Resend OTP in 1s
You can resend the OTP now
```

## Common Mistakes

### Calling the Function Instead of Passing It

```javascript
setTimeout(sayHello(), 1000);    // sayHello runs now
setTimeout(sayHello, 1000);      // correct
```

### Forgetting to Stop setInterval

```javascript
setInterval(() => console.log("Running..."), 1000);    // never stops
```

Always store the ID and call `clearInterval` when the work is done.

### Passing Arguments the Wrong Way

```javascript
setTimeout(greet("Asha"), 1000);          // wrong
setTimeout(() => greet("Asha"), 1000);    // correct
```

### Creating Many Timers by Accident

```javascript
button.addEventListener("click", () => {
  setInterval(update, 1000);    // every click adds another timer
});
```

Check whether a timer already exists, or clear the old one first.

### Expecting Exact Timing

A delay of `1000` means "at least 1000 ms". Busy code can make the callback run later.

### Using Seconds Instead of Milliseconds

```javascript
setTimeout(done, 2);       // 2 milliseconds, almost instant
setTimeout(done, 2000);    // 2 seconds
```

## Key Points

* `setTimeout(callback, delay)` runs a function **once** after the delay.
* `setInterval(callback, interval)` runs a function **repeatedly**.
* The delay is measured in **milliseconds**.
* Both return an ID; use `clearTimeout(id)` or `clearInterval(id)` to cancel.
* Extra arguments after the delay are passed to the callback.
* Timers with shorter delays run first; equal delays run in creation order.
* The delay is a minimum; the callback waits until the call stack is empty.
* Recursive `setTimeout` avoids overlapping runs and gives more control.
* Wrapping `setTimeout` in a Promise gives a handy `sleep` function.
