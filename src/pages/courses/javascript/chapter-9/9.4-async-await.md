# Chapter 9: Asynchronous JavaScript

## Section 4: async and await

`async` and `await` are modern syntax built on top of Promises. They let you write asynchronous code that **looks and reads like normal synchronous code**, with no long `.then()` chains. Most JavaScript developers use `async/await` for everyday asynchronous work.

---

## 1. async Functions Return Promises

Putting the `async` keyword before a function makes it **always return a Promise**.

```javascript
async function getMessage() {
  return "Hello";
}

console.log(getMessage());

getMessage().then(message => console.log(message));
```

```output
Promise { 'Hello' }
Hello
```

* A returned value is wrapped in a fulfilled Promise.
* A thrown error becomes a rejected Promise.
* You can still use `.then()` and `.catch()` on the result.

---

## 2. The await Keyword

`await` pauses the **async function** until a Promise settles, then gives you the result. The rest of the program keeps running while it waits.

```javascript
const wait = (ms, value) =>
  new Promise(resolve => setTimeout(() => resolve(value), ms));

async function loadData() {
  console.log("Loading...");
  const data = await wait(1000, "Server data");
  console.log("Received:", data);
}

loadData();
console.log("This runs while waiting");
```

```output
Loading...
This runs while waiting
Received: Server data
```

* `await` can only be used inside an `async` function (or at the top level of a module).
* The code after `await` runs only when the Promise is fulfilled.
* The page is **not blocked**; only that one function waits.

---

## 3. From Promise Chains to async/await

Here is the same task written both ways. First with `.then()`:

```javascript
const step = (ms, message) =>
  new Promise(resolve => setTimeout(() => resolve(message), ms));

step(200, "Step 1")
  .then(result => {
    console.log(result);
    return step(200, "Step 2");
  })
  .then(result => {
    console.log(result);
    return step(200, "Step 3");
  })
  .then(result => console.log(result));
```

```output
Step 1
Step 2
Step 3
```

Now with `async/await`:

```javascript
const step = (ms, message) =>
  new Promise(resolve => setTimeout(() => resolve(message), ms));

async function run() {
  console.log(await step(200, "Step 1"));
  console.log(await step(200, "Step 2"));
  console.log(await step(200, "Step 3"));
}

run();
```

```output
Step 1
Step 2
Step 3
```

The second version reads from top to bottom, exactly like synchronous code.

## 4. Error Handling with try...catch

With `async/await`, you handle errors using the normal `try...catch...finally` structure.

```javascript
function getUser(id) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (id > 0) resolve({ id: id, name: "Asha" });
      else reject(new Error("Invalid user id"));
    }, 300);
  });
}

async function showUser(id) {
  try {
    const user = await getUser(id);
    console.log("User:", user.name);
  } catch (error) {
    console.log("Error:", error.message);
  } finally {
    console.log("Request finished");
  }
}

showUser(1);
showUser(-5);
```

```output
User: Asha
Error: Invalid user id
Request finished
Request finished
```

* A rejected Promise that is awaited **throws** an error inside the function.
* The `catch` block receives that error.
* `finally` always runs, which is ideal for cleanup.

## 5. Sequential vs Parallel Execution

Each `await` pauses the function. If two tasks do **not depend on each other**, awaiting them one by one wastes time.

```javascript
const wait = (ms, value) =>
  new Promise(resolve => setTimeout(() => resolve(value), ms));

async function sequential() {
  const start = Date.now();
  const a = await wait(200, "A");
  const b = await wait(200, "B");
  const time = Math.round((Date.now() - start) / 100) * 100;
  console.log("Sequential:", a, b, "in about", time, "ms");
}

async function parallel() {
  const start = Date.now();
  const [a, b] = await Promise.all([wait(200, "A"), wait(200, "B")]);
  const time = Math.round((Date.now() - start) / 100) * 100;
  console.log("Parallel:", a, b, "in about", time, "ms");
}

sequential().then(parallel);
```

```output
Sequential: A B in about 400 ms
Parallel: A B in about 200 ms
```

Use `await Promise.all([...])` when tasks are independent. Use separate `await` lines only when one task needs the result of the previous one.

## 6. async/await in Loops

A `for...of` loop works naturally with `await` and runs one item at a time, in order.

```javascript
const wait = (ms, value) =>
  new Promise(resolve => setTimeout(() => resolve(value), ms));

async function loadUsers() {
  const ids = [1, 2, 3];

  for (const id of ids) {
    const user = await wait(100, "User " + id);
    console.log(user);
  }

  console.log("All users loaded");
}

loadUsers();
```

```output
User 1
User 2
User 3
All users loaded
```

To run all items at the same time, combine `map` with `Promise.all`.

```javascript
const wait = (ms, value) =>
  new Promise(resolve => setTimeout(() => resolve(value), ms));

async function loadAll() {
  const ids = [1, 2, 3];
  const users = await Promise.all(ids.map(id => wait(100, "User " + id)));
  console.log(users);
}

loadAll();
```

```output
[ 'User 1', 'User 2', 'User 3' ]
```

> `forEach` does **not** wait for `await` inside its callback. Use `for...of` or `Promise.all(map(...))` instead.

## 7. async Arrow Functions and Methods

The `async` keyword works with every function style.

```javascript
const wait = (ms, value) =>
  new Promise(resolve => setTimeout(() => resolve(value), ms));

// Async function expression
const getA = async function () {
  return await wait(100, "A");
};

// Async arrow function
const getB = async () => await wait(100, "B");

// Async method inside an object
const api = {
  async getC() {
    return await wait(100, "C");
  }
};

// Async IIFE: run immediately
(async () => {
  console.log(await getA());
  console.log(await getB());
  console.log(await api.getC());
})();
```

```output
A
B
C
```

## 8. Top-Level await in Modules

Inside an ES module (`<script type="module">`), you can use `await` **outside** any function. Press **Run** to see it in action.

```html
<!DOCTYPE html>
<html>
<body style="font-family: Arial, sans-serif; padding: 20px;">
  <p id="output">Loading...</p>

  <script type="module">
    const wait = (ms, value) =>
      new Promise(resolve => setTimeout(() => resolve(value), ms));

    const message = await wait(1000, "Loaded with top-level await!");
    document.getElementById("output").textContent = message;
  </script>
</body>
</html>
```

Top-level `await` does not work in regular scripts, only in modules.

---

## 9. await Works with Any Value

If you `await` something that is not a Promise, JavaScript simply returns it (after a tiny pause).

```javascript
async function demo() {
  const value = await 42;
  console.log(value);
}

demo();
```

```output
42
```

## Real-World Example 🌍

A dashboard that logs in, loads a profile and loads orders, step by step, with proper error handling:

```javascript
const fakeApi = (ms, data, fail = false) =>
  new Promise((resolve, reject) => {
    setTimeout(() => (fail ? reject(new Error("Network error")) : resolve(data)), ms);
  });

async function loadDashboard() {
  try {
    console.log("Logging in...");
    const user = await fakeApi(300, { id: 7, name: "Meena" });

    console.log("Loading profile for " + user.name + "...");
    const profile = await fakeApi(300, { city: "Hyderabad" });

    console.log("Loading orders...");
    const orders = await fakeApi(300, ["Book", "Pen", "Bag"]);

    console.log(`${user.name} from ${profile.city} has ${orders.length} orders`);
  } catch (error) {
    console.log("Could not load dashboard: " + error.message);
  } finally {
    console.log("Dashboard request complete");
  }
}

loadDashboard();
```

```output
Logging in...
Loading profile for Meena...
Loading orders...
Meena from Hyderabad has 3 orders
Dashboard request complete
```

## Common Mistakes

### Forgetting await

```javascript
async function show() {
  const data = getData();       // a Promise, not the data
  console.log(data);            // Promise { <pending> }
}
```

Write `const data = await getData();`.

### Using await Outside an async Function

```javascript
function load() {
  const data = await getData();    // SyntaxError
}
```

Mark the function as `async`.

### Awaiting Independent Tasks One by One

```javascript
const users = await getUsers();
const posts = await getPosts();    // waits for users for no reason
```

Use `await Promise.all([getUsers(), getPosts()])`.

### Using await Inside forEach

```javascript
ids.forEach(async id => {
  await load(id);    // forEach does not wait
});
console.log("Done");  // prints too early
```

Use a `for...of` loop instead.

### Skipping Error Handling

```javascript
async function load() {
  const data = await fetchData();    // a rejection becomes an unhandled error
}
```

Wrap risky `await` calls in `try...catch`.

### Forgetting That async Functions Return Promises

```javascript
const result = loadData();     // a Promise
const result2 = await loadData();    // the actual value
```

---

## Key Points

* An `async` function always returns a Promise.
* `await` pauses the async function until a Promise settles and returns its value.
* `await` works only inside `async` functions or at the top level of a module.
* Other code keeps running while an `await` is waiting, so the page is never blocked.
* Use `try...catch...finally` to handle errors and clean up.
* Use `await Promise.all([...])` to run independent tasks in parallel.
* Use `for...of`, not `forEach`, when you need to `await` inside a loop.
* `async/await` is just cleaner syntax for Promises; both work together.
