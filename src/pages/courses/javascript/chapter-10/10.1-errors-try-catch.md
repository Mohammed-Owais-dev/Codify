# Chapter 10: Error Handling and Practical Projects

## Section 1: Errors and try...catch

Every program meets errors: a user types bad input, a network request fails, or a variable is used before it exists. Without error handling, one mistake stops your whole script. With `try...catch`, your program can notice the problem, react to it and keep running.

---

## 1. What Happens When an Error Occurs?

When JavaScript hits an error it cannot handle, it **stops** running the current code and prints an error message.

```javascript
console.log("Before the error");
console.log(userName);
console.log("After the error");
```

```output
Before the error
ReferenceError: userName is not defined
```

The last line never runs. Error handling lets you avoid this.

---

## 2. Common Types of Errors

JavaScript has several built-in error types. The type tells you what kind of problem occurred.

| Error type | Cause | Example |
| --- | --- | --- |
| `SyntaxError` | Code is written incorrectly | `let = 5;` |
| `ReferenceError` | Using a variable that does not exist | `console.log(x)` |
| `TypeError` | Using a value in the wrong way | `null.length` |
| `RangeError` | A number is outside the allowed range | `new Array(-1)` |
| `URIError` | Invalid URI function usage | `decodeURIComponent("%")` |

A **syntax error** is found before the code runs, so the whole script fails. The other types are **runtime errors** and appear while the code is running.

---

## 3. The try...catch Statement

Put risky code inside `try`. If an error occurs, JavaScript jumps to `catch` instead of crashing.

```javascript
try {
  console.log("Start");
  console.log(userName);
  console.log("This line is skipped");
} catch (error) {
  console.log("Something went wrong");
}

console.log("Program continues");
```

```output
Start
Something went wrong
Program continues
```

* Code in `try` runs normally until an error happens.
* The rest of the `try` block is **skipped** after the error.
* The `catch` block runs and receives the error object.
* The program continues after the `try...catch`.

---

## 4. The Error Object

The `catch` block receives an **error object** with useful information.

```javascript
try {
  const value = null;
  console.log(value.length);
} catch (error) {
  console.log("Name:", error.name);
  console.log("Message:", error.message);
}
```

```output
Name: TypeError
Message: Cannot read properties of null (reading 'length')
```

| Property | Meaning |
| --- | --- |
| `error.name` | The type of error, such as `TypeError` |
| `error.message` | A human-readable description |
| `error.stack` | Where the error happened (useful for debugging) |

---

## 5. The finally Block

The `finally` block runs **always**, whether an error happened or not. It is perfect for cleanup work.

```javascript
function test(shouldFail) {
  try {
    console.log("Trying...");
    if (shouldFail) {
      throw new Error("Failure");
    }
    console.log("Success");
  } catch (error) {
    console.log("Caught: " + error.message);
  } finally {
    console.log("Cleanup done");
  }
}

test(false);
test(true);
```

```output
Trying...
Success
Cleanup done
Trying...
Caught: Failure
Cleanup done
```

## 6. Throwing Your Own Errors

Use the `throw` statement to create an error yourself when something is wrong, such as invalid input.

```javascript
function divide(a, b) {
  if (b === 0) {
    throw new Error("Cannot divide by zero");
  }
  return a / b;
}

try {
  console.log(divide(10, 2));
  console.log(divide(5, 0));
} catch (error) {
  console.log("Error: " + error.message);
}
```

```output
5
Error: Cannot divide by zero
```

* `throw` stops the function immediately.
* Always throw an `Error` object, not a plain string.
* The nearest `catch` up the call chain handles it.

## 7. Custom Error Classes

You can create your own error types by extending `Error`. This helps you tell different problems apart.

```javascript
class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = "ValidationError";
    this.field = field;
  }
}

function validateAge(age) {
  if (age <= 0) {
    throw new ValidationError("Age must be positive", "age");
  }
  return age;
}

try {
  validateAge(-5);
} catch (error) {
  console.log(error.name);
  console.log(error.message);
  console.log(error.field);
  console.log(error instanceof ValidationError);
}
```

```output
ValidationError
Age must be positive
age
true
```

## 8. Handling Different Error Types

Use `instanceof` to react differently to different errors. If you do not know how to handle an error, **rethrow** it.

```javascript
class ValidationError extends Error {}

function process(value) {
  if (typeof value !== "number") {
    throw new ValidationError("Value must be a number");
  }
  return value.toFixed(2);
}

function run(value) {
  try {
    console.log(process(value));
  } catch (error) {
    if (error instanceof ValidationError) {
      console.log("Please enter a number");
    } else {
      throw error;
    }
  }
}

run(3.14159);
run("hello");
```

```output
3.14
Please enter a number
```

## 9. Errors When Parsing JSON

`JSON.parse` throws a `SyntaxError` for invalid text, so always protect it with `try...catch`.

```javascript
function safeParse(text) {
  try {
    return JSON.parse(text);
  } catch (error) {
    console.log("Invalid JSON:", error.name);
    return null;
  }
}

console.log(safeParse('{"name":"Asha"}'));
console.log(safeParse("{ name: Asha }"));
```

```output
{ name: 'Asha' }
Invalid JSON: SyntaxError
null
```

## 10. Errors in Asynchronous Code

A normal `try...catch` **cannot catch** errors thrown inside a callback that runs later.

```javascript
try {
  setTimeout(() => {
    throw new Error("Too late to catch");
  }, 100);
} catch (error) {
  console.log("Never runs");
}
```

The `catch` block has already finished by the time the timer fires. Use the right tool for each async style:

* **Promises:** use `.catch()`.
* **async/await:** use `try...catch` around the `await`.

```javascript
const failLater = () =>
  new Promise((resolve, reject) => {
    setTimeout(() => reject(new Error("Server not reachable")), 200);
  });

failLater().catch(error => console.log("Promise caught: " + error.message));

async function run() {
  try {
    await failLater();
  } catch (error) {
    console.log("await caught: " + error.message);
  }
}

run();
```

```output
Promise caught: Server not reachable
await caught: Server not reachable
```

## 11. Showing Errors to Users

Never show raw technical errors to the user. Show a friendly message on the page and keep details for the console. Press **Run** and enter some text.

```html
<!DOCTYPE html>
<html>
<body style="font-family: Arial, sans-serif; padding: 20px;">
  <input id="ageInput" placeholder="Enter your age">
  <button id="checkBtn">Check</button>
  <p id="message"></p>

  <script>
    const input = document.getElementById("ageInput");
    const message = document.getElementById("message");

    function readAge(text) {
      const age = Number(text);
      if (text.trim() === "" || Number.isNaN(age)) {
        throw new Error("Please enter a valid number");
      }
      if (age < 0 || age > 120) {
        throw new RangeError("Age must be between 0 and 120");
      }
      return age;
    }

    document.getElementById("checkBtn").addEventListener("click", () => {
      try {
        const age = readAge(input.value);
        message.style.color = "green";
        message.textContent = "Your age is " + age;
      } catch (error) {
        message.style.color = "red";
        message.textContent = error.message;
        console.error(error);
      }
    });
  </script>
</body>
</html>
```

## Real-World Example

A settings loader that reads saved JSON and falls back to defaults if the data is missing or broken:

```javascript
const defaults = { theme: "light", fontSize: 16 };

function loadSettings(savedText) {
  try {
    if (!savedText) {
      throw new Error("No saved settings");
    }
    const settings = JSON.parse(savedText);
    return { ...defaults, ...settings };
  } catch (error) {
    console.log("Using defaults because: " + error.name);
    return defaults;
  }
}

console.log(loadSettings('{"theme":"dark"}'));
console.log(loadSettings("{broken json"));
console.log(loadSettings(null));
```

```output
{ theme: 'dark', fontSize: 16 }
Using defaults because: SyntaxError
{ theme: 'light', fontSize: 16 }
Using defaults because: Error
{ theme: 'light', fontSize: 16 }
```

## Common Mistakes

### Wrapping Too Much Code in try

```javascript
try {
  // 200 lines of code
} catch (error) {
  console.log("Something failed");    // which line? nobody knows
}
```

Keep `try` blocks small and focused on the risky part.

### An Empty catch Block

```javascript
try {
  riskyTask();
} catch (error) {
  // silent failure, bugs become invisible
}
```

At least log the error or show a message.

### Throwing Strings Instead of Errors

```javascript
throw "Something went wrong";                 // no stack trace
throw new Error("Something went wrong");      // correct
```

### Expecting try...catch to Catch Async Callback Errors

```javascript
try {
  setTimeout(() => { throw new Error("Oops"); }, 0);
} catch (error) { }    // never catches it
```

Use `.catch()` or `await` inside `try...catch`.

### Forgetting That fetch Does Not Throw on 404

Check `response.ok` and throw an error yourself.

### Catching an Error You Cannot Handle

If you cannot fix the problem, rethrow it with `throw error` so it is not hidden.

### Showing Technical Messages to Users

Show a friendly message such as "Could not load data. Please try again." and log the real error with `console.error(error)`.

---

## Key Points

* Errors stop the current code unless they are handled.
* Common built-in types are `SyntaxError`, `ReferenceError`, `TypeError` and `RangeError`.
* Put risky code in `try`; handle problems in `catch`; run cleanup in `finally`.
* The error object has `name`, `message` and `stack`.
* Use `throw new Error("message")` to raise your own errors.
* Extend `Error` to create custom error classes and test them with `instanceof`.
* `try...catch` does not catch errors in later callbacks; use `.catch()` or `await` inside `try`.
* Always protect `JSON.parse` and other risky operations.
* Show friendly messages to users and log technical details for yourself.
