# Chapter 6: Objects and Modern JavaScript

## Section 5: JavaScript Modules: import and export

A **module** is a JavaScript file that keeps its code private and shares only what you choose with other files. Modules let you split a large program into small, organized files instead of putting everything in one long script.

---

## 1. Why Use Modules?

* **Organization:** each file has one clear job (for example, formatting prices or handling the cart).
* **No name clashes:** variables inside a module are private to that file.
* **Reusability:** import the same function in many places.
* **Easier maintenance:** you can find, test and fix code faster.

Without modules, every `<script>` shares the same global scope, so two files can accidentally overwrite each other's variables.

---

## 2. Named Exports and Imports

Use the `export` keyword to share something, and `import { ... } from "file"` to use it in another file.

### math.js

```javascript
export const PI = 3.14159;

export function add(a, b) {
  return a + b;
}

export function multiply(a, b) {
  return a * b;
}
```

### app.js

```javascript
import { add, PI } from "./math.js";

console.log(add(2, 3));
console.log(PI);
```

```output
5
3.14159
```

* The names inside `{ }` must **match** the exported names.
* Import only what you need; `multiply` stays unused here.
* The path starts with `./` for a file in the same folder and includes the `.js` extension.

---

## 3. Different Ways to Write Named Exports

You can export while declaring, or list everything in one place at the bottom.

```javascript
// Option 1: export while declaring
export const tax = 0.18;
export function total(price) {
  return price + price * tax;
}

// Option 2: export at the bottom
const discount = 0.1;
function finalPrice(price) {
  return price - price * discount;
}

export { discount, finalPrice };
```

```output
```

Both styles work the same way. The bottom list is helpful because you can see all exports of a file in one place.

---

## 4. Renaming with as

Use `as` to rename an import or an export. This avoids clashes when two modules export the same name.

```javascript
import { add as sum, multiply as times } from "./math.js";

console.log(sum(4, 6));
console.log(times(4, 6));
```

```output
10
24
```

---

## 5. Default Exports

A module can have **one** default export. When importing it, you do not use braces and you can choose any name.

### greet.js

```javascript
export default function greet(name) {
  return `Hello, ${name}!`;
}
```

### app.js

```javascript
import greet from "./greet.js";
import sayHello from "./greet.js";

console.log(greet("Asha"));
console.log(sayHello("Ravi"));
```

```output
Hello, Asha!
Hello, Ravi!
```

Both imports receive the same function. Use default exports when a file has one main thing to share.

| | Named export | Default export |
| - | ------------ | -------------- |
| How many per file | Many | **One** |
| Import syntax | `import { add } from "./math.js"` | `import add from "./math.js"` |
| Name when importing | Must match (or use `as`) | Any name you like |

---

## 6. Mixing Default and Named Exports

### user.js

```javascript
export const ROLE = "student";

export default function createUser(name) {
  return { name };
}
```

### app.js

```javascript
import createUser, { ROLE } from "./user.js";

console.log(createUser("Asha"));
console.log(ROLE);
```

```output
{ name: 'Asha' }
student
```

The default import comes first, followed by the named imports in braces.

---

## 7. Importing Everything with a Namespace

`import * as name` collects all exports of a module into one object.

```javascript
import * as math from "./math.js";

console.log(math.add(1, 2));
console.log(math.PI);
console.log(Object.keys(math));
```

```output
3
3.14159
[ 'PI', 'add', 'multiply' ]
```

This keeps the origin of each function obvious (`math.add`) and avoids name conflicts.

---

## 8. Using Modules in HTML

To run a module in the browser, add `type="module"` to the script tag.

```text
<script type="module" src="app.js"></script>
```

* Without `type="module"`, the browser reports an error at the `import` statement.
* Module scripts run in **strict mode** and are **deferred**, so they run after the HTML is parsed.
* Browsers load modules over HTTP. Opening the page directly as a `file://` path usually fails because of security rules, so use a local server such as the VS Code **Live Server** extension.

---

## 9. Important Module Behaviors

### Each Module Runs Only Once

If many files import the same module, the module's code runs a single time.

```javascript
// logger.js
console.log("Module loaded");
export const version = 1;
```

```javascript
// app.js
import "./logger.js";
import { version } from "./logger.js";

console.log(version);
```

```output
Module loaded
1
```

`import "./logger.js";` (with no names) loads a module only for its side effects.

### Imports Are Live, Read-Only Bindings

An imported value reflects changes made inside the exporting module, but the importing file cannot reassign it.

```javascript
// counter.js
export let count = 0;
export function increment() {
  count++;
}
```

```javascript
// app.js
import { count, increment } from "./counter.js";

console.log(count);
increment();
console.log(count);
// count = 5;   // TypeError: Assignment to constant variable.
```

```output
0
1
```

## 10. Re-exporting from One File

A file that gathers exports from other files is often named `index.js`. It lets other files import from a single place.

### utils/index.js

```javascript
export { add, multiply } from "./math.js";
export { default as greet } from "./greet.js";
```

### app.js

```javascript
import { add, greet } from "./utils/index.js";

console.log(greet("Meena"));
console.log(add(1, 2));
```

```output
Hello, Meena!
3
```

---

## 11. Dynamic Import

A normal `import` must be at the top of the file. A **dynamic import** loads a module only when you need it and returns a **Promise** (you will study Promises in Chapter 9).

```javascript
import("./math.js").then(math => {
  console.log(math.add(4, 6));
});
```

```output
10
```

Dynamic imports are useful for loading large features only when the user asks for them.

## 12. A Typical Project Structure

```text
project/
├── index.html
├── main.js
├── cart.js
└── format.js
```

* `index.html` loads only `main.js` with `type="module"`.
* `main.js` imports from `cart.js`, and `cart.js` imports from `format.js`.
* Each file has a single responsibility.

## Real-World Example 🌍

A tiny shopping cart split into three modules:

### format.js

```javascript
export function formatPrice(amount) {
  return `₹${amount.toFixed(2)}`;
}
```

### cart.js

```javascript
import { formatPrice } from "./format.js";

const items = [];

export function addItem(name, price) {
  items.push({ name, price });
}

export function getTotal() {
  const total = items.reduce((sum, item) => sum + item.price, 0);
  return formatPrice(total);
}
```

### main.js

```javascript
import { addItem, getTotal } from "./cart.js";

addItem("Pen", 10);
addItem("Notebook", 60.5);

console.log(`Total: ${getTotal()}`);
```

```output
Total: ₹70.50
```

The `items` array stays **private** inside `cart.js`. Other files can change it only through the exported functions.

## Common Mistakes

### Forgetting type="module"

```text
<script src="main.js"></script>
<!-- SyntaxError: Cannot use import statement outside a module -->

<script type="module" src="main.js"></script>
<!-- correct -->
```

### Missing ./ or the File Extension

```javascript
import { add } from "math";          // wrong, looks for a package called "math"
import { add } from "./math";        // often fails in the browser
import { add } from "./math.js";     // correct
```

### Using Braces for a Default Export

```javascript
import { greet } from "./greet.js";    // wrong, greet is a default export
import greet from "./greet.js";        // correct
```

### Two Default Exports in One File

```javascript
export default function a() {}
export default function b() {}    // SyntaxError, only one default export is allowed
```

### Reassigning an Imported Value

```javascript
import { count } from "./counter.js";

count = 10;    // TypeError, change it with an exported function instead
```

### Opening the Page Directly from the File System

```text
file:///C:/project/index.html    // modules are blocked
http://localhost:5500/index.html // correct, use Live Server
```

---

## Key Points

* A module is a file with its own private scope; only exported items are shared.
* Use `export` to share and `import ... from "./file.js"` to use.
* Named exports can be many and must be imported with matching names inside `{ }`.
* A file can have only one default export, which is imported without braces under any name.
* Use `as` to rename imports and `import * as name` to collect all exports.
* Add `type="module"` to the `<script>` tag to use modules in the browser.
* Modules run once, in strict mode, and are deferred until the page is parsed.
* Imported bindings are live and read-only.
* An `index.js` file can re-export other modules to give one clean import path.
* Run module pages through a local server, not directly from the file system.
