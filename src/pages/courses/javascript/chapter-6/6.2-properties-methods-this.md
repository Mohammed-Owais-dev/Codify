# Chapter 6: Objects and Modern JavaScript

## Section 2: Properties, Methods and this

Objects do more than store data. When a property holds a **function**, it is called a **method**, and the keyword `this` lets that method work with the object's own data.

---

## 1. Properties and Methods

* A **property** stores a value, such as `name: "Asha"`.
* A **method** is a property whose value is a function, such as `greet() { ... }`.

```javascript
const person = {
  name: "Asha",

  greet: function () {
    return "Hello!";
  },

  sayBye() {
    return "Goodbye!";
  }
};

console.log(person.greet());
console.log(person.sayBye());
console.log(typeof person.greet);
```

```output
Hello!
Goodbye!
function
```

* Both styles create a method. The short form `sayBye() { ... }` is the modern way.
* Call a method with parentheses: `person.greet()`.

---

## 2. The this Keyword

Inside a method, `this` refers to the **object that called the method**. It lets a method read and change the object's other properties.

```javascript
const user = {
  name: "Asha",
  greet() {
    console.log(`Hello, ${this.name}`);
  }
};

user.greet();
```

```output
Hello, Asha
```

Here `this` is `user`, so `this.name` is `"Asha"`.

---

## 3. this Depends on How a Function Is Called

The value of `this` is decided when the function is **called**, not where it is written.

```javascript
const user = {
  name: "Asha",
  greet() {
    console.log(`Hello, ${this.name}`);
  }
};

const other = { name: "Ravi", greet: user.greet };

user.greet();
other.greet();
```

```output
Hello, Asha
Hello, Ravi
```

The same function prints different names because it is called through different objects.

---

## 4. Losing this

If you take a method out of its object and call it alone, `this` is no longer the object.

```javascript
"use strict";

const user = {
  name: "Asha",
  greet() {
    console.log(`Hello, ${this.name}`);
  }
};

const lost = user.greet;

try {
  lost();
} catch (error) {
  console.log("Error: " + error.message);
}
```

```output
Error: Cannot read properties of undefined (reading 'name')
```

A plain function call has no object before the dot, so `this` is `undefined` in strict mode. Without strict mode, `this` becomes the global object and `this.name` is not what you expect. This is a very common bug when passing methods as callbacks.

---

## 5. Fixing this with bind, call and apply

These three methods let you choose the value of `this` yourself.

```javascript
const user = {
  name: "Asha",
  greet() {
    return `Hello, ${this.name}`;
  }
};

const bound = user.greet.bind(user);
console.log(bound());

function intro(greeting) {
  return `${greeting}, I am ${this.name}`;
}

console.log(intro.call({ name: "Asha" }, "Hi"));
console.log(intro.apply({ name: "Ravi" }, ["Hello"]));
```

```output
Hello, Asha
Hi, I am Asha
Hello, I am Ravi
```

| Method | What it does |
| ------ | ------------ |
| `bind(obj)` | Returns a **new function** with `this` fixed to `obj` |
| `call(obj, a, b)` | Calls the function now, with arguments listed one by one |
| `apply(obj, [a, b])` | Calls the function now, with arguments in an array |

---

## 6. Arrow Functions and this

Arrow functions do **not** have their own `this`. They use the `this` of the surrounding code. This is helpful for callbacks **inside** methods.

```javascript
const team = {
  name: "Dev Team",
  members: ["Asha", "Ravi"],

  list() {
    this.members.forEach(member => {
      console.log(`${member} is in ${this.name}`);
    });
  }
};

team.list();
```

```output
Asha is in Dev Team
Ravi is in Dev Team
```

Because the arrow function inherits `this` from `list()`, it can read `this.name`. Avoid using an arrow function **as the method itself**, because it will not receive the object as `this`.

---

## 7. Getters and Setters

A **getter** runs code when a property is read. A **setter** runs code when a property is assigned. They look like normal properties from the outside.

```javascript
const account = {
  owner: "Asha",
  _balance: 100,

  get balance() {
    return `₹${this._balance}`;
  },

  set balance(value) {
    if (value < 0) {
      console.log("Invalid amount");
      return;
    }
    this._balance = value;
  }
};

console.log(account.balance);
account.balance = 500;
console.log(account.balance);
account.balance = -5;
console.log(account.balance);
```

```output
₹100
₹500
Invalid amount
₹500
```

* Use `account.balance` without parentheses; it is not a method call.
* The underscore in `_balance` is a naming convention meaning "internal value".
* Setters are a good place for validation.

---

## 8. Method Chaining

If a method returns `this`, calls can be chained one after another.

```javascript
const counter = {
  count: 0,
  inc() {
    this.count++;
    return this;
  },
  dec() {
    this.count--;
    return this;
  }
};

counter.inc().inc().inc().dec();
console.log(counter.count);
```

```output
2
```

---

## 9. Controlling Properties

`Object.defineProperty()` sets extra rules for a property, such as making it read-only or hidden from loops.

```javascript
const product = { name: "Pen" };

Object.defineProperty(product, "id", {
  value: 101,
  writable: false,
  enumerable: false
});

product.id = 999;

console.log(product.id);
console.log(Object.keys(product));
```

```output
101
[ 'name' ]
```

* `writable: false` prevents the value from being changed.
* `enumerable: false` hides the property from `Object.keys()` and `for...in`.

## 10. Creating Many Objects: Factory Functions

When you need many similar objects, write a function that builds and returns them.

```javascript
function createUser(name, role) {
  return {
    name,
    role,
    describe() {
      return `${name} is a ${role}`;
    }
  };
}

const u1 = createUser("Asha", "student");
const u2 = createUser("Ravi", "teacher");

console.log(u1.describe());
console.log(u2.describe());
```

```output
Asha is a student
Ravi is a teacher
```

---

## 11. Creating Many Objects: Classes

A **class** is a template for creating objects with the `new` keyword. Inside a class, `this` refers to the new object being created.

```javascript
class Student {
  constructor(name, marks) {
    this.name = name;
    this.marks = marks;
  }

  average() {
    const total = this.marks.reduce((sum, m) => sum + m, 0);
    return total / this.marks.length;
  }
}

const s = new Student("Asha", [80, 90, 100]);

console.log(s.name);
console.log(s.average());
console.log(s instanceof Student);
```

```output
Asha
90
true
```

* `constructor` runs automatically when you use `new`.
* Methods written in a class are shared by all objects created from it.
* `instanceof` checks whether an object was created from a class.

## 12. Transforming Objects

`Object.fromEntries()` is the reverse of `Object.entries()`. Together they let you transform an object like an array.

```javascript
const prices = { pen: 10, book: 20 };

const doubled = Object.fromEntries(
  Object.entries(prices).map(entry => [entry[0], entry[1] * 2])
);

console.log(doubled);
console.log(Object.assign({}, prices, { bag: 300 }));
```

```output
{ pen: 20, book: 40 }
{ pen: 10, book: 20, bag: 300 }
```

## Real-World Example

A bank account object with methods that use `this`:

```javascript
const account = {
  owner: "Asha",
  balance: 1000,

  deposit(amount) {
    this.balance += amount;
    return this;
  },

  withdraw(amount) {
    if (amount > this.balance) {
      console.log("Insufficient balance");
      return this;
    }
    this.balance -= amount;
    return this;
  },

  summary() {
    return `${this.owner}: ₹${this.balance}`;
  }
};

account.deposit(500).withdraw(200);
console.log(account.summary());

account.withdraw(5000);
console.log(account.summary());
```

```output
Asha: ₹1300
Insufficient balance
Asha: ₹1300
```

## Common Mistakes

### Forgetting this Inside a Method

```javascript
const user = {
  name: "Asha",
  greet() {
    return `Hello, ${name}`;         // wrong, looks for a variable called name
    return `Hello, ${this.name}`;    // correct
  }
};
```

### Using an Arrow Function as an Object Method

```javascript
const user = {
  name: "Asha",
  greet: () => `Hello, ${this.name}`,    // wrong, this is not the object
  greet() { return `Hello, ${this.name}`; }    // correct
};
```

### Passing a Method as a Callback Without Binding

```javascript
setTimeout(user.greet, 1000);                  // this is lost
setTimeout(user.greet.bind(user), 1000);       // correct
setTimeout(() => user.greet(), 1000);          // also correct
```

### Calling a Getter Like a Function

```javascript
console.log(account.balance());    // TypeError, balance is not a function
console.log(account.balance);      // correct
```

### Forgetting new When Creating a Class Object

```javascript
const s = Student("Asha", [80]);        // TypeError
const s = new Student("Asha", [80]);    // correct
```

---

## Key Points

* A method is a function stored as an object property.
* Inside a method, `this` refers to the object that called it.
* The value of `this` depends on **how** a function is called, not where it is written.
* A method taken out of its object can lose `this`; fix it with `bind()` or an arrow wrapper.
* `call()` and `apply()` run a function immediately with a chosen `this`; `bind()` returns a new function.
* Arrow functions use `this` from the surrounding code, so they work well as callbacks inside methods.
* Do not use arrow functions as object methods.
* Getters and setters (`get` and `set`) run code when a property is read or assigned.
* Returning `this` from a method allows method chaining.
* Factory functions and classes create many similar objects.
