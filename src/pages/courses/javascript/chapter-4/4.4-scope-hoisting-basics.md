# Chapter 4: Functions and Scope

## Section 4: Scope and Hoisting Basics

**Scope** decides where a variable can be used. **Hoisting** describes how JavaScript prepares declarations before running the code. Understanding both helps you avoid some of the most confusing bugs.

---

## 1. What is Scope?

Scope is the area of a program where a variable is visible.

| Scope | Created by | Visible |
| --- | --- | --- |
| **Global** | Declared outside all functions and blocks | Everywhere |
| **Function** | Declared inside a function | Only inside that function |
| **Block** | `let` or `const` inside `{ }` | Only inside that block |

---

## 2. Global and Local Variables

```javascript
const globalMsg = "I am global";

function show() {
  const localMsg = "I am local";
  console.log(globalMsg);
  console.log(localMsg);
}

show();
console.log(typeof localMsg);
```

```output
I am global
I am local
undefined
```

A function can read global variables. A local variable cannot be used outside its function, so `typeof localMsg` is `undefined`.

---

## 3. Shadowing

If a local variable has the same name as a global one, the local one **shadows** (hides) the global one inside the function.

```javascript
let x = 10;

function demo() {
  let x = 5;
  console.log("Inside:", x);
}

demo();
console.log("Outside:", x);
```

```output
Inside: 5
Outside: 10
```

---

## 4. Block Scope

Variables created with `let` and `const` live only inside the nearest `{ }`. Variables created with `var` ignore blocks.

```javascript
if (true) {
  const a = 1;
  let b = 2;
  var c = 3;
}

console.log(c);
console.log(typeof a);
console.log(typeof b);
```

```output
3
undefined
undefined
```

This also applies to loops.

```javascript
for (var i = 0; i < 3; i++) { }
for (let j = 0; j < 3; j++) { }

console.log(i);
console.log(typeof j);
```

```output
3
undefined
```

> 💡 This is one reason modern code avoids `var`. A `var` declared in a loop or `if` block is still visible after it.

---

## 5. The Scope Chain

When JavaScript looks for a variable, it starts in the current scope and moves **outward**, one level at a time, until it finds it. This is called the **scope chain**. Inner functions can see variables of outer functions, but not the other way around.

```javascript
const level1 = "outer";

function outer() {
  const level2 = "middle";

  function inner() {
    const level3 = "inner";
    console.log(level1, level2, level3);
  }

  inner();
}

outer();
```

```output
outer middle inner
```

---

## 6. Closures

A **closure** is created when an inner function remembers the variables of the function where it was created, even after that outer function has finished.

```javascript
function makeCounter() {
  let count = 0;

  return function () {
    count++;
    return count;
  };
}

const counter = makeCounter();
console.log(counter());
console.log(counter());
console.log(counter());
```

```output
1
2
3
```

`count` is not visible from outside, yet the returned function keeps using it. Each call to `makeCounter()` creates a separate, private `count`.

```javascript
function makeCounter() {
  let count = 0;
  return () => ++count;
}

const a = makeCounter();
const b = makeCounter();

console.log(a());
console.log(a());
console.log(b());
```

```output
1
2
1
```

---

## 7. What is Hoisting?

Before running your code, JavaScript scans each scope and registers the declarations. It seems as if declarations are moved to the top of their scope. This is called **hoisting**.

---

## 8. Hoisting of Function Declarations

Function declarations are fully hoisted, so they can be called anywhere in their scope.

```javascript
welcome();

function welcome() {
  console.log("Welcome!");
}
```

```output
Welcome!
```

---

## 9. Hoisting of `var`

With `var`, the **declaration** is hoisted but the **value** is not.

```javascript
function demo() {
  console.log(v);
  var v = 10;
  console.log(v);
}

demo();
```

```output
undefined
10
```

JavaScript treats this code as if it were written like this:

```javascript
function demo() {
  var v;
  console.log(v);
  v = 10;
  console.log(v);
}
```

---

## 10. Hoisting of `let` and `const`: The Temporal Dead Zone

`let` and `const` are also hoisted, but they cannot be used until their declaration line runs. The time between the start of the scope and the declaration is called the **temporal dead zone (TDZ)**.

```javascript
console.log(score);
let score = 90;
```

```output
ReferenceError: Cannot access 'score' before initialization
```

This is better than `var`, because the mistake is reported instead of silently giving `undefined`.

---

## 11. Hoisting with Function Expressions

A function stored in a variable follows the rules of the variable.

```javascript
console.log(typeof hello);
hello();

var hello = function () {
  return "Hi";
};
```

```output
undefined
TypeError: hello is not a function
```

The `console.log` line prints `undefined`, because `var hello` exists but has no value yet. Then `hello()` is called while `hello` is still `undefined`, which causes the error. With `const` or `let`, the error would be a `ReferenceError`.

---

## 12. Accidental Global Variables

Assigning a value to a name that was never declared creates a **global** variable. This is a common source of bugs.

```javascript
function bad() {
  leaked = 42;
}

bad();
console.log(leaked);
```

```output
42
```

Strict mode turns this mistake into an error.

```javascript
"use strict";

function bad() {
  leaked = 42;
}

bad();
```

```output
ReferenceError: leaked is not defined
```

---

## 13. Best Practices

* Declare variables with `const` or `let`, never leave them undeclared.
* Declare variables as close as possible to where they are used.
* Keep the number of global variables small.
* Avoid `var`.
* Declare variables at the top of their scope, before using them.
* Use clear names so shadowing does not confuse readers.

---

## Real-World Example 🌍

A bank account that keeps its balance **private** using a closure:

```javascript
function createAccount(initialBalance) {
  let balance = initialBalance;

  return {
    deposit(amount) {
      balance += amount;
      return balance;
    },
    getBalance() {
      return balance;
    }
  };
}

const account = createAccount(1000);

console.log(account.deposit(500));
console.log(account.getBalance());
console.log(account.balance);
```

```output
1500
1500
undefined
```

The balance can only be changed through `deposit()`. Code outside cannot touch the variable directly.

## Common Mistakes

### Using a Local Variable Outside Its Function

```javascript
function f() {
  const result = 10;
}

f();
console.log(result);    // ReferenceError
```

Return the value instead.

### Expecting `var` to Respect Blocks

```javascript
if (true) {
  var secret = "visible";
}
console.log(secret);    // "visible"
```

### Using a Variable Before Its Declaration

```javascript
console.log(total);    // ReferenceError with let and const
let total = 5;
```

### Forgetting `let` or `const`

```javascript
count = 5;    // creates an accidental global
```

### Relying on Global Variables Too Much

Globals can be changed from anywhere, which makes bugs hard to find. Pass values through parameters.

---

## Key Points

* Scope decides where a variable is visible: global, function or block.
* `let` and `const` are block-scoped; `var` is function-scoped.
* An inner scope can read outer variables, but not the reverse.
* JavaScript looks up variables through the scope chain.
* A closure lets a function remember variables from its outer function.
* Function declarations are fully hoisted; `var` is hoisted as `undefined`.
* `let` and `const` cannot be used before their declaration (temporal dead zone).
* Always declare variables, and use strict mode to catch mistakes.
