# Chapter 4: Functions and Scope

## Section 5: Callback Functions

A **callback** is a function that you pass to another function as an argument, so that the other function can call it later. Callbacks are everywhere in JavaScript: in events, timers, array methods and server requests.

---

## 1. Functions as Arguments

Because functions are values, you can pass them like any other argument.

```javascript
function greet(name, callback) {
  console.log("Hello, " + name);
  callback();
}

function done() {
  console.log("Greeting finished");
}

greet("Asha", done);
```

```output
Hello, Asha
Greeting finished
```

* `done` is the **callback function**.
* `greet` is the function that receives it and decides **when** to call it.
* Pass the function **name** without parentheses: `done`, not `done()`.

---

## 2. Anonymous and Arrow Callbacks

You do not need to name a callback. You can write it directly in the call.

```javascript
function greet(name, callback) {
  console.log("Hello, " + name);
  callback();
}

greet("Ravi", function () {
  console.log("Anonymous callback");
});

greet("Meena", () => {
  console.log("Arrow callback");
});
```

```output
Hello, Ravi
Anonymous callback
Hello, Meena
Arrow callback
```

---

## 3. Callbacks with Arguments

The function that receives a callback can pass data to it.

```javascript
function processOrder(item, onComplete) {
  console.log(`Processing ${item}...`);
  onComplete(item);
}

processOrder("Book", item => {
  console.log(`${item} has been shipped!`);
});
```

```output
Processing Book...
Book has been shipped!
```

---

## 4. Customizing Behavior with Callbacks

A callback lets one function do different things depending on what you pass.

```javascript
function calculate(a, b, operation) {
  return operation(a, b);
}

console.log(calculate(10, 5, (x, y) => x + y));
console.log(calculate(10, 5, (x, y) => x * y));
console.log(calculate(10, 5, Math.max));
```

```output
15
50
10
```

A function that takes another function as an argument is called a **higher-order function**. `calculate` is one.

---

## 5. Callbacks in Array Methods

Array methods use callbacks heavily. You will study them in detail in Chapter 5.

```javascript
const numbers = [1, 2, 3];

numbers.forEach(n => console.log(n * 10));

const doubled = numbers.map(n => n * 2);
const big = numbers.filter(n => n > 1);

console.log(doubled);
console.log(big);
```

```output
10
20
30
[ 2, 4, 6 ]
[ 2, 3 ]
```

* `forEach` runs the callback for every item.
* `map` builds a new array from the callback results.
* `filter` keeps the items for which the callback returns `true`.

### Sorting with a Callback

By default `sort()` compares items as **text**, which gives unexpected results for numbers. A comparison callback fixes that.

```javascript
const values = [30, 5, 100];

console.log([...values].sort());
console.log([...values].sort((a, b) => a - b));
console.log([...values].sort((a, b) => b - a));
```

```output
[ 100, 30, 5 ]
[ 5, 30, 100 ]
[ 100, 30, 5 ]
```

---

## 6. Synchronous vs Asynchronous Callbacks

* A **synchronous** callback runs immediately, as in `forEach` and `map`.
* An **asynchronous** callback runs **later**, after something finishes, such as a timer, a click or a network request.

`setTimeout(callback, delay)` calls a function after a delay in milliseconds.

```javascript
console.log("Start");

setTimeout(() => {
  console.log("Callback after 1 second");
}, 1000);

console.log("End");
```

```output
Start
End
Callback after 1 second
```

JavaScript does not wait for the timer. It continues with `End` and runs the callback when the time is up.

---

## 7. Callbacks for Events

When you add a click handler, you pass a callback that runs **each time** the button is clicked. Press **Run** and click the button.

```html
<!DOCTYPE html>
<html>
<body style="font-family: Arial, sans-serif; padding: 20px;">
  <button id="saveBtn">Save</button>
  <p id="status">Not saved yet</p>

  <script>
    document.getElementById("saveBtn").addEventListener("click", function () {
      const status = document.getElementById("status");
      status.textContent = "Saving...";

      setTimeout(function () {
        status.textContent = "Saved!";
      }, 1000);
    });
  </script>
</body>
</html>
```

There are two callbacks here: the click handler and the timer callback.

## 8. Error-First Callbacks

In Node.js, a common convention is to call the callback with an **error** as the first argument (or `null` if everything worked), followed by the result.

```javascript
function divide(a, b, callback) {
  if (b === 0) {
    callback(new Error("Cannot divide by zero"));
  } else {
    callback(null, a / b);
  }
}

function handle(error, result) {
  if (error) {
    console.log("Error: " + error.message);
  } else {
    console.log("Result: " + result);
  }
}

divide(10, 2, handle);
divide(5, 0, handle);
```

```output
Result: 5
Error: Cannot divide by zero
```

## 9. Callback Hell

When one asynchronous step depends on the previous one, callbacks get nested deeper and deeper. This pyramid shape is called **callback hell**.

```javascript
setTimeout(() => {
  console.log("Step 1 done");

  setTimeout(() => {
    console.log("Step 2 done");

    setTimeout(() => {
      console.log("Step 3 done");
    }, 300);
  }, 300);
}, 300);
```

```output
Step 1 done
Step 2 done
Step 3 done
```

Deep nesting is hard to read and to fix. Modern JavaScript solves this with **Promises** and **async/await**, which you will learn in Chapter 9.

---

## 10. Named Callbacks Improve Readability

Giving the callbacks names flattens the code.

```javascript
function step3() {
  console.log("Step 3 done");
}

function step2() {
  console.log("Step 2 done");
  setTimeout(step3, 300);
}

function step1() {
  console.log("Step 1 done");
  setTimeout(step2, 300);
}

setTimeout(step1, 300);
```

```output
Step 1 done
Step 2 done
Step 3 done
```

## Real-World Example 🌍

A small order system in which the payment step calls the next step when it finishes:

```javascript
function pay(amount, onSuccess) {
  console.log(`Paying ₹${amount}...`);

  setTimeout(() => {
    console.log("Payment received");
    onSuccess();
  }, 500);
}

function confirmOrder() {
  console.log("Order confirmed. Thank you!");
}

pay(999, confirmOrder);
console.log("Waiting for payment...");
```

```output
Paying ₹999...
Waiting for payment...
Payment received
Order confirmed. Thank you!
```

## Common Mistakes

### Calling the Callback Instead of Passing It

```javascript
setTimeout(greet(), 1000);    // greet runs now, and its result is passed
setTimeout(greet, 1000);      // correct
```

### Passing Arguments the Wrong Way

```javascript
setTimeout(greet("Asha"), 1000);          // wrong
setTimeout(() => greet("Asha"), 1000);    // correct, wrap it in an arrow function
```

### Forgetting That the Callback Runs Later

```javascript
let result;
setTimeout(() => { result = 42; }, 100);
console.log(result);    // undefined, because the callback has not run yet
```

### Calling a Callback That Was Not Provided

```javascript
function run(callback) {
  callback();    // TypeError if run() is called without an argument
}
```

Check first: `if (typeof callback === "function") { callback(); }`.

### Deeply Nested Callbacks

Use named functions now, and Promises later.

---

## Key Points

* A callback is a function passed as an argument to another function.
* Pass the function name without parentheses: `callback`, not `callback()`.
* A function that accepts a callback is a higher-order function.
* Callbacks power array methods such as `forEach`, `map`, `filter` and `sort`.
* Synchronous callbacks run immediately; asynchronous callbacks run later.
* `setTimeout(callback, delay)` runs a callback after a delay.
* Event handlers are callbacks that run when an event happens.
* Deeply nested callbacks are called callback hell; Promises and `async/await` solve it.
