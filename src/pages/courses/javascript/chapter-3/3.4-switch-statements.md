# Chapter 3: Operators and Control Flow

## Section 4: switch Statements

When you compare **one value** against many possible choices, a long `if...else if` chain becomes hard to read. The `switch` statement offers a cleaner way.

---

## 1. The `switch` Statement

**Syntax:**

```text
switch (expression) {
  case value1:
    // code
    break;
  case value2:
    // code
    break;
  default:
    // code when nothing matches
}
```

How it works:

1. The `expression` is evaluated once.
2. Its result is compared with each `case` value, from top to bottom.
3. When a match is found, that block runs.
4. `break` stops the switch. `default` runs if no case matches.

---

## 2. A Simple Example

```javascript
const day = 3;

switch (day) {
  case 1:
    console.log("Monday");
    break;
  case 2:
    console.log("Tuesday");
    break;
  case 3:
    console.log("Wednesday");
    break;
  default:
    console.log("Another day");
}
```

```output
Wednesday
```

---

## 3. The `default` Case

`default` runs when no `case` matches. It is like the `else` of a switch and is usually written last.

```javascript
const color = "purple";

switch (color) {
  case "red":
    console.log("Stop");
    break;
  case "green":
    console.log("Go");
    break;
  default:
    console.log("Unknown color");
}
```

```output
Unknown color
```

---

## 4. Why `break` Matters: Fall-Through

Without `break`, JavaScript continues running the **next** cases as well. This is called **fall-through**.

```javascript
const n = 1;

switch (n) {
  case 1:
    console.log("One");
  case 2:
    console.log("Two");
    break;
  case 3:
    console.log("Three");
}
```

```output
One
Two
```

`case 1` had no `break`, so the code of `case 2` also ran.

---

## 5. Grouping Cases

Fall-through is useful when several cases should run the same code.

```javascript
const month = 4;

switch (month) {
  case 12:
  case 1:
  case 2:
    console.log("Winter");
    break;
  case 3:
  case 4:
  case 5:
    console.log("Spring");
    break;
  default:
    console.log("Another season");
}
```

```output
Spring
```

---

## 6. `switch` Uses Strict Comparison

`switch` compares with `===`. The value and the type must match.

```javascript
const value = "1";

switch (value) {
  case 1:
    console.log("Number one");
    break;
  case "1":
    console.log("String one");
    break;
  default:
    console.log("No match");
}
```

```output
String one
```

If the cases only had the number `1`, the string `"1"` would not match.

---

## 7. Using Strings

```javascript
const fruit = "mango";

switch (fruit) {
  case "apple":
    console.log("Apples cost 120 per kg");
    break;
  case "mango":
    console.log("Mangoes cost 90 per kg");
    break;
  default:
    console.log("Fruit not available");
}
```

```output
Mangoes cost 90 per kg
```

---

## 8. `switch (true)` for Ranges

A `case` compares exact values, so ranges need a trick: switch on `true` and use conditions as cases.

```javascript
const marks = 82;

switch (true) {
  case marks >= 90:
    console.log("Grade A+");
    break;
  case marks >= 75:
    console.log("Grade A");
    break;
  case marks >= 60:
    console.log("Grade B");
    break;
  default:
    console.log("Needs improvement");
}
```

```output
Grade A
```

For ranges, an `if...else if` chain is often clearer.

---

## 9. Returning Values with `switch`

Inside a function, `return` can replace `break`.

```javascript
function getDayName(n) {
  switch (n) {
    case 1: return "Monday";
    case 2: return "Tuesday";
    case 3: return "Wednesday";
    default: return "Unknown";
  }
}

console.log(getDayName(2));
console.log(getDayName(9));
```

```output
Tuesday
Unknown
```

---

## 10. `switch` vs `if...else if`

| Use `switch` when | Use `if...else if` when |
| --- | --- |
| Comparing one value to many exact values | Checking ranges or complex conditions |
| Choices are fixed, such as days or menu options | Different variables are compared |
| You want cleaner, flatter code | You need `&&` and `||` in conditions |

---

## Real-World Example

A simple calculator that uses `switch` on the operator:

```javascript
const a = 10;
const b = 5;
const operator = prompt("Enter an operator (+, -, *, /):");

switch (operator) {
  case "+":
    console.log("Result:", a + b);
    break;
  case "-":
    console.log("Result:", a - b);
    break;
  case "*":
    console.log("Result:", a * b);
    break;
  case "/":
    console.log("Result:", a / b);
    break;
  default:
    console.log("Invalid operator");
}
```

If the user enters:

```text
*
```

The output will be:

```output
Result: 50
```

## Common Mistakes

### Forgetting `break`

```javascript
case 1:
  console.log("One");
  // missing break, so the next case also runs
```

### Expecting Type Conversion

`switch ("5")` does not match `case 5`, because `===` is used.

### Using Ranges in `case`

```javascript
case marks > 50:    // compares marks with true, not what you expect
```

Use `switch (true)` or an `if` chain.

### Duplicate Case Values

Only the first matching `case` runs, so duplicates are useless.

### Putting `default` in the Middle Without `break`

`default` can appear anywhere, but without `break` it falls through to the next case. Place it last.

---

## Key Points

* `switch` compares one expression against many `case` values.
* The comparison uses strict equality `===`.
* `break` ends the switch; without it, execution falls through to the next case.
* `default` runs when no case matches.
* Stack several `case` labels to share one block of code.
* Use `switch (true)` for simple ranges, or prefer `if...else if`.
* Inside functions, `return` can replace `break`.
