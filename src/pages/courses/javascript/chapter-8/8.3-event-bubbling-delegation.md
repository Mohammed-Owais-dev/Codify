# Chapter 8: Forms, Validation and Browser Storage

## Section 3: Event Bubbling and Delegation

When an event happens on an element, it does not stay there. It travels through the DOM tree, passing through the element's parents. Understanding this journey lets you write less code and handle elements that are created later, using a technique called **event delegation**.

---

## 1. How Events Travel

An event moves in **three phases**:

```text
1. Capturing phase : window → document → html → body → div → button   (down)
2. Target phase    : the event reaches the clicked element (button)
3. Bubbling phase  : button → div → body → html → document → window   (up)
```

* **Capturing** goes from the top of the tree down to the target.
* **Bubbling** goes from the target back up to the top.
* By default, `addEventListener()` listens during the **bubbling** phase.

---

## 2. Event Bubbling

When you click the inner element, the listeners of its parents run too.

```html
<!DOCTYPE html>
<html>
<body style="font-family: Arial, sans-serif; padding: 20px;">
  <div id="outer" style="padding:24px; background:#bfdbfe;">
    Outer div
    <div id="middle" style="padding:24px; background:#fde68a;">
      Middle div
      <button id="inner">Inner button</button>
    </div>
  </div>
  <pre id="log"></pre>

  <script>
    const log = document.getElementById("log");

    function report(name) {
      return () => { log.textContent += "Clicked: " + name + "\n"; };
    }

    document.getElementById("inner").addEventListener("click", report("button"));
    document.getElementById("middle").addEventListener("click", report("middle div"));
    document.getElementById("outer").addEventListener("click", report("outer div"));
  </script>
</body>
</html>
```

Click the button and you will see:

```output
Clicked: button
Clicked: middle div
Clicked: outer div
```

The event **bubbled up** from the button through its parents.

## 3. `event.target` vs `event.currentTarget`

| Property              | Meaning                                                 |
| --------------------- | ------------------------------------------------------- |
| `event.target`        | The **exact element** that was clicked (the origin)     |
| `event.currentTarget` | The element **whose listener is running** right now     |

```javascript
document.querySelector("#outer").addEventListener("click", event => {
  console.log("target:", event.target.id);
  console.log("currentTarget:", event.currentTarget.id);
});
```

```output
target: inner
currentTarget: outer
```

This output appears when the inner button is clicked. The listener belongs to `outer`, but the click started on `inner`.

---

## 4. Stopping Propagation

`event.stopPropagation()` stops the event from continuing to the parents.

```javascript
document.querySelector("#inner").addEventListener("click", event => {
  event.stopPropagation();
  console.log("Only the button handler runs");
});

document.querySelector("#outer").addEventListener("click", () => {
  console.log("Outer handler");   // not reached when the button is clicked
});
```

```output
Only the button handler runs
```

> **Warning:** Use `stopPropagation()` sparingly. It can break other code that relies on seeing the event, such as analytics, dropdown closers and delegated handlers.

---

## 5. Bubbling vs Default Behavior

These two are **different** and often confused.

| Method                    | Stops                                         |
| ------------------------- | --------------------------------------------- |
| `event.preventDefault()`  | The browser's default action (following a link, submitting a form) |
| `event.stopPropagation()` | The event from travelling up to parent elements |

Calling one does not call the other.

---

## 6. Capturing Phase (Optional)

Pass `true` (or `{ capture: true }`) as the third argument to listen during the capturing phase instead.

```javascript
const outer = document.querySelector("#outer");
const inner = document.querySelector("#inner");

outer.addEventListener("click", () => console.log("outer (capture)"), true);
inner.addEventListener("click", () => console.log("inner (bubble)"));
outer.addEventListener("click", () => console.log("outer (bubble)"));
```

```output
outer (capture)
inner (bubble)
outer (bubble)
```

Capturing is rarely needed, but it shows the full order of events.

## 7. The Problem: Many Listeners

Imagine a list with many items. Adding a listener to each one works, but has drawbacks.

```javascript
document.querySelectorAll("#list li").forEach(item => {
  item.addEventListener("click", () => {
    console.log("Clicked " + item.textContent);
  });
});
```

* It creates **one listener per item**, which wastes memory for long lists.
* Items **added later** (with `append()`) do **not** have a listener.

Event delegation solves both problems.

---

## 8. Event Delegation

With **delegation**, you add **one listener to the parent** and use bubbling to catch clicks from all the children. `event.target` tells you which child was clicked.

```html
<!DOCTYPE html>
<html>
<body style="font-family: Arial, sans-serif; padding: 20px;">
  <ul id="list">
    <li>HTML</li>
    <li>CSS</li>
    <li>JavaScript</li>
  </ul>
  <button id="addBtn">Add item</button>
  <p id="picked">Click an item</p>

  <script>
    const list = document.getElementById("list");

    list.addEventListener("click", event => {
      if (event.target.tagName === "LI") {
        document.getElementById("picked").textContent =
          "You clicked: " + event.target.textContent;
      }
    });

    let count = 1;
    document.getElementById("addBtn").addEventListener("click", () => {
      const li = document.createElement("li");
      li.textContent = "New item " + count++;
      list.append(li);
    });
  </script>
</body>
</html>
```

Items added with the button work immediately, because the listener is on the **parent**, not on each item.

## 9. Using `closest()` for Reliable Delegation

If the clicked element contains **child elements** (like an icon or `<span>` inside a button), `event.target` may be the inner element. `closest()` finds the correct ancestor.

```javascript
const list = document.querySelector("#tasks");

list.addEventListener("click", event => {
  const deleteBtn = event.target.closest(".delete");

  if (deleteBtn && list.contains(deleteBtn)) {
    deleteBtn.closest("li").remove();
  }
});
```

`event.target.closest(".delete")` returns the nearest element with class `delete`, whether the click landed on the button itself or on something inside it. It returns `null` if there is no match.

## 10. Delegation with `data-` Attributes

Use `data-action` attributes to let one handler manage several different buttons.

```html
<!DOCTYPE html>
<html>
<body style="font-family: Arial, sans-serif; padding: 20px;">
  <div id="toolbar">
    <button data-action="save">Save</button>
    <button data-action="edit">Edit</button>
    <button data-action="delete">Delete</button>
  </div>
  <p id="status">No action yet</p>

  <script>
    document.getElementById("toolbar").addEventListener("click", event => {
      const button = event.target.closest("button");
      if (!button) return;

      const action = button.dataset.action;
      const messages = {
        save: "Saving...",
        edit: "Editing...",
        delete: "Deleting..."
      };

      document.getElementById("status").textContent = messages[action];
    });
  </script>
</body>
</html>
```

## 11. Events That Do Not Bubble

Most events bubble, but a few do not.

| Event                  | Bubbles? | Note                                  |
| ---------------------- | -------- | ------------------------------------- |
| `click`, `input`, `keydown`, `submit` | Yes | Work well with delegation   |
| `focus`, `blur`        | No       | Use `focusin` / `focusout` for delegation |
| `mouseenter`, `mouseleave` | No   | Use `mouseover` / `mouseout` instead  |

## Real-World Example

A shopping cart where items can be added, removed and quantity-adjusted, all through **one** delegated listener:

```html
<!DOCTYPE html>
<html>
<body style="font-family: Arial, sans-serif; padding: 20px; max-width: 360px;">
  <h3>Shopping Cart</h3>
  <ul id="cart" style="list-style:none; padding:0;">
    <li data-price="499">Keyboard — ₹499
      <button data-action="remove">Remove</button></li>
    <li data-price="299">Mouse — ₹299
      <button data-action="remove">Remove</button></li>
    <li data-price="799">Headset — ₹799
      <button data-action="remove">Remove</button></li>
  </ul>
  <p><strong>Total: ₹<span id="total">0</span></strong></p>
  <button id="addItem">Add Webcam (₹999)</button>

  <script>
    const cart = document.getElementById("cart");
    const total = document.getElementById("total");

    function updateTotal() {
      let sum = 0;
      cart.querySelectorAll("li").forEach(li => {
        sum += Number(li.dataset.price);
      });
      total.textContent = sum;
    }

    cart.addEventListener("click", event => {
      const button = event.target.closest("[data-action='remove']");
      if (!button) return;

      button.closest("li").remove();
      updateTotal();
    });

    document.getElementById("addItem").addEventListener("click", () => {
      const li = document.createElement("li");
      li.dataset.price = "999";
      li.innerHTML = 'Webcam — ₹999 <button data-action="remove">Remove</button>';
      cart.append(li);
      updateTotal();
    });

    updateTotal();
  </script>
</body>
</html>
```

The newly added webcam can be removed straight away, because the click listener lives on the `<ul>`.

## Common Mistakes

### Confusing `target` and `currentTarget`

`event.target` is the clicked element. `event.currentTarget` is the element that owns the listener. In a delegated handler, they are usually different.

### Checking `target.tagName` When Children Exist

```javascript
if (event.target.tagName === "BUTTON") { }     // fails if the click lands on an <i> or <span> inside the button
const btn = event.target.closest("button");    // reliable
```

### Overusing `stopPropagation()`

Stopping propagation hides events from other listeners and can create hard-to-find bugs. Use it only when you truly need it.

### Delegating to an Element That Is Replaced

If you replace the parent element itself (for example, with `innerHTML` on its own parent), its listener is lost. Attach the listener to a container that stays on the page.

### Expecting `focus` to Bubble

`focus` and `blur` do not bubble. Use `focusin` and `focusout` for delegation.

### Forgetting the Click Might Be Outside Any Item

Clicking the empty space of the parent also triggers the handler. Always check that `closest()` found something before using it.

---

## Key Points

* Events travel in three phases: capturing, target and bubbling.
* By default, listeners run during the bubbling phase, from the target up to its parents.
* `event.target` is the element where the event started; `event.currentTarget` is the element with the listener.
* `stopPropagation()` stops bubbling; `preventDefault()` stops the default action. They are different.
* Event delegation uses **one listener on a parent** to handle many children.
* Delegation works for elements added later and uses less memory.
* Use `event.target.closest(selector)` to find the right element reliably.
* `data-action` attributes let one handler manage many buttons.
* `focus`, `blur`, `mouseenter` and `mouseleave` do not bubble.
