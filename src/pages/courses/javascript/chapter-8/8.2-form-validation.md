# Chapter 8: Forms, Validation and Browser Storage

## Section 2: Form Validation

**Form validation** checks that the data a user enters is complete and correct **before** it is used or sent to a server. Good validation prevents mistakes and gives users clear, helpful feedback.

---

## 1. Why Validate?

* Users forget required fields or make typing mistakes.
* Wrong data (an invalid email, a too-short password) causes problems later.
* Clear messages help users fix problems quickly.

> ⚠️ **Warning:** JavaScript validation improves the user experience, but it can be bypassed. A real website must **always validate again on the server**.

There are two layers you can use in the browser: **built-in HTML validation** and **custom JavaScript validation**.

---

## 2. Built-in HTML Validation

HTML attributes can validate fields automatically, with no JavaScript.

| Attribute     | Purpose                                    | Example                         |
| ------------- | ------------------------------------------ | ------------------------------- |
| `required`    | The field cannot be empty                  | `<input required>`              |
| `type="email"`| Must look like an email address            | `<input type="email">`          |
| `minlength`   | Minimum number of characters               | `<input minlength="6">`         |
| `maxlength`   | Maximum number of characters               | `<input maxlength="20">`        |
| `min` / `max` | Smallest / largest number or date          | `<input type="number" min="18">` |
| `pattern`     | Must match a regular expression            | `<input pattern="[0-9]{10}">`   |

```html
<!DOCTYPE html>
<html>
<body style="font-family: Arial, sans-serif; padding: 20px;">
  <form>
    <p><input type="text" placeholder="Name (required)" required></p>
    <p><input type="email" placeholder="Email" required></p>
    <p><input type="number" placeholder="Age (18 to 60)" min="18" max="60"></p>
    <p><input type="text" placeholder="10-digit phone" pattern="[0-9]{10}" title="Enter exactly 10 digits"></p>
    <button type="submit">Submit</button>
  </form>
</body>
</html>
```

Try submitting with empty or wrong values. The browser shows its own message and blocks submission.

## 3. The Constraint Validation API

Every form control has methods and properties for checking validity in JavaScript.

| Member                    | Description                                          |
| ------------------------- | ---------------------------------------------------- |
| `input.checkValidity()`   | Returns `true` if the field passes all rules         |
| `input.validity`          | An object describing exactly which rule failed       |
| `input.validationMessage` | The browser's error text                             |
| `input.setCustomValidity(msg)` | Sets your own error message (empty string = valid) |
| `form.checkValidity()`    | `true` if **every** field is valid                   |
| `form.reportValidity()`   | Checks the form and shows the browser's messages     |

```javascript
// <input id="age" type="number" min="18" max="60" required>
const age = document.querySelector("#age");

age.value = "10";
console.log(age.checkValidity());
console.log(age.validity.rangeUnderflow);

age.value = "25";
console.log(age.checkValidity());
```

```output
false
true
true
```

Useful `validity` flags: `valueMissing`, `typeMismatch`, `tooShort`, `tooLong`, `rangeUnderflow`, `rangeOverflow`, `patternMismatch`.

## 4. Custom Validation with JavaScript

For rules that HTML cannot express, such as "passwords must match", write your own checks and show your own messages.

```html
<!DOCTYPE html>
<html>
<body style="font-family: Arial, sans-serif; padding: 20px;">
  <form id="form" novalidate>
    <p>
      <input id="username" type="text" placeholder="Username">
      <br><small id="usernameError" style="color:#dc2626;"></small>
    </p>
    <button type="submit">Register</button>
  </form>
  <p id="success" style="color:#16a34a;"></p>

  <script>
    const form = document.getElementById("form");
    const username = document.getElementById("username");
    const error = document.getElementById("usernameError");
    const success = document.getElementById("success");

    form.addEventListener("submit", event => {
      event.preventDefault();
      success.textContent = "";

      const value = username.value.trim();

      if (value === "") {
        error.textContent = "Username is required.";
      } else if (value.length < 4) {
        error.textContent = "Username must be at least 4 characters.";
      } else {
        error.textContent = "";
        success.textContent = "Registered as " + value + "!";
      }
    });
  </script>
</body>
</html>
```

The `novalidate` attribute on the form turns off the browser's built-in messages so that you can show your own.

## 5. Validating with Regular Expressions

A **regular expression** (regex) describes a pattern. `regex.test(text)` returns `true` or `false`.

```javascript
const emailPattern = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
const phonePattern = /^[0-9]{10}$/;

console.log(emailPattern.test("asha@example.com"));
console.log(emailPattern.test("asha@example"));
console.log(phonePattern.test("9876543210"));
console.log(phonePattern.test("98765"));
```

```output
true
false
true
false
```

| Pattern         | Meaning                                      |
| --------------- | -------------------------------------------- |
| `^` and `$`     | Start and end of the text                    |
| `[0-9]`         | Any one digit                                |
| `{10}`          | Exactly 10 times                             |
| `[^\s@]+`       | One or more characters that are not spaces or `@` |
| `\.`            | A literal dot                                |

## 6. Reusable Validation Functions

Keep each rule in a small function that returns an error message (or an empty string if the value is valid).

```javascript
function validateEmail(email) {
  const pattern = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  if (email === "") return "Email is required.";
  if (!pattern.test(email)) return "Enter a valid email address.";
  return "";
}

function validatePassword(password) {
  if (password.length < 8) return "Password must be at least 8 characters.";
  if (!/[0-9]/.test(password)) return "Password must contain a number.";
  if (!/[A-Z]/.test(password)) return "Password must contain an uppercase letter.";
  return "";
}

console.log(validateEmail("asha@example.com") === "");
console.log(validateEmail("asha@"));
console.log(validatePassword("abc"));
console.log(validatePassword("Secret123") === "");
```

```output
true
Enter a valid email address.
Password must be at least 8 characters.
true
```

## 7. Validating While the User Types

Validate on `blur` (when the user leaves the field) or `input` (while typing) to give instant feedback.

```html
<!DOCTYPE html>
<html>
<head>
  <style>
    input { padding: 6px; border: 2px solid #94a3b8; border-radius: 6px; }
    input.invalid { border-color: #dc2626; }
    input.valid { border-color: #16a34a; }
    .error { color: #dc2626; font-size: 13px; min-height: 18px; }
  </style>
</head>
<body style="font-family: Arial, sans-serif; padding: 20px;">
  <input id="email" type="text" placeholder="Email">
  <div id="emailError" class="error"></div>

  <script>
    const email = document.getElementById("email");
    const emailError = document.getElementById("emailError");
    const pattern = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

    email.addEventListener("input", () => {
      const ok = pattern.test(email.value.trim());

      email.classList.toggle("valid", ok);
      email.classList.toggle("invalid", !ok);
      emailError.textContent = ok ? "" : "Enter a valid email address.";
    });
  </script>
</body>
</html>
```

> 💡 **Tip:** Avoid showing an error before the user has had a chance to type. Validating on `blur` or on submit feels friendlier than validating on the very first keystroke.

## 8. Confirming Passwords

Checking that two fields match is a classic custom rule.

```javascript
function passwordsMatch(password, confirm) {
  return password !== "" && password === confirm;
}

console.log(passwordsMatch("Secret123", "Secret123"));
console.log(passwordsMatch("Secret123", "secret123"));
console.log(passwordsMatch("", ""));
```

```output
true
false
false
```

## 9. Making Errors Accessible

Error messages should be available to screen readers too.

```html
<label for="mail">Email</label>
<input id="mail" type="email" aria-describedby="mailError" aria-invalid="true">
<p id="mailError" role="alert">Enter a valid email address.</p>
```

* `aria-describedby` links the field to its message.
* `aria-invalid="true"` tells assistive technology the value is wrong.
* `role="alert"` makes the message announced when it appears.

## 10. Validating the Whole Form

When the user submits, check all fields, collect the errors, and only continue if there are none.

```html
<!DOCTYPE html>
<html>
<body style="font-family: Arial, sans-serif; padding: 20px; max-width: 320px;">
  <form id="signup" novalidate>
    <p><input id="email" type="text" placeholder="Email" style="width:100%"></p>
    <p><input id="password" type="password" placeholder="Password" style="width:100%"></p>
    <p><input id="confirm" type="password" placeholder="Confirm password" style="width:100%"></p>
    <button type="submit">Sign Up</button>
  </form>
  <ul id="errors" style="color:#dc2626;"></ul>
  <p id="ok" style="color:#16a34a;"></p>

  <script>
    document.getElementById("signup").addEventListener("submit", event => {
      event.preventDefault();

      const email = document.getElementById("email").value.trim();
      const password = document.getElementById("password").value;
      const confirm = document.getElementById("confirm").value;

      const errors = [];
      if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) errors.push("Enter a valid email.");
      if (password.length < 8) errors.push("Password needs at least 8 characters.");
      if (password !== confirm) errors.push("Passwords do not match.");

      const list = document.getElementById("errors");
      list.innerHTML = "";
      errors.forEach(message => {
        const li = document.createElement("li");
        li.textContent = message;
        list.append(li);
      });

      document.getElementById("ok").textContent =
        errors.length === 0 ? "Account created successfully!" : "";
    });
  </script>
</body>
</html>
```

## Real-World Example 🌍

A login form that validates both fields, marks the wrong one and moves the cursor to it:

```html
<!DOCTYPE html>
<html>
<head>
  <style>
    .field { margin-bottom: 14px; }
    input { width: 100%; padding: 8px; border: 2px solid #94a3b8; border-radius: 6px; box-sizing: border-box; }
    input.invalid { border-color: #dc2626; }
    .error { color: #dc2626; font-size: 13px; min-height: 16px; }
  </style>
</head>
<body style="font-family: Arial, sans-serif; padding: 20px; max-width: 320px;">
  <h3>Log In</h3>
  <form id="login" novalidate>
    <div class="field">
      <input id="mail" type="text" placeholder="Email">
      <div class="error" id="mailErr"></div>
    </div>
    <div class="field">
      <input id="pass" type="password" placeholder="Password">
      <div class="error" id="passErr"></div>
    </div>
    <button type="submit">Log In</button>
  </form>
  <p id="result"></p>

  <script>
    function setError(input, errorBox, message) {
      errorBox.textContent = message;
      input.classList.toggle("invalid", message !== "");
      return message === "";
    }

    document.getElementById("login").addEventListener("submit", event => {
      event.preventDefault();

      const mail = document.getElementById("mail");
      const pass = document.getElementById("pass");

      const mailOk = setError(
        mail,
        document.getElementById("mailErr"),
        /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(mail.value.trim()) ? "" : "Enter a valid email."
      );
      const passOk = setError(
        pass,
        document.getElementById("passErr"),
        pass.value.length >= 8 ? "" : "Password must be 8+ characters."
      );

      if (!mailOk) mail.focus();
      else if (!passOk) pass.focus();

      document.getElementById("result").textContent =
        mailOk && passOk ? "Login successful!" : "";
    });
  </script>
</body>
</html>
```

## Common Mistakes

### Relying Only on Browser-Side Validation

Users can edit or disable JavaScript. Always validate again on the server.

### Forgetting `novalidate` When Using Custom Messages

Without `novalidate`, the browser's own messages appear first and may stop your handler from running.

### Not Trimming Before Checking

```javascript
if (name === "") { }          // "   " passes as filled
if (name.trim() === "") { }   // correct
```

### Using a Regex Without `^` and `$`

```javascript
/[0-9]{10}/.test("abc1234567890xyz");    // true, matches a part of the text
/^[0-9]{10}$/.test("abc1234567890xyz");  // false, the whole text must match
```

### Vague Error Messages

"Invalid input" does not help. Say what is wrong and how to fix it: "Password must contain at least one number."

### Showing Errors Only with Color

Use text messages as well, because some users cannot distinguish colors.

---

## Key Points

* Validation checks that user input is complete and correct.
* HTML attributes such as `required`, `minlength`, `min`, `max` and `pattern` give free validation.
* `checkValidity()`, `validity` and `setCustomValidity()` let JavaScript use the browser's validation.
* Use `novalidate` when you show your own error messages.
* Regular expressions with `.test()` check formats such as email and phone numbers.
* Write small, reusable validation functions that return an error message.
* Validate on submit, and optionally on `blur` or `input` for instant feedback.
* Use `trim()` before checking for empty values.
* Make errors accessible with text, `aria-describedby` and `role="alert"`.
* Always validate again on the server.
