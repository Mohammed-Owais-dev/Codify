# Chapter 8: Forms, Validation and Browser Storage

## Section 4: localStorage and sessionStorage

Normally, when a user refreshes a page, all the JavaScript variables disappear. The **Web Storage API** lets you save small pieces of data **inside the user's browser**, so a theme, a draft or a to-do list can survive a page refresh.

---

## 1. Two Kinds of Web Storage

| Feature        | `localStorage`                          | `sessionStorage`                     |
| -------------- | --------------------------------------- | ------------------------------------ |
| Lifetime       | Stays until you delete it               | Cleared when the **tab** is closed   |
| Survives refresh | Yes                                   | Yes                                  |
| Shared between tabs | Yes (same website)                 | No (each tab has its own copy)       |
| Typical use    | Theme, saved lists, user settings       | Temporary form steps, one-visit data |
| Size limit     | About 5 MB per website                  | About 5 MB per website               |

Both have **exactly the same methods**, so learning one teaches you both.

---

## 2. The Storage Methods

| Method                  | Purpose                                  |
| ----------------------- | ---------------------------------------- |
| `setItem(key, value)`   | Saves a value under a key                |
| `getItem(key)`          | Reads a value (or `null` if missing)     |
| `removeItem(key)`       | Deletes one item                         |
| `clear()`               | Deletes **all** items                    |
| `key(index)`            | Returns the key at a position            |
| `length`                | Number of stored items                   |

```javascript
localStorage.setItem("username", "Asha");
localStorage.setItem("theme", "dark");

console.log(localStorage.getItem("username"));
console.log(localStorage.getItem("language"));
console.log(localStorage.length);

localStorage.removeItem("theme");
console.log(localStorage.length);

localStorage.clear();
console.log(localStorage.length);
```

```output
Asha
null
2
1
0
```

---

## 3. Seeing Your Data in DevTools

Press `F12`, open the **Application** tab (**Storage** in Firefox) and choose **Local Storage** or **Session Storage** in the left panel. You can view, edit and delete items there, which is very useful for debugging.

---

## 4. Bracket and Dot Shortcuts

Storage objects also work like normal objects.

```javascript
localStorage.city = "Hyderabad";
localStorage["country"] = "India";

console.log(localStorage.city);
console.log(localStorage["country"]);
```

```output
Hyderabad
India
```

> 💡 **Tip:** Stick to `setItem()` and `getItem()`. They are clearer and avoid problems if a key has the same name as a built-in property such as `length`.

---

## 5. Storage Saves Only Strings

Everything you save is **converted to a string**. Numbers and booleans come back as text.

```javascript
localStorage.setItem("score", 95);
localStorage.setItem("passed", true);

const score = localStorage.getItem("score");

console.log(score);
console.log(typeof score);
console.log(score + 5);
console.log(Number(score) + 5);
console.log(localStorage.getItem("passed") === "true");
```

```output
95
string
955
100
true
```

---

## 6. Saving Objects and Arrays with JSON

Objects and arrays would become the useless text `"[object Object]"`. Convert them with **`JSON.stringify()`** before saving and **`JSON.parse()`** after reading.

```javascript
const user = { name: "Asha", age: 21, skills: ["HTML", "CSS"] };

localStorage.setItem("user", JSON.stringify(user));

const saved = JSON.parse(localStorage.getItem("user"));

console.log(saved.name);
console.log(saved.skills[1]);
console.log(Array.isArray(saved.skills));
```

```output
Asha
CSS
true
```

| Function             | Direction                       |
| -------------------- | ------------------------------- |
| `JSON.stringify(x)`  | JavaScript value → JSON string  |
| `JSON.parse(text)`   | JSON string → JavaScript value  |

---

## 7. Handling Missing Data

`getItem()` returns `null` when the key does not exist, and `JSON.parse(null)` returns `null`. Always provide a default.

```javascript
const tasks = JSON.parse(localStorage.getItem("tasks")) || [];
const theme = localStorage.getItem("theme") ?? "light";

console.log(tasks);
console.log(theme);
```

```output
[]
light
```

---

## 8. Helper Functions

Wrapping storage in small functions keeps the rest of your code clean.

```javascript
function save(key, value) {
  localStorage.setItem(key, JSON.stringify(value));
}

function load(key, fallback = null) {
  const raw = localStorage.getItem(key);
  if (raw === null) return fallback;

  try {
    return JSON.parse(raw);
  } catch {
    return fallback;
  }
}

save("settings", { fontSize: 18, notifications: true });

console.log(load("settings"));
console.log(load("missing", "default value"));
```

```output
{ fontSize: 18, notifications: true }
default value
```

The `try...catch` protects your page if the stored text is damaged or was not saved with `JSON.stringify()`.

---

## 9. `sessionStorage`

`sessionStorage` works the same way, but its data lives only while the **tab** is open.

```javascript
sessionStorage.setItem("visitStart", "10:30 AM");
sessionStorage.setItem("step", "2");

console.log(sessionStorage.getItem("visitStart"));
console.log(sessionStorage.getItem("step"));
```

```output
10:30 AM
2
```

Close the tab and reopen the page, and these values are gone. A page **refresh** keeps them.

---

## 10. Looping Through All Stored Items

```javascript
localStorage.setItem("a", "1");
localStorage.setItem("b", "2");
localStorage.setItem("c", "3");

for (let i = 0; i < localStorage.length; i++) {
  const key = localStorage.key(i);
  console.log(key + " = " + localStorage.getItem(key));
}
```

```output
a = 1
b = 2
c = 3
```

The order of keys is not guaranteed, so do not rely on it.

---

## 11. Handling Storage Errors

Storage can fail. The browser may block it (private mode or strict privacy settings), or the 5 MB limit may be reached. Wrap important calls in `try...catch`.

```javascript
function safeSave(key, value) {
  try {
    localStorage.setItem(key, JSON.stringify(value));
    return true;
  } catch (error) {
    console.log("Could not save:", error.name);
    return false;
  }
}

console.log(safeSave("notes", ["Learn storage"]));
```

```output
true
```

If storage is unavailable or full, the function prints a message such as `Could not save: QuotaExceededError` and returns `false`.

---

## 12. The `storage` Event

When one tab changes `localStorage`, **other tabs** of the same site are notified through the `storage` event. This lets tabs stay in sync, for example when the user logs out in one tab.

```javascript
window.addEventListener("storage", event => {
  console.log("Changed key:", event.key);
  console.log("Old value:", event.oldValue);
  console.log("New value:", event.newValue);
});
```

The event fires in the **other** tabs, not in the tab that made the change.

---

## 13. What Not to Store

> **Warning:** Web Storage is **not secure**. Any JavaScript running on your page can read it, and users can view and edit it in DevTools. **Never store passwords, credit card numbers or secret tokens** in `localStorage` or `sessionStorage`.

Also remember:

* Storage belongs to one **origin** (protocol + domain + port). Another website cannot read it.
* It is only for **small** amounts of data, about 5 MB. Use IndexedDB for larger data.
* The browser stores it only on **that device and browser**. It does not follow the user to another computer.

---

## 14. Storage vs Cookies

| Feature               | Web Storage             | Cookies                         |
| --------------------- | ----------------------- | ------------------------------- |
| Capacity              | About 5 MB              | About 4 KB                      |
| Sent to the server automatically | No           | Yes, with every request         |
| Expiry date           | No (local) / tab (session) | Can be set                   |
| Easy to use in JS     | Yes                     | More awkward                    |

## Real-World Example

A notes box that **remembers what you typed**, even after a refresh. The `try...catch` helpers keep the page working when storage is blocked, which can happen in an embedded preview.

```html
<!DOCTYPE html>
<html>
<body style="font-family: Arial, sans-serif; padding: 20px; max-width: 360px;">
  <h3>My Notes</h3>
  <textarea id="notes" rows="5" style="width:100%" placeholder="Write something..."></textarea>
  <p><button id="clearBtn">Clear Notes</button></p>
  <p id="status" style="color:#475569; font-size:14px;"></p>

  <script>
    const memory = {};

    function readNotes() {
      try {
        return localStorage.getItem("notes") ?? "";
      } catch {
        return memory.notes ?? "";
      }
    }

    function writeNotes(text) {
      try {
        localStorage.setItem("notes", text);
      } catch {
        memory.notes = text;
      }
    }

    const notes = document.getElementById("notes");
    const status = document.getElementById("status");

    notes.value = readNotes();

    notes.addEventListener("input", () => {
      writeNotes(notes.value);
      status.textContent = "Saved (" + notes.value.length + " characters)";
    });

    document.getElementById("clearBtn").addEventListener("click", () => {
      notes.value = "";
      writeNotes("");
      status.textContent = "Notes cleared";
    });
  </script>
</body>
</html>
```

> 💡 **Tip:** Some live previews run your code in a restricted sandbox where `localStorage` is blocked. This is why the example falls back to a plain variable. For real persistence, run the same code from your own `.html` file in the browser.

## Common Mistakes

### Saving Objects Without `JSON.stringify()`

```javascript
localStorage.setItem("user", { name: "Asha" });
console.log(localStorage.getItem("user"));   // "[object Object]"
```

Use `JSON.stringify()` when saving and `JSON.parse()` when reading.

### Forgetting That Values Are Strings

```javascript
localStorage.setItem("count", 5);
const next = localStorage.getItem("count") + 1;   // "51", not 6
```

Convert with `Number()`.

### Not Handling `null`

```javascript
const items = JSON.parse(localStorage.getItem("items"));
items.push("New");   // TypeError if nothing was saved yet
```

Use a fallback: `JSON.parse(localStorage.getItem("items")) || []`.

### Storing Sensitive Data

Never store passwords or secret tokens. Anyone with access to the browser, or any script on the page, can read them.

### Expecting `sessionStorage` to Persist

It is cleared when the tab closes. Use `localStorage` for long-term data.

### Forgetting to Save After Changing Data

Changing an array in memory does not update storage. Call `setItem()` again after every change.

---

## Key Points

* Web Storage saves small amounts of data in the browser.
* `localStorage` stays until deleted; `sessionStorage` is cleared when the tab closes.
* Use `setItem()`, `getItem()`, `removeItem()` and `clear()`.
* `getItem()` returns `null` for a missing key.
* Storage saves **strings only**.
* Use `JSON.stringify()` to save objects and arrays, and `JSON.parse()` to read them back.
* Always provide a default value for missing data.
* Wrap storage code in `try...catch`, because storage can be blocked or full.
* The limit is about 5 MB per website.
* Never store passwords or other sensitive information.
